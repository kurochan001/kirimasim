## 5. 保守者に決めていただくこと

2026-10-31 に、保守者が以下のおすすめを受け入れました。VPI と specify の文面は、書いたときに改めて承認が要ります。

- **VPI と specify：** 棚卸し（3）で Icarus 13.0 が動かすと分かった形に絞り、標準のものだけを提案します。
  specify は module path（単純なものとエッジ付きのもの、立ち上がり・立ち下がり・ハイインピーダンスへの遅延）を先に、
  次に Icarus が動かす timing check（`$setup`、`$hold` など）を提案します。
  VPI は、プローブが必要とするシステムタスク・関数の登録、値と時刻の読み書き、callback を提案します。cocotb 全体を合格条件にはしません。
- **`wire real`：** 当面は互換オプションを設けず、既定は厳格な受理のままにします。後の比較で必要になれば、
  そのときに、文書化した `--compat` のモードの 1 項目として提案します。
- **`-W<name>` と `--compat=<name>`：** CLI.md 2 のとおり slang 自身の警告名と互換モードを渡し、
  各モードが何を緩めるかを CLI.md に挙げます。kirimasim 独自のモードは今は作りません。
- **分担：** 領域ごとに担当を 1 人に決め、作業を始める前に引き継ぎの資料に書き、ほかのエージェントの作業中のブランチ（`codex/*`）を先に確かめます。
  Claude Code は 1、2、3、5、8〜11 と、VPI と specify の提案を受け持ちます。
  class の実行（4）は保守者が割り当てるエージェントが受け持ち、既定では class の static プロパティを手がけた Codex とします。
  割り当ては保守者から伝えていただきます。2026-10-31 の後刻、保守者は Claude Code の受け持ちも Codex に引き継ぎました。
- **M8 の人のレビュー：** TEST_SUITE と AI_POLICY のとおり人が行います。Claude Code は、抽出した対象の一覧、その seed、
  レビューの記入表を用意し、保守者が確かめて結果を記録します。
