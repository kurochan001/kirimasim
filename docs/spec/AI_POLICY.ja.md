# AI_POLICY：AI 開発とレビューの決まり

[English](AI_POLICY.md) · 英語版が正本で、これはその日本語版です。食い違ったときは英語版に従います。

状態：**承認済み（2026-10-14）**。2026-10-15 に、テストスイートの期待値の決め方の注記を足した（承認済み）。2026-10-20 に、大域状態とその許可リストを「人が握るもの」に入れた（承認済み）。

この文書は、kirimasim を AI と一緒に開発するときの決まりです。設計仕様書の「AI 開発の方針」を書き直したものです。

## 基本の考え方

- kirimasim のコードの大半は AI（Claude Code）が生成する。人は、仕様・テスト・レビューに責任を持つ。README にもこのことを明記する。
- AI は仕様書から実装する。仕様と食い違う変更が要るときは、実装の前に、仕様書の修正として人が承認する。
- AI が近道として使いがちな書き方（禁止した C++ の機能、期待値の書き換えなど）は、人のレビューに頼らず、CI の自動の検査で止める。

## コミットの表示

- AI を使ったコミットには `Assisted-by: <ツール>:<モデルと版>` のトレーラーを付ける（例：`Assisted-by: Claude Code:claude-opus-5-5`）。
- 今は `Signed-off-by:` を求めない。書いているのが人 1 人と AI だけで、外部からのコードの PR も受け付けないため。外部からのコードの PR を受け付けるときに、DCO（または CLA）を導入する。
- AI に `Co-Authored-By` は使わない。

## 人が握るもの

次のものは人が決め、AI は案を出すだけにする。

- 仕様書（`docs/spec/`）
- テストの期待値（テストスイートでは、AI が規格の節と照らして案を作り、人は手順とまとまりごとの結果を承認する。1 本ずつ人が確かめたかどうかは、テストの `:spec_check:` で区別する。TEST_SUITE.md）
- 性能の予算（PerfCount の期待値としきい値）
- 新しい依存の追加
- 大域状態を足すことと、`tools/global_state_allowlist.txt` に項目を足すこと（RUNTIME_ABI.md の 9.3 節、9.4 節）
- 公開する文章

## 期待値を守る決まり

- 既存のテストの期待値を変える・削除する・緩める変更と、実装の変更は別の PR にする。既存のテストの本体を削除・差し替えて同じ効果を得る変更も同じ扱いにする。
- 新しいテストとその期待値、新しい PerfCount の項目の追加は、実装の PR に含めてよい。人が根拠を確かめる。
- 期待値の変更には、理由と規格の節番号を書き、人が承認する。
- CI は、base と head の merge-base から head までの差分で判定する。

## クリーンルーム

- 実装する AI に、Icarus Verilog と Verilator のソースを読ませない。動作は規格と実行結果から仕様に書き、その仕様から実装する。この手順を記録に残す。
- 規格の本文・図・例のコードを写さない。節番号の参照と、自分の言葉による要約だけにする。

## 外部からの寄稿

- 今は、外部からは仕様の提案と Issue だけを受け付け、コードの PR は受け付けない（`CONTRIBUTING.md`）。
- コードの PR を受け付けるようになったら、AI の使用を開示し、人が内容を理解して責任を持つものを受け付ける（LLVM の human in the loop の方針と同じ考え方）。

## 分からないこと

確かめていないことは推測で埋めず「未確認」と書く。版の番号は実際に調べた値を使う。
