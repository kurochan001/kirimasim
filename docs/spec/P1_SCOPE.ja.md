P1は、以下の承認済み`wire real`例外を適用したうえで、Icarus Verilog 13.0以上の範囲の実行機能を目指します。既存の合格率の基準は
引き続き必要ですが、それだけでは達成と判定しません。コンパイラ・ランタイムの版と
自作の仕組み別プローブを記録します。正確な13.0版の対応範囲と全面的な同等性は未確認です。

Icarusが対応する標準の実行機能を、必要に応じてP1へ前倒しします。動的なコンテナ、
クラス、programの実行、VPI、スイッチレベルのモデル、specifyパス、タイミング機能を
含みます。SIR_SPEC・SCHEDULER_SPEC・SYSTEM_TASKS・VPI_SPEC・WAVEFORM・TEST_SUITEと
プロジェクトの説明にあるP4・P5・対象外の記述より、必要な部分について本書を優先します。
それ以外は従来の段階を保ちます。P3は引き続きC++生成です。
[2026-10-24承認のP2方針](../notes/sir-v1-proposal.ja.md)により並行準備でき、SIR v1の
文法/境界の最終確定をP1完了後のP2へ移します。P1の実行機能範囲・合格gate・既存期待値は
保ちます。比較の範囲を超える
制約付きランダム化やUVMなど、他の後続段階の計画は保ちます。

IEEE 1800の値とスケジューリングの意味、4値の既定、共通カーネル、厳密なslangの診断、
既存のP1の基準と期待値を保ちます。実装に任される差は記録し、相手の不具合は再現しません。
仕様の詳細が不足する場合や食い違う場合は、実装前に意味の修正案をレビューします。
今回の承認は範囲の変更であり、未記入の詳細を決めるものではありません。

独自拡張と外部インターフェースは別途一覧化します。厳密な受理規則に反する拡張には、
文書化した互換オプションと意味の提案が実装前に必要です。新しい依存・インストールは
引き続き別途承認を必要とし、この変更では選定しません。

本書は目標であり、実装済み機能の宣言ではありません。実装済みの形は
[P1_SUPPORT](../P1_SUPPORT.ja.md)、測定した差は
[進捗記録](../notes/p1-icarus-progress.ja.md)を参照してください。

## 任意のIcarus `wire real`拡張（2026-11-01承認）

**Icarus Verilog 拡張である `wire real` への対応は、P1 の必須条件に含めません。
この拡張への依存が確認されたケースは、未サポートであっても P1 の達成を妨げません。**
この拡張への未対応だけを、P1未達、P1のブロッカー、IEEE 1800標準機能の実装不足とは
判定しません。P1完了条件のIcarus互換性に関する記述すべてにこの例外を適用し、
その他の基準は保ちます。

`real`変数と実数演算、標準で認められる`real`変数への単一の連続代入、
`nettype real`によるユーザー定義ネット型は、この例外には含めません。
これらは既存のP1基準に従い、本改定を理由に除外しません。
`nettype real`を新たにP1必須機能へ追加する変更でもありません。
今回の決定による実装の追加・削除・無効化は行いません。

拡張依存を確認したケースだけを、名前・ソースのハッシュ・理由付きで分類します。
テスト名やソースに`real`という文字があるだけでは除外しません。標準と拡張が混在する
テストは必要に応じて分離し、独立して検査できる標準機能を評価対象に残します。
現時点で有限プローブから確認した対象は`real_net`で、
`tools/icarus_feature_probe.py`の`P1_OPTIONAL_PROBES`に記録します。
ソースが変わった場合は依存を再確認します。

未サポート・コンパイル失敗をPASSへ書き換えません。適切なコンパイルエラーでの拒否は
許容します。クラッシュ・ハング・内部エラーなど、独立した実行・基盤の不具合は、
対象外ケースでも既存の不具合基準で失敗とします。評価対象数と対象外件数・理由は分けて報告します。
過去の観測結果は保持し、現在のP1判定は[TEST_SUITE](TEST_SUITE.ja.md#任意拡張の分類)の
必須範囲の分類と独立不具合の検査を用います。
