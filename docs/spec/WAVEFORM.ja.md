この文書は、kirimasim が波形として書くものを決める。設計の書き出しのタスク、またはコマンドラインの `--wave`（CLI.md の 2.2 節）が書く、21.7.1 節と 21.7.2 節の 4 値の VCD のファイルである。規格の本文は写さず、節の番号を添えて、この文書の言葉でまとめる。「規格で確認」「解釈」「本書の決まり」「参考」は、SYSTEM_TASKS.md と同じ意味である。

## 1. 範囲

- **P1：** `$dumpfile`、`$dumpvars`、`$dumpoff`、`$dumpon`、`$dumpall`、`$dumplimit`、`$dumpflush` による 4 値の VCD（21.7.1、21.7.2）と、`--wave=<file>.vcd` と `--wave-scope`、`--wave-glitches`（CLI.md の 2.2 節）。
- **後で：** FST（`--wave=<file>.fst`）は、新しい依存の libfstapi が要り、入れる前に人が決める（CLAUDE.md）。それまで `.fst` はコマンドラインの誤りである。21.7.3 節と 21.7.4 節の拡張 VCD（`$dumpports` など）は、未対応として報告する。

## 2. 書き出すもの

- **スコープ（21.7.2.3 と 21.7.5 の解釈）：** モジュールのインスタンス（スコープの種類 `module`）、名前付きの `begin` と `fork` のブロック（`begin`、`fork`）、static な変数を持つタスクと関数（`task`、`function`）。名前付きの generate ブロックは `begin` のスコープとする（本書の決まり。4 値の VCD にはその種類が無い）。アンパックの構造体の変数は、そのメンバを変数とする `fork` のスコープである（規格で確認：21.7.5）。
- **変数とネット：** それらのスコープのネットと static な変数で、表 21-11 の型と、それに当たる 1364 の型のもの。アンパックの配列と automatic な変数は書き出さない（規格で確認：21.7.5）。文字列、chandle、クラスのハンドルなど、VCD に型の無い動的なデータも書き出さない（本書の決まり）。パラメータも書き出さない（本書の決まり。4 値の VCD では、値の変化の外で値とともに並べるしかない）。
- **型（規格で確認：21.7.5、21.7.2.3）：** `bit`、`logic`、パックの配列と構造体は、全体の幅の `reg`。`int` と `enum` は `integer` 32（基の型を持つ enum は、その型の対応に従う）。`byte`、`shortint`、`longint` は `reg` 8、16、64。`integer` は `integer`、`time` は `time`。`real` と `shortreal` は `real`、`realtime` は `realtime` で、どれも大きさは 64（本書の決まり。21.7.2.3 は大きさをビット数とし、表 21-11 はこれらに大きさを与えていない。2026-10-21 に追加、承認済み）。ネットはその種類（`wire`、`tri`、`wand`、`wor`、`triand`、`trior`、`tri0`、`tri1`、`supply0`、`supply1`）で、`uwire` は `wire`（規格で確認：21.7.2.3）。`event` は大きさ 1 の `event`（本書の決まり。2026-10-21 に追加、承認済み）。
- **参照の名前：** 変数の名前。パックの範囲を 1 つ持つと宣言したものは、宣言のとおり `[msb:lsb]` を付け、そのほかの 1 ビットより広い整数型は `[幅-1:0]` を付ける（本書の決まり）。範囲は、`$var reg 4 ! a [3:0] $end` のように、名前の後に空白を置いて書く（2026-10-21 に追加、承認済み）。
- **順と識別子（本書の決まり）：** スコープはエラボレーションの順に深さ優先で、各スコープでは、ネットと変数を宣言の順に並べ、その後に下のスコープを置く。識別子は、`!` から `~`（33 から 126）の文字で書く 94 進の数で、上の桁から書き、この順に `!` から付ける。ポートでまとめて 1 つのネットになった名前は、1 つの識別子を共有する（VALUE_SEMANTICS.md の 5 節。規格で確認：21.7.2.3 はこれを許す）。

## 3. ファイル

- **見出し（規格で確認：21.7.2.1、21.7.2.3）：** `$date` は、実行を始めた日時で、driver が Context に渡す（RUNTIME_ABI.md の 9.3 節の 8）。UTC で `YYYY-MM-DD hh:mm:ss UTC` と書く（本書の決まり）。`$version` は、`kirimasim <版>` と、次の行に、ソースに書かれたとおりの `$dumpfile` の呼び出し、または `--wave=<file>`（規格で確認：21.7.2.3 は書かれたとおりの呼び出しを求めている）。`$timescale` は、シミュレーションの精度で、`1 ps` のように書く。次にスコープと変数、そして `$enddefinitions`。`$date`、`$version`、`$timescale` の中身は、それぞれ自分の行に、タブの後に書く（本書の決まり。2026-10-21 に追加、承認済み）。
- **時刻：** シミュレーションの精度を単位とする `#<n>`（規格で確認：21.7.2.1）。
- **値（規格で確認：21.7.2.2）：** 1 ビットの変数は、`0`、`1`、`x`、`z` の後に、空白を置かずに識別子。それより広いものは、`b` とビットを表 21-8 と 21-9 の最も短い形で書き、空白、識別子。実数は、`r` と `%.16g` の形の数、空白、識別子。イベントは、トリガされた時刻ごとに `1` と識別子。

## 4. 値を書く時点

- **始まり（規格で確認：21.7.1.3）：** `$dumpvars` は、それを実行した時刻スロットの終わりから書き始める。見出し、時刻、そのときの書き出す変数すべての値を並べた `$dumpvars` の節を書く。イベントは除く。
- **変化（UNSPECIFIED_BEHAVIOR.md の D3、2026-10-19 に承認）：** その後の各時刻スロットの終わりに、時刻と、最後に書いた値と違う値を持つ変数を書く。`--wave-glitches` のときは、時刻スロットの中の変化をすべて、起きた順に、起きたときに書く。
- **制御のタスク（本書の決まり）：** `$dumpoff`、`$dumpon`、`$dumpall` は、実行した時刻スロットの終わりに、そのスロットの変化の後で効く。`$dumpoff` は、すべての変数を x とした `$dumpoff` の節を書き（実数は x を持たないので除く）、`$dumpon` まで変化を書かない。`$dumpon` は、そのときの値を並べた `$dumpon` の節を書く（規格で確認：21.7.1.3）。`$dumpall` は、そのときの値を並べた `$dumpall` の節を書く（規格で確認：21.7.1.4）。`$dumpvars` の前には、何もしない。書き出しが止まっているときの `$dumpoff`、書き出しているときの `$dumpon`、止まっているときの `$dumpall` は、何もしない（本書の決まり。2026-10-21 に追加、承認済み）。
- **`$dumpvars` の引数（規格で確認：21.7.1.2）：** 引数が無ければ、すべてのスコープ。`levels` とスコープや変数があれば、0 と書いたスコープは、その下のスコープをすべて含めて書き出し、n なら、その下の n - 1 段のモジュールのインスタンスまで書き出す（名前付きのブロック、タスク、関数、generate ブロックは、そのモジュールに付いていく）。変数は、それだけを書き出す。1 つの時刻スロットの中の複数の `$dumpvars` は合わせる。levels だけのときは、トップのモジュールをその levels で書き出す。書き出さないもの（アンパックの配列、文字列。2 節）を名指ししても、何も足さない（本書の決まり。2026-10-21 に追加、承認済み）。**後の時刻の `$dumpvars`（本書の決まり）：** 規格はすべてを同じ時刻に実行することを求めているので、後の時刻のものは、実行時の警告 `kirima-dumpvars-late`、`$dumpvars: dumping started at an earlier time; the call is ignored` を出して無視する（文は 2026-10-21 に追加、承認済み）。
- **`$dumpfile`（規格で確認：21.7.1.1）：** ファイルの名前を決める。`$dumpfile` を実行していなければ `dump.vcd`。書き始める前の後からの `$dumpfile` は名前を置き換え、書き始めた後のものは、実行時の警告 `kirima-dumpfile-late`、`$dumpfile: dumping has started; the call is ignored` を出して無視する（本書の決まり。文は 2026-10-21 に追加、承認済み）。ファイルは、書き始めるときに、kirimasim を起動したディレクトリを起点に作り、同じ名前のものがあれば上書きする。開けないファイルは、警告 `kirimasim: warning: the dump file "<name>" cannot be opened (<reason>); nothing is dumped` を出し、実行は続ける（本書の決まり。2026-10-21 に追加、承認済み）。
- **`$dumplimit`（規格で確認：21.7.1.5）：** ファイルがそのバイト数に達したら、書き出しをやめ、上限に達したことを注釈に書く。大きさは、各時刻スロットの行を書いた後に見るので、ファイルはその行の分だけ上限を越えることがある。注釈は `$comment the dump limit of <n> bytes was reached $end`（本書の決まり。2026-10-21 に追加、承認済み）。
- **`$dumpflush`（規格で確認：21.7.1.6）：** たまっているものを書き出す。
- **終わり：** 実行がどう終わっても、そのときにファイルを書き出して閉じる（ファイルと同じ。SYSTEM_TASKS.md の 6.1 節）。最後の時刻の行は足さない（本書の決まり）。最後の時刻スロットの終わりの後に変わったもの（終わりで途中で切れた時刻スロットや、final 手続きで変わったもの）は、そのときに、時刻スロットの終わりと同じように書き、途中で切れた時刻スロットの `$dumpvars` は、そのときに書き出しを始める（本書の決まり。2026-10-21 に追加、承認済み）。

## 5. `--wave`

- `--wave=<file>.vcd` は、すべてのプロセスより前に、時刻 0 で `$dumpfile("<file>.vcd"); $dumpvars;` を実行したものとして書き出す。設計の `$dumpfile` と `$dumpvars` は、場所ごとに 1 回、実行時の警告 `kirima-dump-command-line`、`<task>: --wave sets what is dumped; the call is ignored` を出して無視し、`$dumpoff`、`$dumpon`、`$dumpall`、`$dumplimit`、`$dumpflush` はそのまま効く（本書の決まり。文は 2026-10-21 に追加、承認済み）。名前が `.vcd` で終わらないファイルは、コマンドラインの誤りである（2026-10-21 に追加、承認済み）。
- `--wave-scope=<パターン>[,<パターン>...]` は、階層名か、それを囲むスコープの階層名が、どれかのパターンに合うスコープだけを残す。`*` は任意の文字の並び、`?` は 1 文字に合う（本書の決まり）。無ければ、すべてのスコープ。空のパターンは、コマンドラインの誤りである。`--wave` が無いときは、設計の `$dumpvars` が書き出すものの中から選ぶ（2026-10-21 に追加、承認済み）。
- `--wave-glitches`（CLI.md の 2.2 節）：4 節を見よ。`--wave` が無いときは、設計自身の書き出しに効く（2026-10-21 に追加、承認済み）。

## 6. テストスイートへの影響

- テストの道具は、VCD のファイルを、実行ごとに変わる `$date` の節を除いて比べる。テストスイートのテストは、これを設計の中で行う。`$dumpflush` の後に自分の書き出しを読み戻し、`$date` の行と、リリースごとに変わる `$version` の `kirimasim <版>` の行を除いて表示する（`tools/gen_dump_matrix.py`。2026-10-21 に追加、承認済み）。
