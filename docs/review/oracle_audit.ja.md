# P1 母集団の期待値の監査

[English](oracle_audit.md) · 英語版が正本です。日本語版はそれに従い、違いがあるときは英語版が優先します。

状態: **決定**（2026-10-21）。4 節の推奨をオーナーが受け入れました。除外するテストはなく、期待値も README の件数も変えません。以下の判定は AI モデル（Claude Code）が行い、人は 1 件ずつは確かめていません。

## 1. 目的

テストスイートの期待値の多くは Icarus Verilog 13.0 で記録され、Icarus がコンパイルできないテストは Verilator 5.052 で記録されています（`:oracle:`、kirimasim-tests の README）。どちらかが IEEE 1800-2023 に従っていないところでは、その結果が期待値に入りえます。P1 母集団のテストに通る kirimasim も、同じ振る舞いをしているかもしれません。この監査は、`tests/gates/p1_population.txt` の母集団（kirimasim-tests c983cf799b4d の 1466 件）からそうしたテストを探し、規格が結果を決めていないテスト（4.7 など）とは分けて扱います。

## 2. 方法

`tools/oracle_audit.py` は、母集団の全テストを次の 3 つで実行し、テストごとに 1 行の [oracle_audit.csv](oracle_audit.csv) を書きます。

- Icarus Verilog 13.0（`iverilog -g2012`、`vvp -n`）
- Verilator 5.052（`--binary --timing --x-assign unique --x-initial unique`）。`+verilator+rand+reset+2` とシード 1・7・42・2026 で実行し、スイートのランナーがいま渡しているのと同じく `+verilator+error+limit+1000000` も渡す
- kirimasim（main、900dbf3）

行ったのはプログラムの実行だけで、Icarus Verilog と Verilator のソースコードは読んでいません。実行方法は英語版の 2 節にあります。

次のどれかに当てはまるテストを候補としました。

| | 条件 |
| --- | --- |
| a | 期待値を Verilator が記録し、x か z が関わる（期待値・コード・`:fourstate: yes` のどれか） |
| b | Icarus と Verilator の両方が実行でき、出力が違う |
| c | Verilator の出力がシードで変わる |
| d | 結果がイベントの順序で変わりうる構文（`#0`、ノンブロッキング代入、`fork`、名前付きイベント、`$strobe`・`$monitor`、複数の手続きから書かれる変数）を使い、期待値をシミュレータが記録した |

a と d の検出はテキストに対して行うので、取りこぼしよりも拾いすぎに寄ります。何を検出したかは CSV にあります。そのうえで、候補をそれぞれ条項と突き合わせて読みました。

- **a・b・c:** x・z・強度・ネットの解決・書式、または記録したシミュレータに左右される期待値の行をすべて確かめました。
- **d:** 2 つのプロセス、または 1 つのプロセスの 2 つの文が、規格の決めていない順序で動きうる箇所を探し、表示される行がそれに左右されるかを確かめました。

判定は次の 5 つです。

- **相手のバグ:** 期待値が、それを記録したシミュレータの逸脱に従っている。
- **規格で未規定:** 表示される行が、規格の決めていないことに左右される。
- **テスト自体の誤り:** テスト自身の検査か期待値が規格に反している。
- **問題なし。**
- **要人間判断:** 決め手となる条項がない。

## 4. 決定

以下の推奨を、2026-10-21 にオーナーが受け入れました。どれも、kirimasim の仕様書ですでに承認されている解釈に従っています。

### 4.1 文と文の間でのプロセスの中断（4.7）

4.7 は、手続きの中の時間制御のない文は 1 つのイベントとして実行しなくてよく、シミュレータはいつでも手続きを中断してほかのプロセスを動かしてよい、としています。

- **`ch4/test_event_delta_cycles`:** always ブロックが起きた回数を表示するので、直接左右されます。
- **`ch9/test_sens_level`:** 起こされたブロックが待ちに戻る前にも中断され、2 つ目の変化を取り逃すときに左右されます。

2 件とも **規格で未規定** です。kirimasim の UNSPECIFIED_BEHAVIOR.md B2 は、すでにこの点を規格が決めていないものとして挙げ、kirimasim の選択（プロセスは待つまで切り替えない）を記録しています。

2 件とも **母集団に残します**。期待値はその選択どおりの結果で、TEST_SUITE.md は、規格が結果を決めていないテストでは kirimasim の実行を kirimasim の選んだ結果（`choice`）と比べます。除外は、シミュレータのバグを記録した期待値のためのもので、それは 1 件もありません。

B2 に左右されるほかのテストも同じです。機械的に数えると、レベル感応の always ブロックがあり、どこかでブロッキング代入が 2 つ続くテストは 38 件あります。1 件ずつは確かめていませんが、ゲートでの合否はその確認に左右されません。リストを新しいコミットに移すときに、kirimasim-tests でそれらを `:nondeterministic: yes` にし、規格が許す結果を並べることはできます。それは kirimasim-tests の変更で、この監査の範囲の外です。

### 4.2 %E と %G の指数記号の大文字小文字（21.2.1.1）

Table 21-2 は `%e or %E`、`%g or %G` をそれぞれ 1 つの指定として並べ、real の書式は C の書式を持つとしています。C では `%E` と `%G` は `E` を出します。kirimasim の SYSTEM_TASKS.md 3.6 は 21.2.1.1 をそう読んでいます（2026-10-17 承認）。

このため `ch21/test_format_advanced` と `ch21/test_format_float` は **問題なし** です。期待値の `E` はこの読み方どおりで、Icarus 13.0 と kirimasim はそう出し、Verilator 5.052 は出しません。

16 進の a〜f は、SYSTEM_TASKS.md 3.2 の規則で小文字です。この規則の裏付けになる規格の文はありません。ただし 3 つのシミュレータがどれも小文字を出すので、これを理由に印を付けたテストはありません。

### 4.3 NaN

5 件（`test_math_advanced`、`test_math_hyperbolic_special_values`、`test_math_special_values`、`test_realtobits_bitstoreal`、`test_system_functions_edge`）は、NaN が自分自身と等しくないときだけ通ります。規格は NaN に触れていません。

それらの行は決まっているものとしました。根拠は 6.12（real は C の double で、注で IEEE 754 の表現とされる）と 20.8.2（数学関数は C と同じに振る舞う）で、kirimasim の VALUE_SEMANTICS.md 7 の解釈です。**問題なし** です。

### 4.4 除外

ありません。Icarus Verilog や Verilator のバグを記録した期待値はなく、規格で未規定の 2 件は残す（4.1）ので、除外リストは作らず、kirimasim への Issue も立てず、README の件数も変えません。

後で除外が要るときのために: ゲートが実行するのは、母集団リストの見出しにある kirimasim-tests 179c55de9c83 のテストです（リストは c983cf799b4d で選んだもの）。kirimasim-tests の main で期待値を直しても、リストを移すまではゲートに届きません。リストの移動は、TEST_SUITE.md により人の承認が要る変更です。このリポジトリ（tests/gates/）に除外リストを置けば、すぐに効きます。
