# 繰り返しイベント制御を持つブロッキング代入

[English](repeated-event-controls.md)。実装`87ae3a2`、2026-10-24。
既存の承認済みSCHEDULER_SPEC 8とIEEE 1800-2023 9.4.5の規則を実装し、
新しいSIR命令やスケジューリングの方針は追加しません。

以下のイベント制御付きNBAの制限は、この検証時点のものです。その後の
[ソースevent-NBAの実装](event-nba-source-execution.ja.md)に、現在の対応範囲と残る制限を記載しています。

## 実行と制限

`target = repeat(count) @(event_expression) value`を、既存の代入内制御の経路で実行します。

1. 右辺を評価し、その値を保持します。
2. 回数を1回評価し、幅・符号・状態の型を保ってフレーム変数へ格納します。
   0以下・X/Zの回数なら、イベントを待ちません。
3. 既存の名前付きイベント・スロットの購読・式の監視で、指定回数を待ちます。
   混合する項と`iff`は既存の規則を使い、偽のguardでは1回と数えません。
4. 最後の待機の後にブロッキング代入先を選び、保持した値を書きます。
   待機が0回なら、回数の評価後すぐに代入します。

frontが比較・分岐・フレームの読み書き・既存の待機命令へ変換します。
回数を機械の1ワードへ狭めたり、元の回数式を再評価したりしません。反復ごとに新しい待機を
登録するため、登録より前に起きたイベントは数えません。kernel・VMは変更せず、
一時値は待機をまたぎません。コンテナの値の捕捉とスカラー・文字列の保持は、
既存の型付きフレームと回収のルートを使います。

検査した対象は固定配列の要素、packed連結、自動変数、実数・文字列、動的コンテナ全体です。
この版で未対応だった固定配列・unpacked構造体全体のブロッキング代入内制御は、
[後続の実装](blocking-aggregate-timing.ja.md)で対応しました。
イベント制御付きの**ノンブロッキング**代入は、発行元を止めずに待ちを登録する必要があり、
別の残作業です。このブロッキング用のループで非同期の登録に対応したとは扱いません。

## 検証

[独自の行列ジェネレータ](../../tools/gen_repeated_event_matrix.py)でソース75件とジェネレータ検査を追加しました。
主な64件は実行場所8種類、1・32・65・129ビット、2値・4値の値を横断します。
右辺・回数の評価順、待機中に変わる元の回数、遅い代入先の選択、X/Z、実数・文字列の保持、
名前付き・混合・式の監視、packed連結、待機を省く回数を検査します。
追加11件は切り詰めや符号変更を検出する65・129ビットの正の回数、状態の型、
狭い符号付き・符号なし・X/Zの回数、混合`iff`、回収の安全点をまたぐ独立したコンテナ値を含みます。

従来のreleaseバイナリ（`51cafd204560`と表示）では、最初の70件すべてが未対応で止まりました。
その比較後に回数の型の5件を追加しています。実装後は75件とジェネレータ検査が通過し、dev全体は2,907件中2,905件成功、
従来の2件がスキップです。`87ae3a2`のローカルCIはdev・release・ASan・UBSanと
全静的検査を通過しました。ASan・UBSanも各2,907件中2,905件成功、releaseは
2,908件中2,906件成功で、スキップは同じ2件です。clang-format・clang-tidy・期待値保護も
含みます。既存のスイート本体・期待値・性能の回数は変更していません。

意図的な3種類の誤りもビルドでき、新しいソースの標準出力の相違で検出しました。
回数を符号付きの下位ワードへ狭める、0でも1回待つ、ブロッキング対象を制御より前に捕捉する
誤りです。アンカー・判定ツール自身の検査を除いた全体でも失敗します。
変更前の全体が通過し、復元後のソースもローカルCIより前に再ビルドしました。
実際に実行した3件と、483件のアンカーの適用検査は別に扱います。

Icarusのコンパイラ・ランタイムはともに`14.0 (devel) (s20260301-411-gca6b8d376)`です。
同じ75件のうち48件で期待出力が一致しました。26件は参照側でコンパイルできません。
automatic taskの式の制御、package変数への代入、`iff`、コンテナのコンパイル失敗を含みます。
別の1件はコンパイル後、1ビットのX回数で待ち続け、検査用のwatchdogへ到達しました。
これらの失敗で、対象の形を独立に検証できたとは扱いません。
他のシミュレータのソース・テストは読んでいません。

独自の比較を4本追加し、有限の一覧を68本から72本へ拡張しました。
最初の3本はIcarusが通り、旧kirimasimは未対応で、実装後に通過します。
同じ72本ではIcarusだけが通る差分が29本から26本へ減り、従来の68本の差分26本は変わりません。
4本目は1ビットのX・Z回数を独立に開始し、イベントを発火しません。
9.4.5では待たずに代入するため`7 9`が期待値で、kirimasimも一致しますが、Icarusは`0 0`でした。
参照側の不一致を6本から7本へ増やし、実行機能の差分へ混ぜたり、期待値を弱めたりしません。
13.0そのものと全面的な同等性は未確認です。

## 再実行

```sh
ctest --preset dev -R repeated_event --output-on-failure
python3 tools/gen_repeated_event_matrix.py --check
python3 tools/icarus_feature_probe.py --kirimasim build/dev/src/driver/kirimasim \
  --extended --output build/repeated-event-icarus-probes.json --require-parity
```

比較は必要な実行機能の差分が残るため終了コード1です。
JSONには版・個別の結果・差分・参照側の不一致を区別して記録します。
