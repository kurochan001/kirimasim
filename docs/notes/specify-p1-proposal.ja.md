# specify module pathの最初の実行契約案

[English](specify-p1-proposal.md)。2026-11-01。**1〜8節は保守者が2026-11-01に承認済みで、実装はこれからです。**

P1_SCOPEと優先順位のspecify項目が求める具体的なレビュー案です。
P1の範囲の承認は、未記入のタイミング規則の承認ではありません。
保守者が1〜8節を最初の実装契約として明示承認しました。9節には版の制約を含む証拠と未確認事項を記します。
9節の版の制約は記録に残し、この承認は既存期待値の移行を含みません。

## 1. 最初に実装する範囲

通常のコンパイル・実行で受理したmodule pathを適用し、タイミングを黙って無視する
オプトイン方式にはしません。`parse`は従来どおり構文解析・エラボレーションだけです。
module instance、スカラー4値の入力net、スカラーの`wire`/`tri`出力netから始めます。
単純な`=>`と完全接続の`*>`で、複数のスカラー入力・出力を扱います。
無条件のエッジ付きpathは`posedge`、`negedge`、エッジ指定なしと、そのデータ・極性の
注釈を含めます。

各出力先には通常の内部機能ドライバが1つあります。連続代入、または固定の駆動強度を持つ
既存の組み合わせ論理プリミティブです。手続きで更新する内部状態から、1つの連続代入で
出力を駆動する形も含めます。その機能経路に既存の分布遅延がある場合は3節に従います。
階層・generate内のinstanceは状態を分離します。specparam、parameterの上書き、
定数の実数/整数遅延、`--mintypmax`も含めます。

最初のソース接続では、ベクトル端子/bit選択、出力変数、inout/受動経路、出力先の複数の
物理ドライバ、三状態/MOS/UDPの出力ドライバ、状態依存の`if`/`ifnone`、pulse制御宣言、
SDF、timing checkは受け付けず、位置付きの未対応診断を出します。
必要なものは後続のP1作業に残り、新しいP1例外ではありません。
スカラーの実行だけでspecify全体の網羅を示すものではありません。
specparamだけのblockは従来どおりです。

## 2. 遅延の正規化と4値の遷移

内部では12遷移を次の順に正規化します。
`01, 10, 0z, z1, 1z, z0, 0x, x1, 1x, x0, xz, zx`。
これは内部データ契約の提案で、外部ABIの追加ではありません。

式が1つなら全項目に使います。2つの式R/FではXを含まない6項目が
`R,F,R,R,F,F`です。0からZと1からZを、どちらも最小値にする規則ではありません。
3つの式R/F/Zでは`R,F,Z,R,Z,F`です。6つならXを含まない6項目を直接指定し、
12なら全項目を明示します。Xの項目を省いた場合、Xへ向かう遷移には可能な最早の遅延を、
Xから出る遷移には可能な最遅の遅延を使います。候補はX以外の端点（0・1・Z）です。
通常のゲートの3遅延選択で置き換えてはいけません。

各min/typ/maxを先に選びます。選んだ遅延の負値は0とし、定義moduleの精度で既存の遅延の
正規化規則に従って一度丸め、その後global tickへ変換します。有限でない値・表現できない値、
時刻overflowの既存の扱いを保ちます。負値を符号なしの遠い将来へ変換しません。
初期のpath clockは時刻0を基準とし、書かれる出力netは最初の機能値を選択した期限で公開するまで、
従来のX初期状態を保ちます。

## 3. 入力の時刻、pathの選択、分布遅延

各スカラー入力の、最後の射影された4値の遷移とそのシミュレーション時刻を記録します。
強度だけの変化は入力の論理イベントではありません。エッジの適格性には既存の`valsem`を使い、
エッジ指定なしではすべての4値変化を見ます。最後の実際の入力イベントの適格性を保ち、
古い適格イベントを新しいものとして残しません。

出力の機能結果が変わると、その出力への適格pathのうち最も新しい入力時刻を選びます。
同じ時刻で複数が適格なら、実際の出力遷移に対する最小遅延を選びます。その入力時刻から
絶対期限を求め、現在の機能結果の到着時刻より前には公開しません。
たとえば分布遅延の到着がtick 30、pathの期限がtick 28なら、公開は30であり37ではありません。
適格なpathがなければ通常の機能結果の到着を保ちます。初期評価にも時刻0基準の同じ規則を使い、
架空の入力イベントや隠れたユーザーprocessを作りません。

極性とdata-source式はpathの説明です。moduleの機能計算を置き換えたり、反転させたり、
実行したりしません。特にdata-source注釈だけにある関数呼出しを実行したり、乱数を消費したり
してはいけません。

## 4. 保留更新、pulseの除去、region

各出力先が確定した機能の寄与と、任意の保留中の完全な寄与/期限を所有します。
既定のerror/reject limitは選んだpath遅延と等しく、完全な慣性遅延の除去を使います。
保留する先頭edgeより前に確定した寄与へ戻れば、まだ公開していないpulseを取り消します。
同じ保留寄与は期限を延ばしません。それ以外は所有するpayloadと新しい世代で置き換え、
古いtimerでは公開できないようにします。出力時刻が逆転するpulseは、既定の非表示方針で
取り消します。全イベントを残すtransportとして実装してはいけません。

公開netがforceされていても、比較対象はpathの確定寄与です。forceで固定した読み値を
比較対象にしません。4値の語と保持する強度情報は同じ保留寿命を持ちます。
VM一時値・span・呼出しframeを借用しません。

期限に達したmodule pathの公開は、そのmoduleのActiveの処理です。すでに到達した期限は
現在のActive処理へ予約し、Inactiveでの明示的な`#0`観測より前に見える必要があります。
通常の`drive.delay #0`とは異なります。既存のscheduler順、時刻が進まない実行・資源・実時間の
制限、中断、final/終了時の解放は引き続き適用します。

## 5. 見えるnet、port、force、観測

port collapseより前にpath出力先を調べます。非公開の機能結果と、外から見える遅延後の出力先を
分け、その区別を消す接続はcollapseしません。宣言した出力先の読みは、cellの内外とも確定した
遅延後の値を見ます。非公開の結果に書くのは機能ドライバだけです。
隠れたcarrierをユーザーのreflectionや波形の対象にしません。

元の物理ドライバ1つの同一性を保ち、完全な寄与を運びます。キャッシュした解決済みネット区間を
新しいoriginへ変えません。通常の値通知、強度通知、波形/monitor/VPIの読みは、同じ確定した
公開snapshotを見る必要があります。

承認済みnet-forceモデルを接続します。forceは公開netを直ちに固定し、機能更新と保留期限は
その間も進みます。releaseは現在の確定したpath寄与を同期的に読みます。
force中に過ぎた期限を失わず、まだ先の期限をreleaseで繰り上げません。
bitごとの上書き所有者とContextの分離を保ちます。追加の物理ドライバ/受動網との組合せは
最初の接続の対象外で、黙って1つへ平坦化しません。

## 6. SIR、VM、kernelの境界

検証した静的path行に、数値の入力/出力binding、所有者と機能ドライバの同一性、エッジ指定、
正規化した12遅延、ソース位置を持たせます。書き換えるclock、保留の世代/payload、購読は
Contextが所有します。pathと出力先のIDを固定し、別instanceで状態を共有しません。

frontendは固定slangの型付き`TimingPathSymbol`を読み、slangは変更せず、最適化でportを
消す前にpathを記録します。SIR検証器は、端子のdomain/幅、入力/出力の所有、重複・競合binding、
遅延の形、有効なID、機能ドライバが1つであることを検査します。
不正なnative IRは実行modelの割当て前に拒否し、未対応ソースは位置付きエラーとし、
検証器/内部エラーにしません。

VMは型付きの値と数値bindingを機械的に渡します。時間アルゴリズムは共有kernelに置き、
slang・SIR・LLVMへの依存を追加しません。公開kernelヘッダはC++20を保ち、新しいヘッダは
既存検査にも追加します。公開C ABI、新しい依存、書き換え可能な大域状態、実行時の信号名検索、
隠れたユーザーthread/RNG所有者は追加しません。pathのない既存設計は、従来の速い経路と
PerfCount期待値を保ちます。

## 7. 受理と後続の作業

未対応のpath/timing/pulse構文が混在するblockを、部分実行して成功にしてはいけません。
厳格なfrontend診断を保ち、未対応の組合せを明記します。クラッシュ・ハング・内部エラーは
独立した失敗です。参照でコンパイルできることや、parseだけをタイミング実行の根拠にしません。

状態依存pathには後続の契約と2023版の照合が必要です。確認した2017版は、条件のLSBと、
X/Zを有効にする悲観的な規則を使い、通常の`if`とは違います。参照の3観測が異なります。
ベクトル遅延では参照自身が未完全対応と診断する差が2件あります。
これらを標準実装として模倣しません。timing check、pulse制御、複数driver/inout/variable/vector
の形は棚卸しに残し、P1全体で不要とは宣言しません。

## 8. 受入れと期待値の移行

値・時間の独立参照、native Contextの予約、型付きSIR/VM、ソース/port接続、統合/文書の順に、
レビュー可能な単位で実装します。各段階でソースの形だけを照合せず、有用な実行検査を持ちます。

12論理遷移と5種類の遅延個数、時刻0の開始、実数の丸め/min:typ:max/負/0、最終入力と同時入力の
選択、短い/等しい/長いpulse、分布遅延との合成、エッジ極性、注釈を実行しないことを検査します。
保留中のforce/release、内外の読み、波形/monitor、分離、取消、失敗/解体も扱います。
刺激を手続き、task/関数、fork、interface/program、generateに置く、合法な範囲の有界な
ソース文脈行列を作ります。native表では不正な形と広いslotのアドレス境界も必要です。

コンパイルしたnative変異で、X選択の誤り、最終入力選択の欠落、遅延の加算、0のregion違い、
古いtimer、port同一性の消去、注釈の実行、force中の保留消去を検出します。
ビルド失敗や変異登録器自身の検査は意味の故障検出に数えません。変異や全local CI中はソースを
固定し、hashを復元して正の検査を再実行します。dev全体と関連release/ASan/UBSanを実行し、
成功したdev全件JUnitから件数を別コミットで更新します。push前に全local CIを実行します。

現行の生成済み`tests/cli/unsupported_matrix/specify_path.sv`と拒否期待値は、このレビューでは
変更しません。実行を確認してから、元ソースと他の拒否検査を保持する具体的な分類移行を
別に提案します。この契約ではその期待値変更を承認しません。
ソース接続後、固定の`specify_path`プローブを、ソースhash・期待出力を変えず測り直します。

## 9. 根拠と版の制約

[102ケースの棚卸し](specify-reference-inventory.ja.md)にIcarus 13.0の実行と、従来どおりの
native拒否を記録します。記述した期待トレースとの一致87件、参照の差6件、移植可能な期待値を
固定していない観測9件です。nativeの実装は主張しません。外部判定器のコンパイルした6故障は、
nativeシミュレータの変異検査とは区別します。

確認した一次資料はIEEE 1800-2017の30章で、30.4.3、30.4.4.1、30.5.1〜30.5.3、30.6、30.7を
含みます。[MITが置くIEEE出版物](https://rfsoc.mit.edu/6S965/_static/F24/documentation/1800-2017.pdf)を読みました。
[2023版の公式配布](https://www.accellera.org/downloads/ieee)は特定していますが、本文は取得できませんでした
（公式endpointがHTTP 418）。**2023版の本文との節ごとの直接照合は未確認です。**
読んだ資料を2023版と記してはいけません。上の具体的な規則はnative契約の提案で、版の監査や
P1全体が完了したという主張ではありません。レビューでは公式GET配布でIEEE 1800-2023の該当節を
照合し、必要な規則に食い違いがあれば、そのコードの実装前にこの契約を改めます。
規格の本文・図・例のコードはリポジトリに写していません。
