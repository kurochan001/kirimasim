2. **あなた自身の結果を書く。** `sample.csv` と `generators.csv` の `result`・`error_kind`・`note` 欄（か、各シートの
   末尾）に書いてください。下見と違ってかまいません。
3. **Claude Code が何かを直す前に、進め方を決める。** 誤りが確定すると、TEST_SUITE の 20% の決まりが働きます。
   その章の抜き取りを 20% に上げ、同じ機構のテストを全部見直します。下見の誤りがすべて確定すると、10 章ほどと、
   選んだ生成器の多くが対象になります。決めてほしい点：
   - **規格が決めていない点。** 評価の順、プロセスの順、初期化の順を規格が決めていないのに、一つの結果に固定した
     テストと生成器があります。`choice`（`:nondeterministic: yes` と `.choice`）に移すか、テストを変えるか。
   - **16 進の小文字。** `%h`・`%x`・`hextoa` は a〜f を小文字で出します。規格の例は小文字ですが、本文は決めて
     いません。`spec` として受けるか、選択として扱うか。
   - **`static` のない初期値つきの静的変数。** いくつかの生成器が、手続きのブロックの中でこう宣言しています。
     6.21 では許されません（slang は警告だけ）。直すかどうか。
