  決めます。先に提案し、承認を受けてから変えます。

## 6. 環境のメモ

- **slang の固定。** `8ffdcdd8`（`cmake/Dependencies.cmake`）。固定を動かしたら、`FETCHCONTENT_SOURCE_DIR_SLANG` から
  slang を取るビルドは、新しい固定のチェックアウトで構成し直します。しないと、古い slang を黙って試します。
- **テスト数。** テストを足したり消したりしたら、次の順にします。
  1. `ctest --preset dev -j8 --output-junit <file>`
  2. `python3 tools/readme_counts.py update --build build/dev --junit <file>`
  3. もう一度全部流して、もう一度 `update`。
  4. コミット。

  ctest が使っているあいだは `build/dev` を作り直しません。
- **変異の確認。** 変異を当て、ビルドし、対象のテストを流し、元に戻します。流れているジョブが使っていないビルドで
  行います。
- **シェル（zsh）。** 引用符のない変数は単語に分かれません。`=` で始まるコマンド（たとえば `echo ==`）は失敗します。
- **CI。** テストのジョブは履歴なしでチェックアウトするので、古いコミットを読む道具のテストはそこで失敗します。
- **GitHub のランナー。** macOS の待ち行列は遅く、ランナーが取れずにジョブが取り消されたことがあります。流し直すのは、
  同じコミットを含む後の実行がないときだけです。

## 7. Mac と WSL2 のあいだの git の中継

Mac にある bare リポジトリ（Mac のユーザーのホームの下の `Projects/kirimasim-handoff.git`）が、2 台のあいだの
非公開の中継です。Mac のクローンでは remote `handoff` です。

- **WSL2 からつなぐ。** 一度だけ、SSH で remote に加えます。Mac の LAN のアドレスを使います（WSL2 からは `.local`
  の名前が引けないことがあります）。認証は鍵です。

  ```sh
  git remote add handoff <Mac のユーザー>@<Mac の LAN のアドレス>:Projects/kirimasim-handoff.git
  ```

  Mac のリモートログインが有効である必要があります。2026-11-14 に WSL2 からつながりました。`git fetch handoff`
  が通り、WSL2 の Claude Code が `from-wsl/handoff-2026-11-14` で返事をしています。
- **その枝を origin に push しない。** GitHub は公開です。
- **枝の決まり**（2026-10-17 から使っているもの）：
  - 頼む側が、枝 `<topic>` に `handoff/<topic>/README.md` を置きます。手順と、比べるための自分の結果を書きます。
    Mac では、作業用の worktree で `origin/main` から作り、手元の枝 `wsl/<topic>` は push の後に消しました。
  - 答える側は、`from-wsl/<topic>`（WSL2 から）か `from-mac/<topic>`（Mac から）で返します。
  - 結果のファイルには、ホームのパスとマシン名を書きません。
- **使い道。**
  - まだ `main` に出せないコミット（たとえば local CI が通っていない枝）。
  - macOS と Linux の比べ合わせ。たとえば、M8 のための Linux の測定を、2 節の macOS の試しの測定と比べるとき。
- **使わないもの：非公開の資料。** 中継には kirimasim の履歴が入っているので、非公開のファイルを入れた枝が誤って
  origin に出るおそれがあります。非公開フォルダは、同じ SSH で写します。たとえば
  `rsync -a --protocol=29 <Mac のユーザー>@<Mac の LAN のアドレス>:Projects/<非公開フォルダ>/ ~/Projects/<非公開フォルダ>/`。
  Mac の rsync は protocol 29 だけを話す openrsync なので、`--protocol=29` がないと、WSL2 からの写しは使い方の
  表示で止まります（2026-11-14）。Mac の Claude Code の記憶（メモリ）のフォルダも、同じ方法で写せます。WSL2 の
  Claude Code は、WSL2 のクローンのパスから名前を作った記憶のフォルダを読みます（2026-11-14 に確かめました）。
- **中にあるもの。** 10 月の枝が 16 本（`slang-*`、`memsafety-stack`、`from-wsl/*`、`from-mac/*`）。以前の確認の
  記録で、何もする必要はありません。2026-11-14 の移動で、`from-mac/handoff-2026-11-14` と
  `from-mac/wsl2-setup-2026-11-14`、それに WSL2 の返事の `from-wsl/handoff-2026-11-14` と
  `from-wsl/wsl2-setup-2026-11-14` が加わりました。
