# 提案：閉じた一覧で P1 を終える

[English](p1-closed-exit-proposal.md)。状態：**2026-11-07 に承認し、有効です。規則は [P1_SCOPE](../spec/P1_SCOPE.ja.md#閉じた完了一覧2026-11-07-に承認) と [TEST_SUITE](../spec/TEST_SUITE.ja.md) にあり、このノートは提案時の理由を残すものです**。英語版が正本です。

## 問題

P1_SCOPE は、Icarus Verilog 13.0 以上の実行範囲を目標にしています。同じ箇所で、厳密な範囲と完全な同等性は未確認だとも書いています。[P1 対応表](../P1_SUPPORT.ja.md#残っている作業と対象範囲)とプローブの記録も、有限の一覧では目標を確かめられないと繰り返しています。どちらの記述も正しいのですが、合わせると、どの測定でも「P1 が終わった」とは言えないことになります。

これが後のフェーズを止めています。

- SIR v1 の文法と kernel の境界の最終確定は、[P1 の完了後](sir-v1-proposal.ja.md)です。
- `src/analysis/` と `src/codegen/` は、それぞれ 10 行の仮のファイルだけです。第 2 層の実装は P2 の後の P3 で始まります。

つまり、対象の 187 プローブで差は **1 件** だけです。この 1 件は、slang を改変しない限り kirimasim 側では解消できません。上流への報告はまだしていません。

P1 を開いたままにしているのは、P1 対応表のもう 1 つの行です。動的コンテナ、クラス、VPI、スイッチレベル、specify などの「Icarus が対応する部分集合」です。その部分集合に何が入るのかが分かっておらず、調べ続けても終わりがありません。

## 提案

**次の 4 つが揃ったら P1 を終えます。** これらの外にある形は、P1 を開いたままにする理由になりません。

1. **既存の基準**はそのままです。sv-tests、固定母集団、必須テストの一覧、`valsem` との突き合わせ、人のレビュー記録を含む M8 の報告です。
2. **プローブの一覧を固定します。** 188 件を、名前とソースのハッシュで `tests/gates/p1_probes.txt` に記録します。`tests/gates/p1_population.txt` が母集団にしているのと同じ形です。この一覧に対して、`tools/icarus_feature_probe.py --extended --require-parity` が Icarus 13.0 と比べて通ることを条件にします。一覧の変更には人の承認が要ります。除外は `real_net`（承認済み）と、ソースのハッシュで指定する `dense_udp_coverage`（2026-11-07 に選択）です。後者は行を足すだけでは済みません。TEST_SUITE とツールの `independent_failure` は、除外で時間切れを許さないと定めています。改訂では、このハッシュに限ってフロントエンドの時間切れを許し、クラッシュと内部エラーは失敗のままにする必要があります。
3. **名前を挙げた機構を、固定時点の実装のまま含めます。** それぞれ機構の行列テストが通り、P1 対応表に説明があることを条件にします。対象は、VPI の最初の範囲、スカラーの specify パスと状態依存パス、承認済みの取り決めの範囲のクラス、動的コンテナ、ポートと強度、program、FST と VCD です。新しい機能は求めません。P1 が何を提供するのかを明記するためのものです。
4. **Icarus と出力が違う 25 件のプローブに、それぞれ根拠を明記します。** 根拠は規格か承認済みの取り決めです。P1_SCOPE は、こうした差を文書にし、他のシミュレータの欠陥を再現しないよう既に求めています。25 件すべてが文書になっているかは**未確認**です。

**移すもの：** P1 対応表の「必須の P1 実行ギャップ」の行のうち、一覧に名前のない形です。

| 分野 | 移す先 |
| --- | --- |
| 行列の範囲を超えるクラスと動的コンテナの形 | P4 |
| 最初の範囲を超える VPI | P4 |
| `%p` のハンドルと記憶域の形、`$fread` の形 | P4 |
| 行列の範囲を超えるスイッチレベル | P5 |
| 残りの specify パス、パルス制御、タイミング検査 | P5（2026-11-07 に選択。フェーズの表には記載なし） |

**移さないもの：** 誤った結果は、どのフェーズでもバグです。IEEE の値とスケジューリングの意味、4 値の既定、slang の厳密な診断、既存の期待値は変えません。比較ツールは情報として動かし続け、後から見つかった形は P4 と P5 の一覧に加えます。

**失うもの**

- 「Icarus 13.0 以上」という主張を取り下げ、代わりに対象の範囲を明記します。README、P1_SCOPE、TEST_SUITE の今の書き方が違うので、同時に変える必要があります。
- Icarus は動かせるが一覧にない形を使う設計は、P4 か P5 まで拒否されます。結果は誤った値ではなく、終了コード 2 と、位置付きの未対応の診断です。

**得るもの：** ツールの実行で P1 を判定できるようになり、P2 と P3 を始められます。

## 別案

- **今の目標を続ける：** 狙いとしては正直ですが、終わりがありません。P2 と P3 は待ち続けます。
- **もう 1 回だけ棚卸しをしてから固定する（選択せず）：** VPI、specify、プロセス制御、クラスの形に時間を区切って取り組み、その結果の一覧で固定します。差をより多く見つけられる代わりに、その時間がかかります。188 件を書いた時点で、これらの分野は調べ切れていませんでした。より強い主張がほしい場合には妥当で、固定の日付が遅いだけの同じ案です。

## 承認された場合

次を別々のコミットにし、それぞれ承認を受けます。P1_SCOPE と TEST_SUITE の改訂（日英）、基準のファイルとその検査、`dense_udp_coverage` の除外、P1 対応表と README の書き換え、その後に M8 の報告と判定です。P2 は[その提案](sir-v1-proposal.ja.md)から始めます。提案に残る項目（Op の一覧、正確な文法、API の宣言）は、別途レビューが必要です。

## 保守者の選択（2026-11-07）

1. 188 件で今固定する。
2. `dense_udp_coverage` をソースのハッシュで除外する。
3. specify の残りの形は P5 に移す。
4. README では、「Icarus 13.0 以上」に代えて、一覧の範囲を実行し、Icarus 13.0 と 188 プローブで比較すると説明する。

これらは方向を決めるものです。上に挙げた改訂は、2026-11-07 に差分を確認のうえ承認されました。
