状態：保守者は第 1 節の MOS 成分と遅延伝播の改定を **2026-10-29** に明示的に承認しました。
第 6 節の記録どおり、実装・検証済みです。
通常の解決と強度の根への橋渡しは、既に承認済みの program 規則に含まれます。
第 2 節は既存の承認済み flush 規則の実装であり、新しい flush 時点ではありません。

## 1. program が駆動するネットを、更新元の評価集合で解決する

承認済みの [program 改定](program-execution-proposal.ja.md) は、接続したネットの駆動と解決を
reactive な更新に含めます（24.3.2）。一方、[MOS/switch 第 6 節](mos-switch-proposal.ja.md) は、
Reactive 起源の更新を含め、dirty な強度成分をすべて Active に予約すると明記しています。
`sim.h` のカーネル API コメントも Active 固定の規則です。

通常の合成 resolver と、登録された物理寄与への橋渡しを駆動元の更新に従わせる修正は、
既存の program 規則の実装です。今回承認を求めたのは、Active 固定の成分解決と、
Inactive/Active 固定の遅延伝播方針の変更です。

`ef958a65` での調査では、通常の混在ドライバのネットと登録された強度成分の両方で、
program の `#0` 後に古い値を読むことを再現しました。
すべての resolver を常に Reactive へ動かすと module 起源の更新まで遅れるため、その方式は採用しません。

承認された意味の改定：

- active 評価集合での更新による内部ネット解決は Active で確定し、reactive 評価集合での更新による解決は
  Reactive で、後続の Re-Inactive より先に確定します。
- 成分の一括公開、完全な強度の比較、未確定更新の集約、別々の確定遷移を保ちます。
- 初期の解決は Active のままです。既存の遅延・取消し規則を保ち、予約された伝播は予約元の更新の集合を保持します。
  ゼロ遅延の Inactive/Re-Inactive も含みます。
- 通常の利用者プロセスは、宣言元・呼び出し元のスレッド集合を保ちます。program に起こされた module 手続きや
  連続代入は reactive 集合が空になってから Active で動きます。残る Reactive/Re-Inactive/Re-NBA より
  その Active の処理を先行させません。

`mos-switch-proposal.md` 第 6 節と、関連する scheduler/SIR の矛盾する記述を更新します。
内部表現は更新の集合の保持に必要な分だけ拡張します。外部 ABI の版と format-0 の版は変えません。
これは P2 の凍結ではありません。

同じ解決ネットの Active/Reactive 更新、弱い module 寄与と program の駆動・解放、登録された MOS 成分、
Re-NBA・ゼロ遅延伝播、初期状態、通常の module 待機者の従来どおりの順序を検証します。
既存テストと期待値は維持します。

## 2. 遅延レポートの破棄のため、手続きの最外スコープを識別する

[SCHEDULER_SPEC](../spec/SCHEDULER_SPEC.ja.md) 15.3・15.4 は、手続きの最外スコープを disable するとき、
保留中の遅延アサーションを破棄するよう定めます。`ef958a65` の VM は生存中のブロック実行だけを探していたため、
ブロック終了後もレポートが保留中の場合にこの規則を実行できませんでした。
名前付きの最外スコープと内側の名前付きブロックを区別する必要があります。

既存規則の実装：

- 手続きの最外の名前付きスコープを `disable` すると、その手続きの保留中の observed/final 遅延レポートを破棄します。
  実行が完了した後の保留レポートも対象です。unique/priority レポートと、既に Observed/Postponed で確定した
  レポートは保ちます。
- 内側ブロックの disable、通常のブロック終了、遅延からの再開はこの破棄時点ではありません。
  既存の event/wait 再開時の破棄規則は保ちます。
- 各 SIR プロセスに、任意の数値による最外スコープとの関連を加え、VM の生存中の実行スタックに依存せず保持します。
  front は先頭の時間制御を含む手続き本体から識別し、破棄が必要な self-disable には実際の disable 命令を出します。
  実行時の名前検索は導入しません。
- SIR で数値の関連を検証し、遅延レポートだけを破棄するカーネル操作を提供します。既存の format-0 のテキスト期待値は
  保ちます。もともと不完全な dump はこの内部フィールドを省略して構いませんが、将来の完全な SIR 表現には保持が必要です。
- scheduler の承認済みの破棄時点を変えずに、SIR 仕様へ数値の関連を記載します。外部 C ABI の版は変えません。

生存中・完了後の最外の実行、self-disable、内側の disable、observed/final レポート、維持すべき unique/priority、
呼び出したサブルーチンからのレポート、破棄してはいけない確定済みレポートを検証します。

IEEE の 2017 年版の 16.4/16.4.4 は独立に確認しましたが、2023 年版の該当段落の全文は**未確認**です。
実装の根拠はプロジェクトで既に承認した scheduler の規則であり、2023 年版を確認したという新しい主張ではありません。
その主張を加える前に、正当に利用できる版で 2023 年版の該当条項を確認します。IEEE の本文や例は転載していません。

## 3. 実装変更の根拠とならない、報告された期待値

- #63 の最初のテストは、Re-NBA に起こされた module の待機者が Reactive の待機者より先に動くと期待しています。
  これは承認済みの reactive 集合を空にする規則と矛盾します。program がすぐ完了すると、Active の待機者より先に
  実行自体が終了する場合もあります。
- #62 の構文テストは、後続の代入の後に遅延アサーションの式を評価すると期待しています。
  式と値渡し引数はアサーション文の時点で捕捉し、レポート・アクションの実行だけを遅らせます。
- #62 の latch テストは、latch 自身が書く変数の変更で同じ latch が再開すると期待しています。
  ここには暗黙感度の除外規則が適用されます。

これらの期待値を満たすために実装の意味を変えてはいけません。
既存の外部テストを直す場合は、別の変更とします。

## 6. 承認済みの MOS・遅延伝播の実装

2026-10-29 に承認した改定は `b20b223f` で実装しました。
dirty な強度成分は Active と Reactive に独立して予約し、初期の解決は Active のままです。
native の Reactive callback が bank を起動する場合も同じです。通常の module プロセスは宣言元のスレッド集合を保ちます。

通常の遅延ドライバ、強度の起源、導通更新は、予約イベント内にスケジューリング集合を保持します。
明示的なゼロは Inactive/Re-Inactive、正の遅延は期日の Active/Reactive を使います。
同一の保留更新は期限と集合の両方を保持し、取消し、完全な状態の公開、別々の確定遷移を維持します。

新規ソース回帰 3 件とカーネルテスト 6 件で、経路の組合せ、根・導通、初期状態、集合をまたぐ保留の保持と取消しを検証します。
関連するコンパイル済み変異 4 種類はすべて単体のアサーションで検出し、その後ソースを復元して再検査しました。
全 910 件の変異定義が適用可能です。

[根拠](program-strength-region-expectations.ja.md)を記載しました。値・順序・Inactive・プロセス回数の検査は維持します。
