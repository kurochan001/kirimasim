## 理由と証拠

IEEE 1800-2023 の 28.8 節と承認済み [MOS/スイッチ契約 3/6/7 節](mos-switch-proposal.ja.md)
は受動伝搬を対象とします。新しいソース変換で、6 種の受動スイッチを既存の型付き SIR と
共有カーネルに接続しました。最初の独自 139 設計が通り、静的な強度、両方向、制御、
プリミティブ配列とポート接続、完全区間の感度、循環と遅延を含みます。
互いに独立した網は別々に解いてから一括公開し、65/129 ビットの混在制御でも無関係な辺の
組み合わせを掛け合わせなくなりました。さらに検証を進めています。

変更していない `tests/cli/unsupported_matrix/switch_bidirectional.sv` は、module、
generate、子 module に裸の tran を含みます。現在は終了コード 0、標準出力なし、情報以外の
診断なしで動きます。`tests/tools/check_source_mos_boundaries.py` の変更していない
`wire a,b;tran m(a,b);` 入力も同じです。根のない常時導通網は適法で、Z のまま静止します。
どちらの入力も出力を要求しません。ファイル名や形で拒否を残すと、CLAUDE.md の機構単位の
実装規則に反します。

## 依頼する変更の全体

人の承認後に限り、[未適用パッチ](passive-expectation-migration.patch)を、`src/` 変更なしの
別コミットで適用します。

1. 未対応 generator の `ACCEPTED` に `switch_bidirectional` だけを追加します。
   生成版 19 と全ソースのバイト列は維持します。
2. `tests/cli/unsupported_matrix.accepted` にその名前だけを追加し、
   `tests/cli/unsupported_matrix.stderr` から古い 3 診断（12:10、4:8、9:8）だけを除きます。
3. source-MOS 境界の入力 6 件はすべて維持します。裸の tran だけを「コード 0、標準出力なし、
   情報以外の標準エラーなし」に変えます。他の 5 件のコード 2、位置付き診断と既存 assertion
   は維持し、スキップ・削除・入力の置き換えはしません。
4. CLI 全体と境界検査、および適切な回帰確認を実行して結果を記録します。
   公開や push の承認を求めるものではありません。
