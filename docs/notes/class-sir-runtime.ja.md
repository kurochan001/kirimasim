# class の実行：SIR の実装段階

[English](class-sir-runtime.md) · 英語版が正です。

[共有カーネルの実装段階](class-runtime-kernel.ja.md)に続き、
[承認済みの class の契約](class-runtime-proposal.ja.md)の1、3〜8、10節に沿って、
SIR の表現と検証を実装しました。**ソースの class の実行と、VM の実行処理の接続はまだです。**
class の契約全体や P1 の class 要件が完了したとは扱いません。

## 型と記述

`class<!cN>` が静的な class の型を保持し、オブジェクトの動的な型と分けます。
`ClassId` は既存のコンテナの `TypeId` と別です。
宣言スコープ、基底・interface、final・abstract、自身が宣言するフィールドと固定次元、
const・初期化の有無、static のスロット、構築用の関数、弱参照の型、仮想スロットの対応を保持します。
フィールドの型の再帰は許し、継承の循環は拒みます。隠された同名フィールドは宣言元の番号を保ちます。

仮想スロットの型と実装を分け、interface に実行本体を仮造しません。
所有元、引数の値の型・次元・方向、中断の形、戻り値、基底から継承する実装を検証します。
同じスロットの実装は中断のフラグを揃えます。`mayWait` は待機を許す印で、各呼び出しが必ず待つという意味ではありません。
static メソッドは implicit receiver を持たず、通常の automatic な呼び出しになります。

class の定数は型付き null だけです。class の記述番号を通常の値に使ったり、
算術、型の無い ref、任意の builtin やシステム関数からハンドルを作ったりする形を拒みます。
コンテナに class のハンドルを値として入れる際も、要素の型を保ちます。
従来の設計のテキストは増やさず、新しいダンプには class・field・仮想スロット・構築の所有元を出します。

## 構築と呼び出し

インスタンスメソッドの最初の入力は、再代入できない receiver です。
構築用の関数は、宣言元の class に登録された、待機しない automatic function です。
割り当てか直接の基底の構築からだけ入り、通常の call や遅延レポートからは呼べません。
割り当て、コピー、互換な型への変換、キャストの検査と値、識別子、乱数状態の seed、
プロパティの読み書き、メソッド、弱参照の操作を命令で表します。

構築の段階は呼び出しに属する内部状態で、ソースの値や偽造できる SSA の権限値にはしません。
制御フローの検査で、直接の基底、自身の段階の開始、宣言初期化、本体、完了の順を確かめます。
本体へ入るすべての経路で必要な初期化が済んでいることと、通常の return より前の完了を検証します。
初期化は、その呼び出しの自身のフィールドだけに行い、固定配列では宣言順に全要素を渡します。
const の宣言初期化と本体での代入の権限は別です。
実行時の一度限りの代入は、接続後に既存のカーネルの構築権限と初期化ビットで検査します。

仮想呼び出しと直接呼び出しを分けます。待つメソッドには task 用の形と継続ブロックを要求し、
待機前の SSA を待機後に使えない既存の規則も適用します。
引数式の副作用は命令より前に終える表現です。フロントエンドの接続時には、
実引数より先に一度評価する receiver の保持と、承認済みの null 検査・copyback の時点も守る必要があります。

`object.cast.check` はリテラル null と型付き null を区別します。
内部の値を返す命令は失敗時に型付き null を返すので、ソースの `$cast` の変換では、
検査結果で書き込みを分岐し、失敗時に代入先を変えないようにします。

## 参照と receiver の所有元

`ref<class<!cN>>` と `ref.readonly<class<!cN>>` で、型と書き込みの権限を保ちます。
読み取り専用の参照を mutable な ref 引数へ渡す形や、通常・NBA の書き込みを拒みます。
変数・配列全体・選択した要素の形は、生成命令、格納する参照の宣言、
ブロック引数に入るすべての経路から検証し、トークンのビット列から推測しません。

guard のフレームの共有と fork の capture も、既存の字句上の所有元から辿ります。
数値のフィールド番号を固定点まで伝え、ネイティブの再帰や命令ごとの全関数検索を避けます。
capture の後でも、ストア・mutable な参照・copyback で `this` を再代入できません。

## 実行の境界と残り

VM は、定数の登録、スロット、activation、オブジェクトの割り当てより前に class の記述を検出します。
不正なら `invalid class SIR`、正しい記述でも実行処理が未接続なら、その旨を明示して停止します。
どちらも VM API の既存の internal load error の結果を使います。
フロントエンドの既存の未対応の診断は変えていません。
新命令や未接続の class の値を、古い実行経路で黙って動かすことを防ぐ境界です。

slang の型の収集、構築・メソッドの変換、カーネルへの実行の接続が残っています。
境界を外す前に、すべての格納域、一時値、保留する値、receiver、中止時の解放まで接続する必要があります。
プロパティと class コンテナ要素の ref、プロパティのビット・NBA の対象、unpacked 構造体のフィールド表現、
event フィールドのルート、監視、書式、ソースの全配置の行列も残ります。
class コンテナ要素の ref は、型の無い参照として通さず、明示して拒んでいます。
