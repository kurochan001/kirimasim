# 実行時の配列メソッド：実装時点の記録

[English](runtime-array-methods.md)が正です。状態：一部を実装、2026-10-25。

人が承認した[縮約・整列](array-methods-proposal.ja.md)と
[min/max](array-extrema-proposal.ja.md)の決定を、VALUE_SEMANTICS 7.9、SIR_SPEC 5.8/6、
RUNTIME_ABI 6へ反映済みです。考え方の出典は、その決定、IEEE 1800-2023の
7.12.1–7.12.3・13.5.2と、このリポジトリの既存の型付きの値・参照演算です。
他のシミュレータの実装やテストは読んでいません。テストは独自作成で、新しい依存はありません。

## 共通の変換と値の交換

`Lowerer::lowerArrayMethod`が式・文の両方から縮約・min/max・整列を処理します。
固定配列は宣言の左から右、動的配列・キューは位置の昇順です。従来の固定配列だけの
縮約変換は削除しました。走査、最初の値の扱い、安定な比較、キーの評価はfrontで決め、
算術と比較には既存の共有命令を使います。VMに別の意味の判断は加えません。

`container.swap.values`はコンテナのrefと整数の添字2個を取る、型付きのSIR変更命令です。
終端命令ではありません。verifierが記述子・ref・個数・添字型を検査します。VMは実際の
受信型・上限と、既存の幅を保つ添字判定を使い、`Heap::swapValues`へ委譲します。
不明・負・範囲外・同じ添字なら何もしません。カーネルは既存セル内の正規化された語だけを
交換し、割当てやセルの置換を行いません。両方の交換が完了してから、値が変わったセルだけを
通知し、構造の変更は通知しません。入れ子の所有ハンドルをそのまま移すため、内部のrefも
保持します。固定記憶域も言語上のコピー代入ではなく、生の型付き要素格納で同じ移動をします。
valsemの参照モデルは参照先の値を独立に交換します。tier 1は従来どおりC++ APIを直接呼び、
C ABIは0.3のままです。

空でない縮約は最初の実際の値から始め、単独のZを全メソッドで保持します。空のproductは1、
整数のandは全ビット1、その他は0です。`with`が結果の型を決めます。実行時の配列呼出し式は
slangの定数畳込みを使わず、より大きい実行時の式でも承認済みの規則を保ちます。
slangが先に畳み込んだparameterの形は、制限として残します。

min/maxはキーの前に受信配列の値を保持します。固定配列は一時的な型付きキューへコピーし、
動的配列は共有snapshot命令を使います。最初も含め各キーを1回だけ実行し、比較が確実に真の
場合だけ候補を変えます。結果は独立した上限なしキューで、空か、キーでなく元の要素をちょうど
1個返します。入れ子の値も既存の追加・コピー演算で独立に複製します。

sort/rsortは純粋なキーを先に保持してから隣接交換し、reverseは対になる値を交換します。
X/Z・浮動小数点の比較不能値から全順序は作りません。今回の整列は二乗時間です。
将来の高速化でも比較と参照の規則を保つ必要があります。

## 独立した検証

[生成器](../../tools/gen_array_methods_matrix.py)はPythonの整数演算、明示した4値の真理値表、
不明なキーで区切った連続区間の安定整列から、264ソースと期待出力を作ります。
シミュレータの出力を期待値には使いません。

- 整数180件：固定/動的/キュー × initial/automatic/ref × 1/9/32/65/129ビット ×
  符号あり/なし × 2値/4値。全10メソッド、空・単独、X/Z、同値の安定性、型付きの
  ビット演算キー、32ビットのint/integerへの射影を検査します。2値変換と4値保持を区別します。
- real/shortreal/文字列36件：上限付き実キューを上限なしのref仮引数へ渡す形も含め、
  3種類の実行場所を検査します。
- 要素ref保持24件：単一値・入れ子、固定/動的/上限なし・ありの受信配列と3種類の実行場所。
  選んだ入れ子の結果を変更してコピーの独立性も検査します。
- キーの副作用6件：固定/動的/キューのmin/maxについて、回数、走査の記録、受信式の評価、
  キーの途中の元配列の変更、空の入力でキーを呼ばないことを検査します。
- NaN9件：ビットでペイロードを出力し、先頭・中間・末尾の比較不能キーを検査します。
  名前付き・入れ子のwith9件でも、結果コピーの独立性を検査します。

直接テスト4件では、カーネルと独立したvalsemモデル、入れ子の所有値・GC・複製しない交換、
不正なSIRの型・引数、手書きSIRの実行を検査します。カーネルの行列は幅・値数・コンテナの
各組で有効/無効の添字150組を使い、全要素のrefと通知を検査し、交換中のヒープ割当てを
禁止します。VMは129ビットの正・負・不明・範囲外の添字も検査します。
264ソースと直接4件はdevで成功しました。全構成と実際にビルドした誤実装の結果は、
検証時点の記録へ追記します。

## 残作業

P1や配列メソッド全体の完了ではありません。その他の検索、shuffle、固定複合型・class・
eventの要素、未対応の入力表現が残ります。副作用のある整列キーは拒否し、ユーザー関数の
純粋性もまだ証明しないため、その整列呼出しも保守的に拒否します。min/maxのキーの副作用と
入れ子の縮約には対応します。slangが整数以外の縮約を拒否する診断は緩めません。
parameterの畳込み、広い範囲の性能、Icarusとの全面的な機能同等性は未確認で、対応する
完了条件と独自の比較による確認が必要です。
