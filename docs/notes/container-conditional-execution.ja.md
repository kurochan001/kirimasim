# 動的配列・キューの条件式

## 規則と実装

根拠はVALUE_SEMANTICS 3.1・3.9・3.14・1.4とIEEE 1800-2023
11.4.11・11.4.5・6.8・7.5・7.6・7.10です。既存の承認済み契約に従い、仕様は変更しません。
外部の実装・issueの再現コード・規格の例は使っていません。ソース・期待値・故障は独自に作り、
新規テストの期待値には`spec_check: ai`を記します。

`Lowerer::lowerContainerConditional`を、対応済みの動的配列・キュー型の条件式の
共通入口にします。既存の型付き真偽演算で条件を判定し、真偽が既知なら選んだ側だけ、
X/Zなら左・右の順に両側を評価します。広い条件で既知の1を含めば、他にX/Zがあっても真です。
実行した各オペランドの値を、後のオペランドによる変更より先に独立して保持します。
相対的な評価順は承認済みのプロジェクト方針であり、slangのread/write警告は抑えず維持します。

`Lowerer::mergeContainerConditional`が不定条件の統合を行います。長さが違えば配列全体の
既定値である空を返します。同じ長さなら、各要素全体の`==`が確実に真の場合にその要素を残し、
それ以外は要素型の既定値にします。配列をpacked整数のようにビット単位で統合しません。
同じZを含む要素同士でも、論理等価は確実な真にはなりません。既定値は4値整数なら全X、
2値整数・real・shortrealなら0、文字列・入れ子の配列/キューなら空、chandleならnullです。
既存プロジェクトのスカラー型と既定値の規則に従います。

`Lowerer::definitelyEqualValues`は、スカラーの末端を`compareValues`と既存の値演算で
比較します。入れ子の要素は確保ハンドルではなく長さと内容で比較し、不一致・不定なら空にします。
要素全体の比較であり、入れ子の異なる末端を再帰的に条件統合する処理ではありません。
入れ子を含め結果の記憶域は元の両値から独立します。式のバッファには入れ子を含めキューの
上限を適用せず、通常の代入・copybackで実際の代入先の上限を適用します。

frontは既存の型付き分岐・ブロック引数・snapshot・要素読み取り・キュー操作だけを出します。
VM/kernel、SIR formatVersion 0、C ABI 0.3は不変です。automatic/static task、fork、
interface、package、program、generate、クラスのstaticメソッド、関数の戻り値、構造体メンバー、
ref、遅延付き値全体NBAも同じ式の入口を通ります。ヒープに依存する明示的なwaitは、既存の
依存捕捉・回収を使います。依存の追加・書き換え可能な大域状態・性能予算の変更はありません。

等長・異長・空、要素全体の既定値、入れ子の比較と独立コピー、副作用付きオペランドと代入先選択、

## 制限と残作業

対応済みの要素・記憶域表現だけを有効にします。クラス/event object、固定集約値の要素、
連想配列、patternを伴う条件、固定配列と動的配列を混ぜたオペランドは未対応または未確認です。
対応と記す前に、表現ごとの独自実行テストが必要です。固定集約値の条件式を処理する別経路は
変更しません。暗黙のヒープ感度は引き続き明示的に未対応です。キューのスライスへの代入、
追加の配列メソッド、READMEにある他のP1機構も残っています。機能検査から速度の同等性は
主張しません。速度の主張にはPERFORMANCE.mdの計測手順を使います。
