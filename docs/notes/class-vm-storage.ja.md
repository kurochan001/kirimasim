# class の実行：VM の格納と値の接続

[English](class-vm-storage.md) · 英語版が正です。

[class SIR の段階](class-sir-runtime.ja.md)に続き、
[承認済みの class の契約](class-runtime-proposal.ja.md)の1、3〜6、8、10節に沿って、
SIR の格納の記述と保持する値を共有カーネルに接続します。
**class 命令の実行と front は未接続です。** VM の既存の割り当て前の拒否は保っています。
ソースの class の実行や P1 の class 要件の完了とは扱いません。

## 共通のヒープの記述

`vm::detail::HeapPlan` がコンテナと class の記述を変換します。
インタプリタの既存の `prepareHeap` も、通常のコンテナの登録に同じ処理を使います。
コンテナの番号と SIR の型の行番号は別に保持します。
class は記述の順を保ち、再帰的なフィールド型と、基底が派生より後の番号である場合も扱います。
仮想メソッド・宣言元・const・初期化の有無・interface・弱参照の型は数値でカーネルへ渡します。
実行中にソースの名前で探索しません。

固定配列は型付き要素を宣言順に繰り返します。二値・四値の初期値と末尾の語のマスク、
class・string の異なる参照辺、入れ子のコンテナの型を保持します。
event フィールドは、独立したイベントの識別子とルートが未接続なので登録前に拒みます。
型のない整数のフィールドにはしません。

関係する記述をすべて調べてから登録を始めます。資源不足では、使われない不変の型・レイアウトの行が
残ることはありますが、plan・class 表・ソースのオブジェクト・cell・コンテナ・pin・乱数の消費は公開しません。
失敗後に同じ完全な記述でやり直せます。カーネルの class 表の登録は原子的で、その後に失敗しうる処理は置きません。
設計と Context は plan より長く生存する必要があります。

## 型付きの値と保持する対象

`localObject` と `objectValue` が、Context 内の VM の語（a はトークン、b は0）と
カーネルのトークンを変換します。外へ出す前に、元の所有 Context・世代・静的な class の互換性を検証します。
ローカルの語は供給元の Context に属し、ビットだけで別の Context の所有を証明しません。
ヒープの object 語の所有元タグは型付きの境界でだけ付けます。ソースの値・識別子・呼び分けには使いません。

`ObjectProperty` は、最初に選んだ宣言元のフィールドとオブジェクトの pin を保持します。
ハンドル変数を再代入しても対象は変わりません。move では保持を移し、元のアクセスを無効にします。
線形の要素選択では型と語の範囲を保ちます。class 配列の全要素を変換してから公開するので、
不正な型・世代・語や割り当て失敗で先頭だけを変更することはありません。
正規化、コンテナの値コピー、readonly、構築権限、const の意味はカーネルに任せます。
保持するのは格納域であり、プロセス・実行位置・callback ではありません。Context の生存が必要です。

`ObjectTransfers` は引数・戻り値・copyback の class のスカラーと配列を pin できます。
失敗時はそのグループだけを解放し、以前のグループを保ちます。巻き戻しでは確保しません。
opaque な語と ref・const ref はオブジェクトと推測せず、呼び出し側が参照先の型付き格納域を別に保持します。

ヒープの記述を先に登録すると、`ActivationPlan` は class フィールドを静的な class view 付きの
Object としてカーネルへ渡します。scoped フィールドと fork の capture に同じ検証とルート列挙を使います。
すべての join の形で親の終了後も元の binding を保持し、書き込みで型を変えられません。

## 検証と残り

追加の18テストは、幅1・32・65・129・257と二値・四値、固定配列、前方の class、異なるコンテナ番号、
呼び分けの番号、再帰するオブジェクト、入れ子の値コピー、string の辺、opaque なハンドル、
別の Context・古い世代、保持と move、const の構築、失敗時の受け渡し、scoped と capture、
記述のすべての割り当て位置での失敗を検証します。front を介さず、実際の heap と activation を使います。
17個の変異を追加し、既存のコンテナの初期値の変異は、コンテナだけを壊す性質を保って共通処理へ移します。

class SIR 全体は引き続き割り当て前に止まります。class 命令、構築・メソッドの呼び出し、
インタプリタのすべてのルート・保留値の公開を接続してから境界を外す必要があります。
property とコンテナ要素の ref・bit・NBA、managed event、依存の監視、ソースのキャスト・書式、
slang の canonical な型の収集も残ります。既存の拒否テスト・スイート本体・期待値・性能予算は変えていません。
今回は格納の接続の段階なので、機能プローブと P1 母集団は再測定していません。
