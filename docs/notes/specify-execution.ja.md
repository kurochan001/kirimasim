# 最初のスカラーspecify実行

[English](specify-execution.md)。2026-11-02。

[承認済み契約1〜8節](specify-p1-proposal.ja.md)の最初の範囲を、型付きSIR、
第1層、共有kernelへ接続しました。`parse`は従来どおりエラボレーションだけを確認します。
時間処理を黙って無視するスイッチはありません。

## 対応する境界

module cellで、スカラー4値の入力net、スカラーwire/tri出力net、単純・完全接続のpath、
複数のスカラー入力・出力、無条件のposedge/negedgeの資格、データ・極性の注釈を扱います。
各出力の機能ドライバは、通常の連続代入または固定強度の組合せlogic primitiveの1本です。
内部の手続き的な状態を、その代入へ渡せます。specparam/parameter、実数の丸め、負の値の
ゼロへの制限、min/typ/max、1/2/3/6/12個の遅延、階層・generate、force/release、
monitor、VCD、VPIの読取り・callbackを接続しました。

vector・選択・variable・inoutの端子、受動接続または複数ドライバの出力、
three-state/MOS/UDPの機能ドライバ、条件付きpath、明示的なpulse control、PATHPULSE$、
SDF、timing checkは位置付きのエラーで拒否します。P1の新しい例外ではありません。
`wire real`の方針も変えません。契約の2023版との直接照合は未確認のままで、読んだ
一次資料の時間処理の本文は2017版です。

## 時間処理と所有関係

出力の12遷移に、別々の選択済み遅延を持ちます。省略したXへの到着は最も早い端点、
Xからの出発は最も遅い端点を使います。入力の実際の値変化をcallbackより先に所有する時計へ
記録します。資格のある最新入力を選び、同時刻なら最小の遷移遅延を選びます。同じセルでは、
絶対path期限と分布遅延の機能到着の大きい方を使います。直列の別セルは、前段の確定した
公開到着から時計を更新します。

元の物理originが、確定した寄与と、完全な予約区間・世代を所有します。同じ予約値なら期限を保ち、
確定した寄与へ戻ればパルスを取り消し、古いタイマーは公開しません。期限到達・ゼロの更新は
Activeです。forceは公開netを固定し、その下の更新は継続します。releaseは現在の確定した寄与を
読み、将来の期限を早めません。公開ポートの別名、通常の値・強度の読取り、monitor、VPI、VCDは
同じ確定した値を見ます。非公開の機能carrierをreflectionへ出しません。注釈は実行せずRNGも消費しません。

SIR行はinstance・入力・公開出力・非公開結果・origin・所有者の数値IDと、正規化した12遅延を
結び付けます。正の範囲超過は選択まで明示したまま保持します。VMのスロット割当前に、
不正な束縛・所有関係を拒否します。外部net参照の権限はVPIのnet束縛だけに制限し、通常の書込みや
外部の書込み可能な変数へ転用できません。kernelのslang/SIRへの依存と公開C ABIの変更はなく、
公開ヘッダはC++20のままです。

## 確認した証拠

native行列は**正常実行105件と、期待した位置付きの拒否16件**の計121件です。
遷移・遅延個数の全60組、initial/always、static/automatic task、function、fork、generate、
interface、program、package、refの文脈での入力変化を検査します。個別ケースはforceの期限、
内部・外部からの見え方、強度の同時観測、複数出力、generateのインスタンス、直列セルを扱います。
**新規単体82件**では、独立した値の参照、実行時の時間処理、広い入力アドレス、資源不足後の再試行、
独立性、不正SIR、VPI/VCDの一致を検証します。

[コンパイルしたnative変異15件](../measurements/2026-11-02/specify-native-controls.json)は
すべてビルドでき、実行の意味または所有権の検査で検出しました。Xの選択、入力の選択、遅延加算、
ゼロの領域、古いタイマー、公開・非公開ポートの混同、注釈の実行、force中の予約の喪失、VPI通知の
欠落を含みます。ソースを復元し、nativeの両方の基準検査が再度通過しました。登録簿自体の検査失敗と
ビルド失敗は検出へ数えません。

[同じ176プローブ](../measurements/2026-11-02/icarus13-scalar-specify.json)は、全ソース・期待値・
P1分類を保持します。`specify_path`は、従来の期待どおり早い時点の0と遅い時点の1を出力します。
必須範囲の差はdense UDPのフロントエンドの時間超過1件です。任意の`real_net`と参照不一致25件は
別に残します。この有限の一覧だけではP1や残る時間処理の機能範囲を完了しません。
[102ケースの棚卸し](../measurements/2026-11-02/specify-execution-inventory.json)は、nativeで
期待値と一致83件、未対応16件、固定した期待値のない実行3件を記録します。その観測をnative成功へ
書き換えません。母集団、sv-tests、Icarus 14.0は再測定していません。

[従来の期待値1件の移行](specify-expectation-migration.ja.md)は別途承認・コミットし、入力のバイト列を
保ちました。途中の接続で、無関係な未対応宣言の診断件数が変わりましたが、`4aa68356`で従来の診断の
走査を復元しました。元の診断記録とCLIオプション行列は変更せず通過しました。件数は全件成功した
完全なdev JUnitからだけ更新し、実装と別コミットにします。push前にはlocal CI全体を実行します。

dev全体は**11,447/11,447件**が通過し、失敗・skipは0件でした（130.23秒）。[検証メタデータ](../measurements/2026-11-02/specify-execution-validation.json)に、凍結したソース・期待値の照合、復元した変異、成功したJUnitを対応付け、件数だけのコミットは`b62cf990`です。過去の母集団・sv-tests・14.0の記録は測定日を維持します。
