# 状態依存のスカラーspecifyパス：次の実行契約案

[English](specify-state-dependent-proposal.md) · 2026-11-03。

**状態：提案、保守者の承認待ち。実行機能は有効にしていません。**
9節の版の制限を明示したうえで、1〜8節の承認を求める案です。最初のspecify契約の
1・3・6・7節、SIR_SPEC 6、共有スケジューラのmodule-path選択を改定するものです。
P1の完了条件は変えず、既存期待値の移行を承認するものでもありません。

既存契約は、状態依存パスを実装する前の追加レビューを明示的に求めています。
[新しい独自比較](../measurements/2026-11-03/specify-state-dependent-inventory.json)は40入力で、
Icarus 13.0は事前に書いた時刻列32件と一致し、X/Z条件8件で異なりました。
nativeは40件ともparseに成功し、実行時の変換では40件とも未対応として拒否します。
残っている機構を測ったもので、P1のゲートに40件を追加するものではありません。

## 1. 最初に追加する範囲

単純な状態依存スカラーパス`if (condition) (a => q)`と、そのスカラー完全接続形、
単純な`ifnone`の既定パスを追加します。最初の契約のmodule instance、入力net、
wire/tri出力、通常の機能driverが1本という条件は保ちます。複数のスカラー端子は、
条件をグループ化する前に独立した入力・出力の組へ展開します。

条件は、定数・specparamと、定義元moduleのstatic整数変数・netを読めるものとし、
定数位置のbit/part選択も含めます。module-path式の合法性は固定版slangの検査を保ちます。
受理したビット・論理・等価・連結・反復連結・条件演算は既存の値の規則で変換し、
パスの有効判定だけを後述の規則で行います。未対応の条件表現は位置付きソースエラーにします。
副作用のある呼出し、automatic記憶域、class/containerハンドル、実行時に選ぶ格納先、
階層を越える読み取りは条件の評価器へ追加しません。

条件付きのエッジ依存パス、既定パスとエッジ依存宣言を混ぜるグループは後続の範囲に残します。
既存の無条件エッジ依存パスは従来どおりです。ベクトル端子、出力変数、受動接続・複数の
機能driver、明示pulse control、SDF、timing checkも、既存の未対応境界を保ちます。
これらの制限を、必要な機構をP1から除外する理由にはしません。

## 2. 4値の条件からパスを有効にする規則

条件の最下位ビットを使い、0なら無効、1・X・Zなら有効にします。上位ビットが1でも
最下位ビットの0を真にはしません。したがって`2'b10`は無効、`2'b1x`は有効です。
通常の手続き的`if`、論理reduction、イベント制御の`iff`とは違い、それらで代用しません。

この変換は値の参照実装の1か所で定義し、スカラー4状態と幅の広い値を独立に検査します。
最下位ビットを取り出すまでは、条件式の幅・符号・4値演算の規則を保ちます。
X/Zを0へ置き換えず、Icarusの出力からnative期待値を作りません。
記録した参照差8件は、差として見えるまま残します。

## 3. 条件を読む時点と既定パスのグループ

変化した機能寄与のpath期限を選ぶ時点で、その時点の確定済み記憶域から条件を評価します。
入力イベントの時点に有効・無効を固定しません。各条件は1回の選択につき1回読み、
利用者の副作用や途中のスケジューラ実行を入れません。epoch zeroの評価は既存のstatic初期化後、
従来の初期path clockのもとで行います。

条件だけの変化では機能結果や入力遷移を作らず、保留中の公開時刻も変更しません。
入力の強度だけの変化ではsource clockを進めません。同一の保留寄与、確定寄与への戻り、
取消については、新たなpath選択より前に行う既存契約の判断を保ちます。

定義元instance内で展開済みの入力・出力の組ごとに、単純な条件付きパスと、あれば単純な
既定パスをまとめます。`ifnone`は、対応するすべての条件が無効なときだけ候補になります。
対応する条件付きパスが無ければ、無条件の単純パスとして扱います。
すべての条件の最下位ビットが0なら既定パスが有効になり、1つでもX/Zなら抑制します。

同じ組に既定パスと無条件の単純パスを置くなど、不正な組合せの厳格なエラーは保ちます。
既定パスの重複や不正なグループも拒否します。同じ組への異なる条件付き宣言は許し、
複数が同時に有効でもよいものとします。既定パスが無い場合の合法な無条件パスは、
有効な条件付きパスとともに選択に参加します。

## 4. 既存の時間処理で期限を選ぶ

現在の条件・既定パスのグループで候補を絞り、既存の適格なsource clockに従って、
最も新しい入力時刻を選びます。同じ時刻の候補では、対象遷移の遅延が最小のものを選びます。
全体で最短のパスを、より新しい適格な入力より先に選びません。候補が無ければ通常の
機能到着を使います。条件のためのsource clockは追加しません。

12遷移の遅延表、5種類の遅延リスト、min/typ/max選択、精度の丸め、overflow処理を保ちます。
期限は機能到着と「入力時刻＋選択したpath遅延」の最大であり、pathと分布遅延の和にはしません。
そのため、分布遅延の間の条件変化は機能到着時の選択に反映します。

慣性フィルタ、完全な保留寄与の所有、世代による取消、Activeでの公開、資源上限、割込み、
finalと終了時の後始末は最初の契約を保ちます。transport timingや新しい領域は追加しません。
ゼロ・期限経過済みの公開は、moduleのInactiveでの`#0`観測より前に見えるようにします。

## 5. ポート・force・観測・所有

非公開の機能寄与、元の物理driver、公開された遅延出力を保ちます。条件がローカルの出力を
読む場合、forceも含む公開の確定値を読み、隠し機能carrierは読みません。
条件のために追加のdriverや利用者から見える隠し信号は作りません。

出力がforceされている間も、機能更新と、そこで選んだ保留path期限は進めます。
後の条件だけの変化では期限を変えません。releaseは現在の確定寄与を読み、過去の条件を
評価し直したり、将来の処理を前倒ししたりしません。VCD/FST、monitor、VPIは同じ公開値を見ます。
同じmodule定義でも条件が異なるinstanceを含め、instanceとContextの状態を独立に保ちます。

## 6. 型付きSIRとkernelの接続

静的なpath行へ、有効判定の種類（無条件・条件付き・既定）、必要な数値の条件評価器ID、
数値の既定パスグループbindingを追加します。グループは所有者・入力・出力の組を表し、
端子名の文字列、宣言順、遅延でまとめません。ソートやポート正規化でも元のpath IDを保ちます。

frontは、条件の最下位ビットを4値1ビットとして返す読み取り専用のstatic評価器へ変換します。
既存のwatch/subroutine基盤に専用の検証済みの役割を加える形を使えます。
利用者frame、引数、書込み、待機、heap割当、RNG、イベント予約は持ちません。
SIR検証は実行前に、評価器の型・許す命令・ローカルbinding、グループの所有・所属・重複、
既存の機能driverと端子の不変条件を確かめます。未対応のソースはfrontのエラーにし、
不正IRの失敗へ変えません。

VMは型付きSIRを機械的に評価するcallback接続を渡します。有効判定の変換、グループの
絞込み、clock選択、時間処理は共有kernelが行います。callbackのmetadataと記憶域は、
構成とすべての保留処理より長く生存させます。構成は検証・割当を成功時だけ確定します。
失敗は既存の位置付き・資源エラーの経路で返します。可変状態はContextが所有し、
終了後のcallbackや、別のContextへの混入を許しません。

kernel公開ヘッダのC++20、公開C ABI、依存関係を保ちます。実行時の名前検索、新しい依存、
可変global、隠し利用者プロセス、RNG所有者は追加しません。条件付きパスが無い設計では、
既存の経路と性能回数の動作を保ちます。

## 7. 承認後の実装に必要な検証

独立した条件・グループの参照、共有kernel選択、SIR検証・テキスト、VM接続、frontと観測の
順に、レビュー可能な段階で実装します。同じ共有アルゴリズムを通る機構を検査します。

- スカラー4状態、幅の広い0/1/X/Zの最下位ビット、純粋な式・定数選択、ローカル変数・net・
  parameter、独立したinstance。
- 有効パスなし、条件の無い既定パス、有効パスの重なり、既定パスの抑制、異なる入力、
  最新入力の選択、同時刻の最小選択。
- 分布遅延の機能到着の前後で条件が変わる形、保留中に条件だけが変わる形、同一寄与とパルス。
- 出力の12遷移、5種類の遅延リスト、ゼロ・overflow、min/typ/max、初期評価、通常とforce中の
  公開出力、観測、終了時の後始末。
- 不正な評価器・グループ・所有者binding、読み書きと寿命の違反、割当失敗、Contextの独立性。
  影響のない診断は保つ。

最下位ビットの代わりに通常の真偽を使う、真の条件と既定パスを同時に有効にする、
条件を早く固定する、最新入力より先に全体の最小遅延を選ぶ、条件だけで期限を変える、
force・instanceの所有を失う、というnative変異を実際にコンパイルします。
値・時刻・所有のアサーションで検出し、ビルドエラーや変異登録簿自身の検査は数えません。
ソースhashを復元し、基準検査と全local CIを再実行してからpushします。

今回記録した[3件の対照実験](../measurements/2026-11-03/specify-state-checker-controls.json)は、外部比較の判定器だけを検査したものです。
nativeの変異ではなく、上の要件を満たしたことにはしません。

## 8. 既存期待値と完了判定

元の102件の棚卸し、176件の比較、固定P1母集団、リポジトリのfixture、ゲートの分母を保ちます。
新しいツールモードは独立した棚卸しで、CIの合格率ゲートには追加しません。
棚卸しの終了成功は、独立した失敗なく記録したことを表します。native未対応や参照差を
PASSにはしません。厳格な期待一致モードでは参照差8件に対して失敗します。

この案で既存の診断・時間の期待値移行は承認しません。変更前に対象入力・理由・節番号・
具体的な置換案を示し、AGENTS.md/AI_POLICYに従って別にレビューを受けます。
移行は`src/`の変更と分けます。nativeの検証後、全件成功したdev JUnitから日英の
対応表と件数を更新します。この提案だけで実装状態やテスト件数を進めません。
