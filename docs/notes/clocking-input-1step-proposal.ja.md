# クロッキング入力の1stepサンプリング

[English](clocking-input-1step-proposal.md)。英語版を正本とします。
状態：**ユーザー承認済み（2026-10-29）・最初の対応範囲を実装し、検証済み**。基準コミット：`cd663ebf9d66`。

2026-10-29のmacOSで、`tools/local_ci.py`の全21項目が成功しました。
dev/ASan/UBSanは各8,220件、releaseは8,221件すべて成功し、失敗・スキップは0件です。
以前のスキップ2件は、既存のソースと期待出力を維持しています。ソースケース6件、

この結果は、上記コミットを基にした未コミットの作業ツリーに対するものです。

SCHEDULER_SPECの第4部に未記述のクロッキング入力と、型付きSIR・カーネル間の契約を
定める提案です。アサーションやカバレッジの意味、タイムスロットの参照アルゴリズム、
既存の期待出力、外部ABIバージョンは変更しません。P1_SCOPEは必要な機能の前倒しを
認めていますが、未記述の詳細仕様は実装前のレビューを要求しています。

## 最初に対応する範囲

静的なmodule・interfaceインスタンス内の名前付きクロッキングブロックと、入力専用の
整数型clockvarに対応します。既定の入力スキューと明示的な`#1step`を受理し、宣言した
ビット幅、符号、2値・4値の型を保持します。入力とクロックの参照先は、静的なスカラー
またはpacked整数の記憶域と、定数によるビット・部分選択です。入力の別名も、対応する
静的な参照先や選択範囲に解決できるものを扱います。

クロックの値変化・posedge・negedgeと、ブロックイベントの待機`@(cb)`に対応します。
clockvarと元の信号は別の値として保持します。ソースのプロシージャからclockvarへの
書き込みは認めず、最初の更新までは型の既定値を保持します。初期化によって存在しない
クロックエッジを生成しません。

その他のスキュー、output・inout、クロッキング駆動、サイクル遅延、global clocking、
default clockingの暗黙的な参照、動的・automatic記憶域、整数以外の型、副作用のある式、
未対応のイベント制御は位置付きの未対応診断とします。クロッキング全体の対応ではありません。

## サンプリングと公開

1. 新しいタイムスロットのイベントを実行する前に、登録した参照先の値を一度だけ
   保存します。現在のPreponed値、すなわち直前のPostponed値を表します。時刻0では、
   既存のstatic初期化が完了した後、通常のinitialプロシージャが始まる前の状態を使います。
   将来のエッジの1精度刻み前にタイマーを置く方式にはしません。
2. クロック遷移の判定には既存の共通の値・エッジ規則を使います。入力信号の変化だけで
   clockvarを更新したり、`@(cb)`の待機プロセスを起床させたりしません。
3. 認識したクロッキングイベントごとに、Observedの内部処理を登録します。そのブロックの
   入力サンプルを一括でclockvarに反映した後、ブロックイベントを発火します。
   同じブロックの全入力に、同じタイムスロットのスナップショットを使います。
4. 待機プロセスは公開後に再開します。module側は次のActive処理へ入り、programに属する
   呼び出し元は承認済みのprogram契約が定める実行起源とスレッドセットを保持します。
   実行順序は既存のリージョン処理アルゴリズムに従います。`@(cb)`を`@(clk)`や
   `@(posedge clk)`に置き換えて済ませる実装にはしません。
5. 同一シミュレーション時刻でActive・Observedに再入しても、Preponed値を取り直しません。
   NBA・Reactive側でクロックが変化する場合も、認識した遷移ごとに別のクロッキングイベントを
   保持します。無関係なObserved処理では再公開しません。

Observedでの公開は、登録済みclockvarへの専用カーネル操作です。ユーザーコードが
Observedで通常の信号へ書き込めるようにするものではありません。遅延アサーションの
確定処理と既存の読み取り専用リージョンの制限を保持します。イベントのキャンセル、
プロセスのライフタイム、割り込み、終了処理も既存の規則に従います。

## 表現と所有

クロックトリガ、入力範囲、clockvarの格納先、ブロックイベント、ソース位置を型付きSIRの
記述子で表します。型、範囲、所有者、格納先の重複を検証します。実行中は数値IDを使い、
名前は診断用のメタデータに限定します。不完全なformat 0のダンプは当初この記述子を
省略できますが、将来の完全なSIR表現では保持する必要があります。

サンプリング状態とObservedでの公開は共通カーネルが所有します。VMは通常の時刻0実行前に
記述子を登録し、clockvarを通常の型付きロードで読みます。VM専用のサンプリング規則、
可変グローバル状態、新しい依存、環境設定は追加しません。静的なブロックの登録だけで、
イベントのないシミュレーションを継続させません。確保失敗時には部分的な登録や
コールバックを残さず、既存のContextのエラー処理に従います。

## 検証とスキップ解除

既存の`tests/suite/cb/input_sample_1step.sv`と期待出力の2行は変更しません。
その成功に加え、次の独立した検査が通ってから、このテストのスキップ指定だけを削除します。

- 既定・明示スキュー、入力の別名、1/32/65/129ビット、全4値、符号と2値変換。
- 時刻0、イベントのない時間間隔、クロック前・同時刻の入力更新、NBA更新、複数ブロック、
  複数入力の一括公開。
- posedge・negedge・値変化、Active・NBA・Reactive由来のクロック、同一スロット内の
  複数エッジ、繰り返し待機、待機キャンセル。
- 明示的な参照スナップショットとclockvarを比較し、イベント通知前の公開を確認する
  カーネル単体テスト。
- 未対応構文と不正なSIR記述子の拒否、確保失敗、Context分離の検査。

スキップ解除は検査を厳しくする変更であり、期待値の移行ではありません。機能を通すために
既存テスト本体、期待出力、PerfCountの予算などの保護対象を変更しません。

## 根拠と残る確認

既存テストはIEEE 1800-2023の14.4・14.10・14.13を参照しています。承認済みの
SCHEDULER_SPECにはPreponedと直前のPostponedに関する規則があります。
[Dave Richの解説](https://verificationacademy.com/forums/t/input-sampling-for-clocking-blocks/41134)は、
元の信号、サンプリング値、clockvarの違いと、改訂で明確化する点を説明しています。
値を分けて保持する必要性の参考であり、2023年版の条項全体を確認したことにはなりません。

2023年版の全文と、クロッキングの全組み合わせは**未確認**です。全面対応を主張する前に、
正規に入手した規格の4.4.2.1・14.4・14.10・14.13と照合してください。
規格本文や規格中の例は転載していません。
