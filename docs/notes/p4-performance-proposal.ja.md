## 段階Aの測定から分かったこと

- **Ibex。** 433,198 サイクルの中央値は、2 値 native が 10.625 秒、単一スレッドの Verilator
  5.054 が 0.1097 秒でした。native は 1 シミュレーションサイクルあたり 503,199 ホスト命令でした。
  アイランドの評価 130,473,903 回はすべて生成 C++ で動きました。アイランド評価または判別できた
  NBA 適用を含む標本は 63.5% です。自己コストの標本では、判別した NBA 適用分を除く書き込みと通知
  が 25.7%、アイランドのスケジューリングと待機が 32.7%、生成 C++ が 16.8% でした。
  アイランド外の VM インタプリタ自身は 2.6% です。アイランド周辺の費用を先に調べ、NBA は別実験にします。
- **CVA6 合成ビュー。** 2 値は 344.794 秒対 0.8635 秒、Verilator 比 0.250% でした。
  アイランド評価の 4.16% が生成 C++ で動きました。完走中の 4 区間で VM 自身は標本の 59.2% です。
  レジスタファイルとスコアボードの `process-frame`、`instruction store` の拒否は別に調べます。
  一般化した対応を機構別マトリクスで検証し、アイランド全体のフォールバック契約を変える場合は別途提案します。
- **daily。** `+n=200` の 28 回路のうち 14 回路は生成 C++ の呼び出しが 0 回でした。
  `comb_chain` に 32 命令、`hierarchy_fanout` に 1,811 命令の VM 実行が 1 増分ごとに残りました。
  `nba_shift` は 1 サイクル 81 NBA で、登録と判別した適用が CPU 標本の 44% でした。
  0.3.0 の固定 25 回路の 1.17 倍は負荷平均 97〜108 で測っています。絶対値の関門の前に低負荷で再計測し、
  待つ本体の生成とスケジューラの高速化は別の実験にします。[実測と適用範囲](p4-performance-profile.ja.md)

CoreMark の完走では同じ CRC と最終サイクル数を確認しました。Ibex の測定入力 37 ファイルは
OpenROAD の `404977691e84` に一致し、従来の Ibex 欄の `a9adcf481395` は CVA6 の入力の版です。

## ロードマップと速度の関門候補

1. **P4 柱 1。待機をまたぐ呼び出しと、待機を含む手続きの最初の範囲。** 既存の 1a〜1c を先に通します。
   次に、対応する整数値、固定遅延または固定のスカラーイベント待ち、明示的な SIR の継続で記述できる
   `initial` と通常の `always` を生成対象にします。カーネルが停止と起床順を決めます。
   局所値、手順上の命令数、待機の引数を保持し、既存のフレーム木で中止できるようにします。
   遅延ループとイベント待ちの各 1 機構で生成された再開を確認し、`proc_wait` と `comb_chain` の
   テストベンチで VM 命令数とキャッシュ準備後の秒数を測ります。`fork_join` と `func_call` は
   対照に使い、枝の中止や入れ子の生成対応は各受入試験を通してから広げます。
2. **P4 柱 2。中間信号の観測。** 2a・2b を残し、静的・実行時の登録、ガード、force、VPI の可視性を
   決めます。開始後に同じ時刻スロット内で付く観測者も含め、旧値、各中間値、観測リージョンを確認します。
3. **P4 柱 3。静的アイランドの融合評価と直接読み書き。** 証明できる非循環の範囲で F1・F2 を
   実装し、F3 の効果は別に測ります。フィードバックや証明できない観測は従来経路へ進みます。
   P4 に RTL の速度の関門を設け、P5 の SVA、カバレッジ、VPI、DPI が参照する観測・書き込み・NBA の
   契約を先に定めます。RTL の計測を P5・P6 でも続け、P7 はテストベンチ、UVM と最終の調整を中心にします。

下表は改訂時に比較した案です。ロードマップは推奨案を採用します。
Verilator 比は「比較先の経過時間÷kirimasim の経過時間」です。
関門では P3 の設定に固定した単一スレッド、計装なしの Verilator を使い、公式の速度向け設定は別に測ります。

| 候補 | 出発点 | 控えめな案 | 推奨案 | 上積みまたは後続 |
| --- | --- | --- | --- | --- |
| Ibex 2 値 native の Verilator 比 | 1.033% | 1.20%（現状の 1.16 倍） | **1.40%**（1.36 倍） | 1.60%（1.55 倍） |
| Ibex 4 値と 2 値 native の速度比 `T2/T4` | 0.991 倍 | 0.85 倍以上 | 比は記録し、4 値の秒数は同条件の基準の 1.05 倍以内 | 必要なら 0.95 倍以上 |
| CVA6 合成ビュー 2 値の Verilator 比 | 0.250% | 同一ホストで 0.25% を下限候補にする | **0.30%**（1.20 倍）を追跡 | 対応範囲拡大後に 0.40%（1.60 倍） |
| 固定 25 回路の native／VM の幾何平均 | 高負荷で 1.17 倍 | 低負荷での基準以上 | 低負荷で取り直した基準の **1.05 倍**を追跡 | 同基準の 1.10 倍 |

Ibex の 2 値を主関門、4 値を独立した退行防止条件にする案です。公開できる入力準備、比較先の pin、
再現性がそろうまでは CVA6 と daily を追跡指標とします。daily は native と VM の絶対秒数も出し、
VM の悪化で比だけが改善する場合を除きます。個別回路の 10% 超の退行が再現したら、幾何平均と別に調べます。
4 値の速度比較の双方は 4 値で測ります。

P5.1 の後、CVA6 を止める並行 SVA の一部が独立した機構で、観測契約も整っていれば、
その部分を DPI やランダム化より先に置けます。アサーションの期待値は既存の規則に従います。
P6 はスイッチレベル、埋め込みと並列実行を扱い、P7 は実際の UVM の計測から最終調整します。
RTL の速度は P4 以降継続して確認します。

レジスタ型バイトコードは P5 前に小さい SIR 部分集合で試作し、全面切替は原則 P5 の機能完了後とします。
整数ループの対照では SIR 1 命令あたり約 130 ホスト命令を使いましたが、Ibex の実行 SIR は
1 サイクルあたり 54.82 命令でした。P5.1 の UVM、`func_call`、`fork_join`、`proc_wait`、
通常の SIR 読み込みで、温キャッシュ時間、起動、RSS、結果を照合します。
UVM のインタプリタ自己コストが 25% を超え、同じ意味と起動予算で実行時間を 10% 以上短縮する結果が
再現した場合は、P5.1 で前倒しを再検討します。この 2 数値は提案です。

## F1〜F8 の設計案

### F1。組み合わせアイランドの融合評価

時刻 0、リージョン、エッジ、割り込み、中止と、起床済みバッチを選ぶのはカーネルです。
非循環、固定範囲、単一の書き手の整数スロット、決定的なレベル順、途中待機のない範囲から始めます。
1 領域 1 関数とし、待機世代が有効な起床済みメンバーでビット集合を初期化します。
各メンバーがすでに待機を登録し、変化が同じ Active キューの項目内で伝播する場合を対象にします。
島外の待ちイベントやフェーズがバッチを分ける場合は、従来経路を使います。
従来のレベル順・同順位の SIR ID 順で評価し、値を比較して変化した範囲に感度を持つ後続だけを起こします。
ビット範囲と alias の証明を扱い、バッチやメンバー評価をまとめて省くことはしません。
すでに通過したレベルの再評価が必要になりうる場合や順序が不確かな場合、初版では直接書き込み前に
従来経路を選びます。

可視性の境界は F2 を使い、既存のスロットと待機世代を保持します。最初は単純な全体書き込みと、
順序を証明できる出力通知を対象にします。SCC は現行の収束条件と `--max-scc-iter` で実行します。
`bindCombGroup` は比較対象兼フォールバックとして残し、同じバッチには一つの経路だけを使います。
両モードと代表回路で等価性と効果を確認した後、旧経路の整理を検討します。

### F2。観測の境界

カーネルがスロットのアクセス情報とその世代を持ち、重なる範囲、物理 alias、観測者や force の
変化を追います。領域外の購読、式・エッジのガード、監視、波形のグリッチ、VPI、手続き的な上書き、
clocking、module path、保持理由を含めます。観測される書き込みは旧値が残っている元の位置で
既存の通知経路に渡します。同期観測がある場合は、それ以前の直接書き込みが見える状態にします。
直接書き込み中に副作用付きのコールバックを走らせず、借用した記憶域の寿命と観測境界をカーネルが管理します。

初版は同期ガード、動的な観測者の変更、VPI、競合探索、所有の不確かさがあれば、最初の直接書き込み前に
従来経路へ戻します。順序を証明できる単純な島外エッジ待ちは境界で通常の通知を行えます。
再入を扱う後続版はコールバックの前に借用をすべて解除し、観測世代を確認して次の操作から従来経路で続けます。
すでに見えた効果を繰り返しません。保持した名前を検索できるようにします。2a・2b と、`--tier-check` 用の
照合版で検証します。

### F3。元の位置を保つ NBA の束ね方

右辺、対象と添字は発行時に捕捉し、同じビットへの複数代入も 1 件ずつ順序を保ちます。
Context が島ごとに持つ事前確保済みの作業領域に更新を置き、NBA リージョンまでスロットの値を保ちます。
同じリージョンで連続した発行区間だけをキューの 1 件で表します。
島外の発行、捕捉済み NBA、リージョンの違い、遅延が間に入らないことを確かめます。
`wakeIslandMember` のバッチ分割、同じクロックで待つ島外プロセスの順序を保ちます。
観測者や他のプロセスへ制御を渡す前に受理済み区間を公開し、確保や証明に失敗したら次の未発行項目から
通常の `schedule_nba` を使います。

NBA の適用は元の論理位置ごとに実行し、通知と安全点を守ります。再入のときは未処理の後続を公開してから
コールバックを呼びます。遅延、イベント捕捉、リージョンをまたぐ形、Re-NBA、島外更新との曖昧な重複は
初版の対象外です。内部の記録は X/Z と選択範囲を持ち、最後の値だけにまとめません。

### F4・F5。値の型と記憶域

- **F4。** 明示の 2 値近似または既知入力を証明できる経路で、幅に合った SSA の整数局所変数を生成します。
  分割が必要なら型付き引数で渡し、符号、切り詰め、C++ の定義済み演算、浮動小数点のフラグを保ちます。
  先に関数表の参照を減らし、チェックポイントの省略は別に測ります。分岐・命令の上限、終了、SIGINT、
  診断と資源上限を既存と同じ意味上の箇所で確認します。証明できなければ従来の生成本体を使います。
- **F5。** F4 の後に `--state=2` 専用の 1 プレーン記憶域を検討します。SIR の型や保存形式 1 から
  物理配置を分離し、旧 A/B モジュールが新しい配置に触れないよう版付き記述子とキャッシュ無効化で区別します。
  波形と VPI は b を 0 とした正規表現に戻します。既存の表現を要求するサービスは検証が済むまで従来配置を使い、
  波形、VPI、保存 SIR、Context の独立性を照合します。導入は別途承認します。

### F6〜F8。局所化、区画の読み飛ばし、その他の費用

- **F6。** F1〜F3 の後、すべてのアクセスが領域内にあり観測と保持を除外できる中間値を局所化します。
  スロット ID と、フォールバック・途中終了・エラー・最終観測を含む境界での実体化を保ちます。
  `--public`、`--preserve`、保持理由 Waveform・Foreign・Force・Explicit があれば初版の局所化から
  除外します。未知の観測や動的な観測には従来経路を用意し、全論理書き込みの照合を行います。
  ISL-A9 の改訂は独立させます。[F6 の別差分](p4-local-slots-review.patch)
- **F7。** トポロジ順の連続部分を区画とし、対応する dirty ビットがすべて 0 ならその範囲を飛ばします。
  活性の区画でもメンバーごとの判定を維持します。観測境界、クロックとリージョン、SCC、証明の範囲で切り、
  fanout、同時に活性になる見込み、生成コードの大きさを使って区画を選びます。
  非循環の区画化の着想は [Beamer・Donofrio、DAC 2020](https://scottbeamer.net/pubs/beamer-dac2020.pdf)、
  活性判定と余分な評価の釣り合いは [Chen ほか、GSIM](https://arxiv.org/abs/2508.02236) に基づきます。
  疎・密な刺激で判定の削減と命令キャッシュへの影響を測ります。
- **F8。** 配置が両立するアイランドのスロットの連続化、同じクロックを待つ適格なメンバーの物理購読の共有、
  空のリージョンの確認を減らす主ループを別々に測ります。論理購読の本数と順序、島外トリガーの割り込み、
  時刻の進行、リージョン、割り込みと資源の上限を保ちます。配置変更には alias の完全な証明と配置 ID が必要です。
  [Beamer、IEEE Micro 2020](https://www.scottbeamer.net/pubs/beamer-imicro2020.pdf) をカウンタと配置の動機に、
  [Erhart ほか、Arcilator 2023](https://llvm.org/devmtg/2023-10/slides/techtalks/Erhart-Arcilator-FastAndCycleAccurateHardwareSimulationInCIRCT.pdf)
  のレジスタ間の弧を、評価と確定を分ける着想に使いました。kirimasim のイベントリージョンをそのまま使います。

**ABI とキャッシュ。** 借用する記憶域、観測世代、順序付き NBA の公開、領域の入口に必要な機能は
版付きサービスにします。0.5 の関数表の先頭部を保ち、既存サービスを使えるようにします。
非互換の配置や意味の変更が必要な場合だけ RUNTIME_ABI 2 に従って ABI major を上げます。
記憶域の配置、機能、所有権を確認してから生成関数へ入ります。正規 SIR、決定的な解析とオプション、
生成元のダイジェスト、対象、コンパイラとフラグ、公開ヘッダー、サービス版、配置と状態・照合モードを
キャッシュキーに含めます。キーが違えば従来経路または再生成に進みます。同一入力・同一条件の生成 C++ は
バイト単位で決定的にし、生成・ビルド・バイナリサイズ・コールド起動・キャッシュ済み起動・実行を別に計測します。

**照合とカウンタ。** `slot.writes`、`slot.changes`、`nba.scheduled`、`wait.subscriptions`、
`proc.wakeups`、`island.member_evals`、`sched.events.*` と上限の既存の意味を維持します。
観測、停止、エラー、割り込み確認が間に入らないと証明できる区間に限りカウントの加算をまとめ、
フォールバック・途中終了の前にそこまでを反映します。費用は別に測ります。
実際の呼び出し・ヒープ操作・直接書き込み・観測による退避・NBA の区間は、`--stats=json` とは別の
版付き `--report-fusion=<file>` に出す案です。生成関数の実呼び出しと論理メンバー評価を区別します。
照合版は同じ初期状態から VM のアイランド実行と比較し、各メンバーの訪問、ブロッキング書き込みと
変化、起床・再購読・NBA の順序、終了状態と境界での観測値を照合します。
外部への効果はカーネルが 1 回だけ公開し、未対応なら従来の照合経路に戻します。
これを PERFORMANCE 6 の論理カウンタに関する未決事項への案とします。

**P6 の並列実行。** スロットの書き手、読み取り依存、副作用、実行時の観測が互いに独立と証明できる
場合に限り融合領域を並列タスクの単位にします。出力と順序付き NBA は依存する処理の間でカーネルが
決定的に公開します。作業用記憶域と待機状態は Context に所属し、並列用スケジューラは別途レビューします。
P4 では独立した 2 Context を検証します。

**見積もり。** 省けるホスト命令を「適格な件数×1件あたりの命令差」の合計から、境界確認・記録・公開の
費用を引いて求めます。各単価は同じ効果と CRC・サイクル数のまま機構を一つずつ切り替え、
実行命令数の差を実際に変わった件数で割って測ります。段階 A ではその単価は未確認です。
Ibex の各サイクルにメンバー評価約 301 件、書き込み約 984 件、NBA 約 42 件、論理上の購読約 1,158 件があり、
処理経路の重なりがあります。1.40% 案の予算は約 7.84 秒で、10.625 秒から約 26% の短縮です。
同じ命令スループットなら約 **13.2 万ホスト命令／サイクル**の削減が必要です。301 件すべてが適格と仮定して
評価だけで埋めるなら約 **440 命令／件**です。標本の和集合 63.5% が時間比を代表すると仮定し、
その部分だけを半分にすると全体で 1.47 倍、すべて除くと 2.74 倍です。
実測の割合を重ねて足したり、局所 C++ の対照倍率を CoreMark に当てはめたりしません。

## 計測の運用と作業順

1. 固定 25 回路を低負荷で取り直します。公式計測では最初と最後の 1 分負荷平均が論理 CPU 数の 50% 以下
   （今回の 18 コアのホストなら 9.0）、同じホストでの同時ベンチ・CI なしを提案します。各回の負荷を記録し、
   条件を超えたら参考値と明記して再測定します。温キャッシュで交互に各 5 回以上、短い daily は
   T(N) と T(1) の中央値の差を取り、僅差は再測定します。CRC、バージョン、フラグ、入力ハッシュも記録します。
2. 公開用の pin と準備手順の承認後、Linux x86-64 で Ibex を週次測定する案です。
   `perf stat` のイベント、権限、多重化と測定範囲を明記します。1 サイクルあたりのホスト命令は当初は報告のみとし、
   同一 CPU・OS・コンパイラ・実行条件の基準期間を確保した後に回帰予算を検討します。
   決定的な PerfCount とは別に扱います。daily の pin に定義済みの Verilator 5.054 列を、比較可能な回路に
   加えます。X/Z や未対応は記録し、共通の固定集合のみで集約します。
   [比較先の公式設定](https://verilator.org/guide/latest/simulating.html#benchmarking-optimization)
3. 承認後は F1・F2 と最初の待機付き本体の試作を進め、F3 は NBA の多い回路で独立に評価します。
   CVA6 の拒否機構を別に調べ、F4 は切り分け計測の後に進めます。コンパイラの調整、hot/cold 分離、PGO は
   構造の費用を減らした後の優先度に置きます。F5〜F8 は効果と範囲をレビューしてから導入します。
   空欄の CODEGEN_SPEC「2 版切り替え」に現行動作を記す案も本差分に含めました。
   [段階Aの根拠](p4-performance-profile.ja.md)

## 承認範囲と別途判断する事項

主差分で P4 の 3 つの柱、推奨の速度関門と継続測定の目安、低負荷での計測条件、
論理カウンタの契約、明示指定による融合診断を採用しました。P5 のマイルストーンには
CVA6 向け SVA の先行候補を含め、VM バイトコードは P5 前に限定試作します。
[ロードマップ](p3-p7-roadmap-revision.ja.md)に承認範囲を記録しています。

F5 の物理的な 2 値記憶域、F6 の ISL-A9 改訂、ホスト命令数による回帰判定の閾値、
計測ツールや runner の追加、外部ソースとアダプターの準備方法、ソルバの採否は別途判断します。
現時点の再現スクリプトは準備済みの入力を使います。
