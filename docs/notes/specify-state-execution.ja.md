# 単純な状態依存スカラーspecifyの実行

[English](specify-state-execution.md) · 2026-11-03。

承認済みの[契約1〜8節](specify-state-dependent-proposal.ja.md)に沿い、単純なスカラーの
`if`／`ifnone` module pathを、型付きSIR・第1層・共有kernelへ接続しました。
[期待値2件の移行](specify-state-expectation-migration.ja.md)は別途承認され、`src/`を
含まない別コミットにしました。依存、公開C ABI、P1の完了条件は変えていません。

## 対応する動作

単純なスカラーの並列・完全接続パスに、最初の範囲のローカル入力net、wire/tri出力、
通常の固定強度の機能driver1本という条件を保ちます。条件にはローカルなstatic整数値・定数・
定数選択を使えます。条件の**LSBが1/X/Zなら有効、0なら無効**です。上位bitが1でも、
LSBが0なら有効になりません。手続きの`if`とは異なる規則です。

変化した機能寄与が到着するときに、評価器ごとに1回だけ条件を読みます。条件だけの変化では
予約済みの処理を再予約しません。宣言上の同じ入力・出力の組で、条件がすべて無効のときだけ
`ifnone`を有効にします。ポート接続で同じ物理netへまとめられても、異なる端子宣言のグループは
分離したままです。

有効条件・既定パスで絞り込んだ後、最も新しい対象入力時刻を選び、同時なら遷移遅延の最小を
選びます。機能到着時刻と絶対path期限の大きい方を使います。12遷移、5種類の遅延個数、
min/typ/max、既定の慣性除去、Activeでの公開は最初の範囲の規則を保ちます。forceは公開netを
固定し、その間も機能更新は続きます。VPI・VCD・FSTは同じ公開された確定値を観測します。

frontendは読み取り専用の`path-condition`を生成します。利用者frameや引数を持たず、検証済みの
static整数の読み取り・値の演算と、循環しない式の制御フローだけを使います。論理的な端子宣言IDと
物理記憶域IDを分け、スカラーnet viewはdriverを増やさず記憶域を共有します。VMはstatic評価器の
結果を渡し、選択と予約はkernelが所有します。終了時は評価器の接続を切り、所有済みの予約値は
破棄されたInterpreterを呼ばずに完了できます。構成・callbackの失敗も既存のエラー・資源制限の
境界とContextの分離を保ちます。kernelの公開ヘッダはC++20のままです。

## 残る境界と再現

条件付きエッジ依存パス、既定パスとエッジ依存を混ぜるグループ、vector/select/variable/inout端子、
受動接続・複数機能driver、明示的なpulse control、SDF、timing checkは未対応です。
これらは残る機能境界であり、新しいP1例外ではありません。任意の`wire real`例外とP1ゲートの
分母は変えていません。この有限の行列だけではP1の完了を示しません。

契約9節で説明したIEEE 1800-2023の条文ごとの直接照合は、引き続き**未確認**です。
確認した一次本文は1800-2017の30.4.4.1〜30.4.4.4、30.5.3であり、承認によって版の照合が
完了したとは扱いません。slangへの投稿は行っておらず、投稿保留も継続します。

```sh
cmake --preset dev && cmake --build --preset dev
ctest --preset dev -R 'ModulePath|cli/specify' --output-on-failure
python3 tools/gen_specify_state_matrix.py --output build/specify-state-inputs
python3 tools/mutants.py --check
```

CLIのCTestがソース行列とFST復号観測を実行します。native変異は登録表の該当項目と通常の
意味のテストを使い、ソースを復元して基準のテストを再実行します。push前には
`python3 tools/local_ci.py`を実行し、ビルド・テスト・静的検査中は追跡ファイルを編集しません。
