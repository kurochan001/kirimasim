# slang の固定先を 8970e0b1 に更新

[English](slang-8970e0b1-update.md) · 2026-11-28

更新候補は、従来の e81bcd25 から 145 コミット進んだ上流 master の未改変版です。符号付き多次元パック配列の選択に関する slang issue 2131 の修正を含みます。上流では、規則本体を囲む手続きの文脈で検査するために、randsequence の規則を対応する文が所有するようになりました。フロントエンドは、入れ子の文から外側の規則を呼ぶ場合も、宣言シンボルで束縛済みの規則を引きます。既存テストは入れ子の呼び出し、再帰の拒否、重み付きの選択、規則の共有、実行出力、SIR の往復を検査します。[上流の比較](https://github.com/MikePopoloski/slang/compare/e81bcd2560d54dfd17524df70c0f297e759509da...8970e0b1e3a9a142817e62079ea3c3b22ac3def0)・[統合テスト](../../tests/cli/run_randsequence_tests.py)

## macOS arm64 での確認

- kirimasim issue 137 の独立した再現例では、`bit signed [0:1][6:3]` に `8'hb6` を格納しました。0 行目の境界は旧版で 3 と 0、新版で 6 と 3 でした。ビット 6 と範囲 5 から 4 の読み出しは旧版で 0 と 00、新版で 1 と 01。そのビットをクリアした配列は旧版で b6、新版で 36 でした。
- kirimasim 9f825f60 に API 対応を加え、既存の期待値で dev テスト 14,041 件中 14,029 件が通りました。8 件は上限付きキューで警告が増えました。不正なワイルドカード比較 2 件と負の randsequence 重みは slang が先に拒否します。乱数変数を含まない適法な文字列制約部分式には警告が出なくなりました。期待値の差分はこの 4 種を区別し、警告対象の厳密な診断も確認します。キューのテストは 7.10 と 13.5.2 に従う実引数の上限と元の実行出力を要求します。追加された上流警告は仮引数の小さい上限に対するものです。診断の差分案を適用すると、dev 全 14,041 件と Release 全 14,042 件が合格しました。macOS Release の P1 固定リストは 1,466/1,466 件、固定版 sv-tests は 256/344 件が合格しました。
- slang 関連の未解決 issue 32 件の本文から特定できた 150 入力を比較しました。旧版で構文・エラボレーション段階で拒否された 22 件を新版が受理し、うち 6 件はシミュレーションの期待値にも一致しました。例は issue 116 の ref static と issue 76 のブロック・タスク・関数に対する defparam です。16 件には実行時の未対応機能が残ります。不正入力 7 件は新版で拒否され、残り 121 件は parse の終了コードが一致しました。複数の入力を含む issue には個別に未解決項目があり得ます。[入力別結果とテスト版](../measurements/2026-11-28/slang-8970e0b1-issues.json)
- slang の更新に伴い fmt は 12.2.1、mimalloc は 3.7.1、toml++ は 3.5.1 になります。3 ライブラリと slang の MIT 本文は旧版とバイト単位で一致しました。互換プロファイルのコンパイル・解析フラグは継続し、診断設定は新しい固定版に従います。[ライセンス照合](../measurements/2026-11-28/slang-8970e0b1-licenses.json)・[互換プロファイル](../measurements/2026-11-28/compatibility-8970e0b1-profiles.json)
