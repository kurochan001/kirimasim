# ヒープを使うファイルモニターとコールバックの終了

[English](heap-file-monitor-lifetime.md)。2026-10-25に実装・ローカル検証しました。
[型付きパターン実行の区切り](pattern-sir-execution.ja.md)の続きで、既存の
SYSTEM_TASKS 4・6.2、SCHEDULER_SPEC 10.7・10.8に従う修正です。

## 不具合の修正

`Scheduler::kill`は表示コールバックを終了状態にしても、表示・ファイルモニターの登録と
ヒープ読み出しの依存を残していました。その後の要素変更で終了済みコールバックが再び呼ばれ、
最後のコールバックを終了してもヒープの変更hookが残る場合がありました。
通常の待ちを取り消して終了状態にする前に、`detachDisplayMonitor`で解除するよう修正しました。
処理は共有カーネルの1か所にあり、生成元のソースコンテキストによらず、表示とファイルの両方へ
適用します。終了するコールバック自身の登録を解除するもので、終了するソースプロセスが
発行しただけのモニターを取り消す変更ではありません。出力・値・スケジューリングの規則は維持します。

## 独立した検査

独自の[gen_file_heap_monitor_matrix.py](../../tools/gen_file_heap_monitor_matrix.py)から、
キュー／動的配列、mcd／fd、initial・task・function・fork・generateの20ケースを生成します。
期待する行は、実行結果ではなく、ソース中で設定した値とSYSTEM_TASKS 4・6.2から決めています。
選択した要素と長さの依存、別の要素の変更、Postponed前の連続書き込み、添字変更、配列全体の
置き換え、独立した2つのファイルモニター、`$monitoroff`、ファイルを閉じる処理、記述子の再利用、
最後の出力先を閉じた後の停止を検査します。20ケースすべてがローカルで通りました。

新しいschedulerの2テストは、表示／ファイルの両コールバックを検査します。一方を終了して両方の
要素を変更し、残る一方だけが呼ばれること、最後の終了で変更hookが復元され、rootのない
コンテナを回収できることを確認します。もう一方はPostponedの読み出し捕捉中に確保失敗を注入し、
ResourceLimit、正しいコールバックの識別、読み出し・変更hookの復元を検査します。
両テストは修正前の`kill`では失敗し、修正後は成功しました。同じ解除の欠落を誤実装検査へ登録し、
514件すべての適用を確認しています。関連する7つのユニットテストと、選択したCTest 29件が成功しました。

既存テストの本体、期待出力、PerfCountの予算は変更していません。コールバック中の再入による
登録・再配置や、あらゆるソースコンテキストには、さらに広い検査が必要です。
ソースの`%p`の変換処理も残っています。独自87項目のIcarus比較は以前の版・件数を維持し、
この検査だけでP1の全面的な対応を示したとは扱いません。
