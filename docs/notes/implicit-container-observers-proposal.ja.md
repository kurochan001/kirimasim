# コンテナの最初の暗黙監視：実行契約の提案

[English](implicit-container-observers-proposal.md) · 2026-11-05。

**状態：1〜8節は2026-11-06に承認済みです。[最初の実装と検査](implicit-container-execution.ja.md)はローカルで完了しました。既存期待値の移行も別途承認を受け、`b3d20b8b`へ適用しました。**
実行できる本体と、それを再実行する依存の追跡は別の仕組みであり、
[現在の対応一覧](../P1_SUPPORT.ja.md#動的コンテナの共通基盤)で境界を確認できます。
main `6f5c6984`は、暗黙感度に寄与するコンテナの読み出しをまだ拒否します。

[P1_SCOPE](../spec/P1_SCOPE.ja.md)は、未記入の詳細な意味を実装前にレビューするよう求めます。
SCHEDULER_SPEC 6.3・9.2はどのソースの読み出しが感度へ寄与するかを定めますが、
現在のSIRのトリガー範囲は格納ワードを表し、コンテナの値を表しません。
9.5の実際に実行した読み出しを集める監視にも、利用者のコードを実行せずに登録する
暗黙監視の詳細がありません。この案はSIR_SPEC 7.1・7.2、SCHEDULER_SPEC 9.5、
RUNTIME_ABI 6の型付きサービスに、その境界を補います。既存の感度規則とP1ゲートは保ちます。

## 1. 最初に実行する範囲

既存の整数要素の動的配列とキューを、通常の静的な型付きslotにある変数で扱います。
上限付きキューと、対応する幅・2値/4値を含みます。module・interface・generateの記憶域、
package・unitの修飾名、既存の非パラメータ化クラスのstatic記憶域、適格なサブルーチンの
静的記憶域への階層参照が対象です。

既存フロントエンドがそのソース形式を受理する`always_comb`・`always_latch`・
先頭に制御を持つ`always @*`と、直接の連続代入へ接続します。
最初は、サイズの問い合わせと値で渡すinput引数から生じる、コンテナ全体への依存を扱います。
`@*`は、名前で示したコンテナ変数全体が依存先となる既存の要素読み出しも扱います。

comb・latch・連続代入の式で、要素選択が感度へ寄与する形は、最長の静的な接頭辞の記述子を
レビューするまで位置付きの未対応診断を保ちます。全体の読み出しが選択を包含できる場合でも、
最初の実装でその混合形まで受理する必要はありません。呼び出した本体でコンテナを読む連続代入は、
今回の範囲では従来の診断を保ちます。`@*`の感度から既に除外する通常関数本体の読み出しは、
引き続き実行できます。

automatic・ref経由のコンテナの結び付き、入れ子の暗黙制御、入れ子・非整数の要素、
連想配列、クラスに依存する監視は最初の実装には含めません。必要なものはP1の残作業であり、
新しいP1除外ではありません。slangの厳格な合法性検査と、既存のソース形式の制限を保ちます。

## 2. 依存先は静的に決める

型付きの依存を作る前に、SCHEDULER_SPEC 6.3・9.2を適用します。

- comb/latchは、既存の推移的な読み出しグラフに従い、通常関数とstaticメソッドの適格な
  読み出しを含みます。自身・呼出先が宣言した変数、書く範囲、時間制御だけでの読み出し、
  アサーションのactionは除きます。クラス参照とinstanceメソッドの実引数だけを含める規則も保ちます。
- `@*`は、直接読む識別子と実引数の式を含み、値で渡すコンテナも対象です。
  呼出先の本体の読み出しは取り込みません。静的関数の変数を直接修飾名で読む場合は、
  サブルーチンの所属という理由だけで捨てません。関数本体だけに隠れた読み出しとは区別します。
- 直接の連続代入はソースのオペランドを使います。今回、呼出先本体でコンテナを読む
  連続代入の既存の境界は変えません。

frontで宣言の識別・型・適格な格納先を記録し、実際に実行した読み出しで静的感度を決めません。
登録・再登録・付け直しで、ソースの関数、引数の副作用、プロセス本体を実行したり、
ソース言語の一時コンテナを確保したりしてはいけません。
結び付きの重複は決定的に除き、各process kindの書込み検査・呼出し制約・時刻0の方針を保ちます。

## 3. トークンの変化と値の変化を区別する

**レビューを求める解釈案：** 適格な整数コンテナの論理値全体、すなわち長さと順序付きの
要素のビットを比較します。0・1・X・Zを区別し、未使用ビットをマスクします。
ハッシュ、`size()`の結果、内部のコンテナやセルのトークンではなく、正確な値を比較します。

この型付き依存は暗黙感度の結び付きであり、新しい明示的なイベント式の形式ではありません。
明示イベント式の合法性とスカラーの結果の監視は保ち、類推で集約型の`@(q)`を有効にしません。

伸縮、異なる要素の並べ替え、要素の変化では、計算したスカラーの結果が同じでも起床できます。
X→Zも変化です。自己代入や同内容での再確保を含め、同じ値の新しい記憶域に置換しただけでは、
新しいトークンを確保したことを理由に起床しません。空から空、不正な書込みで変更がない場合も
値のイベントを作りません。

コピーや参照の同一性は変えません。承認済みのコンテナ契約が求めるコピー・再確保では、
新しいセルを作ります。キューの移動は残るセルを保ち、古い参照は切り離したセルを保持します。
論理値が同じでも、これらの格納操作を省略してはいけません。

## 4. 確定した変化を観測し、スケジューリングを保つ

待機を登録するときに依存先と読み取り専用の値のスナップショットを保持します。
変数の結び付きの置換と、確定した構造・セルの変化を観測します。
関数やコールバックの走査中も公開時点で変化を判定し、既存のスケジューラが許す時点まで
遅らせるのはプロセスの実行であり、比較ではありません。書込み元の終了後の最終値だけを比べて、
A→B→Aを見失ってはいけません。

swapのような複数セルの操作は1つの公開バッチであり、内部の一時状態はイベントではありません。
最初の適格な変化でそのプロセスの待機を終え、ほかの項目を無効にします。
再開前の追加の書込みで重複した再開を作らず、既存のprocess kindの規則で再登録します。

comb/latchは従来どおり時刻0に1回実行し、`always @*`は最初に待ちます。
直接の連続代入のprocessは実行中の感度も保ちます。合法なソース形式では、module・programの
起源に従うActive/Reactiveの実行を保ちます。ポーリングのtimer、delta遅延による代用、
隠れたprocess、新しい領域順序を導入せず、静止した設計を動かし続けません。

## 5. 型付きSIRと共有カーネルの境界

通常の整数slotトリガーや式の結果の監視とは別に、processのメタデータへ、
型付きのコンテナの暗黙依存を明示します。結び付きは適格な静的コンテナslotと型の記述子を指し、
最初の形式では1つのコンテナ変数全体のAny-change依存を表します。
同じ対象へ通常のトークンのワードの購読も付けてはいけません。

実行時の確保前にprocess kind、slotの範囲・寿命・型、コンテナ記述子と整数要素の配置を検証します。
偽装したhandle型、トークンの部分範囲、不適合な記述子、未対応の監視形式は拒否します。
新しいメタデータの診断用SIRテキストを決定的に出力し、その記述子を持たない既存のformat 0の
goldenは保ちます。SIR v1の確定や外部C ABI版の変更は含みません。

VMは検証済みの数値slot・型をカーネルサービスへ機械的に結び付けます。
共有カーネルがスナップショット、値の比較、弱い依存の登録、公開、取消し、起床を持ちます。
VM側に別の感度アルゴリズムを作らず、実行中の名前検索、kernelのslang依存、
書換え可能な大域状態を追加しません。公開kernelヘッダはC++20を保ちます。

## 6. 所有・付け直し・失敗

スナップショットは正規化した整数値のワードと長さを持ち、ソースのコンテナのコピーや
GC rootにはしません。監視の印は弱く、変数の既存の型付きrootが現在の値を生かします。
内部の読み出しを、外側のソース式の実際の読み出しの捕捉に混入させたり、利用者の
コールバックを呼んだりしてはいけません。

同値の置換で起床しない場合も、置換後の構造とセルへ付け直します。
古い印を外し、切り離した古い参照を通じた書込みで新しい変数の監視を起床させません。
既存の世代検査を使い、回収したトークンが別の新しい値を指さないようにします。

取消し、scope・processの終了、finalの後処理、interpreterの破棄は、確保を伴わずに
印を外して保留通知を無効にします。Contextを独立させます。
登録とスナップショットの状態をトランザクションとして作り、確保・サイズの失敗は既存の
ResourceLimit・終了コード6とし、依存の一部だけを登録しません。
不正IRや内部不具合の分類は保ち、未文書化の容量上限や新しい実行オプションを設けません。

## 7. 実装後にレビューする既存の拒否期待値

この提案では既存期待値を変更しません。判明している後続作業は、
**既存2ファイルの11件の拒否判定**です。

- [動的コンテナのCLI検査](../../tests/cli/run_dynamic_container_tests.py)：
  `always_comb`・`always_latch`・`always @*`・直接の`assign`が`q.size()`を読む4形式と、
  combが`read_size()`を呼ぶ形式の計5件、およびcombが`top.holder.q.size()`を直接読む場合と
  `read_nested()`を通じて読む場合の2件です。
- [ImplicitFront.ActualImplicitContainerReadsRemainDiagnosed](../../tests/unit/implicit_front_test.cpp)：
  wildcardで直接sizeを読む形式、wildcardの`read_argument(q)`、combの`read_global()`、
  latchの`read_global()`の4件です。`assign observed=read_global()`の拒否は残し、
  この最初の契約で連続代入の関数本体のコンテナ読み出しを有効にはしません。

独立した実装の検査が成功した後、変更前後の判定を示して、期待値移行は別途承認を求めます。
srcの変更から移行を分け、入力ソースを保ち、残す拒否の境界も検査します。
本提案の承認には、この移行、テストの削除・改名、アサーションの緩和、性能予算の変更は含みません。

## 8. 受入条件と承認された範囲

2026-11-06の1〜8節の承認は、この最初の型付き監視の契約と実装を対象とし、P1完了や、より広い
インターフェースへの対応を意味しません。依存やインストールは選びません。
ソースの受理を有効にする前に、以下を確認します。

- 独立した列・値のモデルとカーネルのスナップショット・イベントを照合し、空・非空、同じ長さの変更、
  順序、同値のコピー、X/Z、上限操作、不正書込み、複数セル公開、走査中のA→B→Aを検査します。
- ソースの場所、コンテナの種類、幅、2値/4値、直接・実引数・呼出先の読み出し、実引数なしの`@*`、
  書込みの除外、呼出先の私有領域、修飾した静的サブルーチン領域を横断します。
  関数の呼出し回数も検査し、登録でソースを実行しないことを確かめます。
- 同値コピー後の付け直し、切り離したref、世代の再利用、取消し、確保失敗、破棄、
  Contextの独立性、不正なnative SIRを検証します。
- トークンだけ・サイズだけの比較、X/Zの同一視、最終値まで遅らせる比較、誤った呼出し閉包、
  登録時の副作用、古い付け直し、監視の残留を実際にコンパイルした誤りで検査します。
  適用可能な場所の検査だけでは足りません。
- 既存の値・寿命・スケジューラ・object/event・明示監視・wildcard関数の検査を保ち、
  dev全件とrelease・ASan・UBSanの関連検査、clang-format/tidyを行います。
  承認されたpushの前には完全なlocal CIも実行します。成功したJUnitから件数を別に更新し、
  固定した外部ゲートは保ちます。

## 9. 根拠と再現（実装済みの主張ではありません）

[96ケースの棚卸し](../measurements/2026-11-05/implicit-container-review.json)はmain `6f5c6984`と、
明示的に選んだIcarusのコンパイラ・runtime **13.0 stable（`v13_0`）**を使います。
既存2ソースとハッシュをそのまま保持しました。追加した単純なサイズ増加18ケースもIcarusで
記述した結果に一致し、kirimasimは20ケースすべてを拒否します。具体的な実行上の不足です。

残る76ソースは、この案の広い規則を調べるものです。96ケース全体では、kirimasimは未対応84、
提案した出力との一致12です。Icarusは一致26、不一致30、プロセスの失敗40です。
72件の値の追跡に、要素の変更、同値のコピー、一時的な変更と復元、X/Z、削除・再増加、
関数呼出しを含み、4件では直接の連続代入を調べます。プロセスの失敗は別に残し、参照側との差を
正しい意味として採用しません。どちらの比較シミュレータのソースも読んでいません。

測定時点で広い追跡の期待値は**未承認の候補**でした。2026-11-06の契約承認によって、
この観測記録を承認済みテストやP1合格率に変えるものではありません。
既存188プローブ、任意の`wire real`例外、外部母集団は不変で、この提案による実行対応の追加はありません。
手元の2017版では、静的な依存先の選択について9.2.2.2.1・9.2.2.2.2・9.4.2.2を確認しました。
コンテナ値の詳細解釈について、**2023版本文との直接の照合は未確認**です。
2026-11-06の承認は、3節をプロジェクトの契約として採用したものです。
[IEEEの公式アクセスページ](https://standards.ieee.org/ieee/1800/7743/)から本文を確認し、
9.2.2.2.1・9.4.2へ直接照合する作業は別の確認項目として残します。
旧版の依存先の規則だけで、値全体の一致判定まで確定したとは扱いません。
外部への報告は行っていません。

```sh
python3 tools/implicit_container_inventory.py --self-check
python3 tools/implicit_container_inventory.py --kirimasim build/dev/src/driver/kirimasim --output build/implicit-container-review.json
```

参照の観測には`--iverilog=<コンパイラのパス>`と`--vvp=<runtimeのパス>`の両方を追加し、版を確認します。
`--sources=<ディレクトリ>`で独自ソースを保存できます。ツールの終了コード0は観測記録の完了を示し、
機能や提案した意味の検査に合格したという意味ではありません。
