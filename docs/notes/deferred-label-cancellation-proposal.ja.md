# 遅延アサーションのラベル取消し：仕様修正案

[English](deferred-label-cancellation-proposal.md)

状態：**保守者承認済み**（2026-11-03、この会話で明示承認）。
既存期待値は変更しません。下記の操作と検証器の条件を確定し、実装を進めます。

## 1. 問題と仕様の境界

upstream `f3ea0379`での外部の固定クロス選択では、名前付きobserved deferred
アサーションを`disable`する5件に出力差があります。兄弟文・別プロセスの観測は一致し、
取消し対象の報告が残ります。対象の指示文はassert・assume・coverです。
テストの根拠はIEEE 1800-2023 §16.4.4と§16.4–16.4.2、9.6.2です。

現行SCHEDULER_SPEC 15.3–15.4はプロセス全体のflush点を規定し、キューを
空にするのはその点だけとしています。SIR_SPEC 5.7には文の識別子や対象指定の
取消し命令がありません。選択的なラベル取消しの実装前に、下記の明示的な
仕様修正が承認されました。観測された差だけで全形式の内部原因が確定したわけではありません。

## 2. 提案する規範的な修正

1. 遅延アサーション文はプロセスやアクションwrapperとは別の静的識別子を持ち、
   pass/failアクションは同じ文IDを共有します。無名文にも内部IDを付けられます。
2. 正当に名前解決されたアサーションラベルへの`disable`は、その文の未成熟の
   待機報告だけを取り消します。プロセス全体をflushせず、兄弟文や別IDを保持します。
3. 登録時に済んだ条件・入力引数の評価と副作用は保持し、取消しで巻き戻しません。
4. 既に成熟した報告・アクションと過去の時刻の出力履歴は、この待機報告操作では
   変更しません。実行中アクションの追加制御、階層形式、アサーション制御システムタスクは
   本修正で追加しません。未対応形式は明示的な未対応のままとします。
5. 従来のプロセス全体のflush点、通常のblock/taskの制御移動、unique/priority報告、
   保持した報告の順序は変更しません。
6. frontがslangの意味モデルからラベルを解決し、明示的なSIR取消し命令を生成します。
   報告登録に同じ文IDを付けます。ソースの文字列書換えやテスト名の判別は行いません。
   kernelがキューの選別と解放を担当し、VMはSIR命令を機械的に実行します。
7. 取得済み引数のrootとframe所有権は、既存の破棄callback経路で一度だけ解放します。
   状態はContextに所属させます。
8. SCHEDULER_SPEC 15.2–15.4とSIR_SPEC 5.7にIDと操作を追記し、IDを必要としない
   既存report-callのテキストは保持します。正確な符号化と検証器の条件は実装前に確定します。

## 3. 必要な検証

5件の症状を修正する前に、assert/assume/cover、pass/failアクション、単発/複数の待機報告、
対象/兄弟/別プロセス、登録前後、通常のinner/task/outer disable対照を機構別matrixにします。
initial・task・forkから同じ登録規則へ到達させ、入力取得の副作用、生のアクションデータ、
保持した順序、解放を確認します。受理する範囲でobserved/final両キューを確認し、未対応範囲は明示します。

外部の既存deferred-disable 31件と有限クロス全選択を、期待値を変えずに再実行します。
元の失敗snapshotは保持します。固定Icarus/Verilatorの差は別の観測であり、
新しい期待値の根拠にはしません。全local CI、sanitizerと既存期待値の保護検査を維持します。
P1の分母と合格条件は変更しません。

## 4. 確定したSIR表現

`report.call.named "#0"|"final", #N, @S, args...`が、文IDを付けた報告登録です。
`report.cancel #N`は、その静的IDの未成熟報告だけをContext内で取り消します。
IDは既存の`numScopes`で範囲検査する名前解決済みID空間を使い、通常のblock activationは開始しません。
同じアサーションのpass/fail wrapperは同じID、別実体・兄弟文は別IDを持ちます。
検証器は結果なし、IDの種類と範囲、領域、関数wrapper、引数数・方向・型を検査します。
既存の`report.call`の表現は保持します。成熟済み報告・unique/priority・他IDは対象外です。
