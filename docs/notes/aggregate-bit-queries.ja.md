# 固定unpacked集約値に対するビット問い合わせ

[English](aggregate-bit-queries.md)。2026-10-25に、既存のSYSTEM_TASKS 8、
VALUE_SEMANTICS 8、IEEE 1800-2023 20.9に従って実装しました。

`$countbits`、`$countones`、`$onehot`、`$onehot0`、`$isunknown`が、整数の末端要素を持つ
対応済みの固定unpacked配列、構造体、構造体配列を受け付けます。frontはストリーミング式と
同じ`Lowerer::bitstreamOf`を使ってから、既存の`$countbits`システム呼び出しを出力します。
どのビットが制御値と一致するかは共有カーネルが決め、VMにソース型の判断や新命令を加えません。
スカラーも同じ経路を使います。

問い合わせごとに対象式を1回評価し、その集約値を制御引数より先に保持します。
既存の左から右の引数評価と2値フィールドへの変換を維持します。制御式も通常どおり評価し、
最下位ビットを使い、同じ制御値を重複させてもビットを重ねて数えません。

独自の[ジェネレータ](../../tools/gen_aggregate_bit_query_matrix.py)で136ケースを追加しました。
期待値は、記述したビット文字列をPythonで数える独立したモデルから求め、2値のX/Z変換も含みます。
1・5・65・129ビット、2値／4値、固定配列・構造体・構造体配列、initial・task・function・fork、
対応済みのautomaticと配列ref、配列・構造体を返す関数を組み合わせます。
1ビットだけが1の状態、多数の1、X/Z混在の3段階を調べます。副作用のある制御関数は1回ずつ呼び、
重複制御で二重に数えず、制御値の上位ビットを無視することを検査します。
対象を関数呼び出しで渡すケースでは、27回の問い合わせに対し27回だけ評価することを確認します。
136ケースすべてがローカルで通りました。

[代表例の比較記録](../measurements/2026-10-25/aggregate-bit-query-observations.json)に、
独自の配列・構造体・構造体配列の3ソース、ハッシュ、期待出力を残しました。
すべて新しいnativeで通り、保存した以前のnativeで失敗します。Icarus 13.0 stableと14.0開発版は、
配列への問い合わせを実行時に、構造体を使うソースをコンパイル時に拒否します。
その拒否を成功や新しい機能範囲の件数としては扱いません。

この接続は新しい格納形式を追加しません。automaticな構造体配列、構造体ref、構造体配列refは
引き続きP1の残作業です。動的コンテナ・文字列など、未対応のストリーム型も有効にはしません。
未対応の格納形式を試した独自ソースは、対応済みとは扱わずローカルのbuild観測へ残しました。
既存のテスト本体、期待出力、PerfCountの予算は変更していません。

古いスカラー専用の引数処理へ戻す誤実装を、モニターの解除漏れとは別に登録しました。
全面的な機能対応とIcarusが通る未対応項目は、残る機構の実装・検証が必要です。
この追加だけでP1完了とは判定しません。

コンパイルした[2件の誤実装](../measurements/2026-10-25/p1-coverage-negative-controls.json)は、
誤実装ツールの自己検査を除いた新しい実ソース・カーネルのテストで失敗します。
復元後は[ローカルCIの21項目すべて](../measurements/2026-10-25/p1-coverage-validation.json)が成功し、
dev・ASan・UBSanは3,500件成功・2件スキップ、releaseは3,501件成功・2件スキップです。
