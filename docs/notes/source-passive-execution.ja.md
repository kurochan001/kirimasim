## 範囲と根拠

ソースの `tran`、`rtran`、`tranif0`、`tranif1`、`rtranif0`、`rtranif1` を、
[検証済みの受動 SIR](passive-sir-execution.ja.md) と既存の Context 所有の網へ接続しました。
根拠は承認済み [MOS/スイッチ契約 1/3/6/7 節](mos-switch-proposal.ja.md)、
[規範的な対応](p1-execution-contracts-2026-10-25.ja.md)、SIR_SPEC 3/5/7/10 節、
VALUE_SEMANTICS 5.3–5.6 節、SCHEDULER_SPEC 9/12 節と IEEE 1800-2023 の
4.9.5/28.3.6/28.8/28.13/28.14 節です。新しい依存、公開 C ABI、形式の版、性能予算、
大域状態の例外は追加していません。

完全な承認済み契約の一部の実装です。登録 net の force/release、部分・非結合ポートの
同一性、完全な強度の書式と P1 の他の機能は残作業です。通常の固定配列 driver 取り込みの
既存の制限も残ります。6 シードを受け入れることを、完全なスイッチ対応や P1/Icarus 同等性とは
扱いません。

## 共通の正規化経路

`Lowerer::lowerPassive` は厳格な slang の束縛済み端子から、既存の型付き Place と
物理範囲を使って静的な net bit を求めます。module・generate・interface の net、alias と
適格な全体ポート、packed 選択、固定 unpacked 要素、連結、プリミティブ配列を扱います。
スカラー actual は共有でき、幅のある actual はプリミティブ配列と一致する必要があります。
位置は actual の右端とインスタンスの次元から決め、昇順と多次元の境界も扱います。
ソースの文字列を書き換える処理はありません。

固定した slang の API は、非抵抗型の双方向スイッチでは幅のある lvalue を返し、他の
プリミティブでは選択済み引数を返す場合があります。束縛された幅、`arrayPath` と次元を使い、
特定の綴りや失敗例への分岐は作りません。MIT 依存である slang の固定版
`16bd3b920dccfbcde000195f9d38d9b00432c9c8` の `PrimitiveInstanceSymbol::getPortConnections`
と公開宣言を確認しました。Icarus/Verilator の実装やテストは読んでいません。
正規化は承認済み契約と型付き API から独自に書きました。

条件付きスイッチは静的な cont 所有者を一つ持ちます。既存の暗黙感度の規則でスカラー制御と
正規化した on/off 遅延を捕捉して、辺を一つ更新します。区間だけの変化ではその式を再実行しません。
無条件スイッチには、端子の正規化後に実行するプロセスを残しません。
どちらもソース位置を保ち、共通カーネルの publisher を使います。

`finishStrengthNets` は従来どおり物理的な通常/MOS 根を取り込み、辺の所有者を結び、公開する
成分を併合します。解決済み readout は新しい根にせず、経路・alias・循環で driver を作りません。
force 対象の net は位置付きの未対応です。不正な型、動的な端子、uwire の inout 接続では
slang の厳格なエラーを保ちます。独自の [位置付き境界 6 件](../measurements/2026-10-26/source-passive-boundaries.json)
に、それらと現在の配列幅・force の制限を記録しています。

## 独立した網の分割と、一括公開の維持

最初の混在制御ベクトルで、公開成分に多数の独立したスカラー網を含めると、無関係な不定辺の
組み合わせまで掛け合わせる性能上の不足が見つかりました。その実行中のテストは中断して
アルゴリズムを直しており、成功扱いにしていません。

`StrengthDrivers::configureEdges` が、可能な接続から独立した網と辺のない単独 node を
準備します。`Scheduler::solvePassiveStrengthIsland` は、それぞれを従来の物理 origin・
world・経路の方法で厳密に解きます。最初は非導通の辺も接続に含め、不定な辺を近似しません。
独立した網の根は交わらないため、world の選択を分割しても宛先の区間は変わりません。
不定辺の数の上限や X への置き換えは追加せず、一つの接続網の中では指数時間になる可能性が
残ります。

すべての網を解き終えてから、元の成分 publisher が全値・区間を一括して確定し、callback を
呼びます。割り込み・資源不足では部分結果を公開しません。静的な作業領域は登録時に
transaction として確保・交換し、world ごとの割り当ては増やしません。
受動辺のない通常設計は元の経路を使います。

新しいカーネルテストは、独立した不定網 65 個と単独 node 2 個を、要素境界をまたぐ 132-node
公開に含めます。各対は独立した参照と一致し、最初と根の更新後の callback が、完成した
全 132-node snapshot を見ることを確認しました。利用者のプロセスは作りません。
従来のグラフ・資源・タイマー・参照テストも通ります。

## ソースと参照の証拠

`tools/gen_source_passive_matrix.py` は **独自 143 設計** を生成します。module・generate・
interface での強度・負荷・方向・制御、1/9/65/129 bit 配列、混在したベクトル制御、
昇順・rank-two・連結接続、スカラー共有、根のない循環、不定 world の相関、混在 wired 種類、
区間だけの感度、遅延導通、片側 high-Z を保つ三状態の根 4 種を含みます。
期待値は独立した符号付き点と world の列挙および承認済み契約から AI が作成したもので、
他シミュレータのテストの写しではありません。

143 設計がすべて通ります。[コンパイルした故障の記録](../measurements/2026-10-26/source-passive-controls.json)
は新規 8 件と既存の side-mask 故障 1 件を含み、すべて実際のソース・snapshot テストで検出しました。
anchor の自己検査による検出は含めず、ソースはバイト単位で復元済みです。
最初の 8 件の復元確認は 141 テスト、side-mask の追加確認は high-Z 根の新規 4 設計です。

[Icarus 13.0 との比較](../measurements/2026-10-26/source-passive-icarus.json)は、compiler/runtime
`13.0 (stable) (v13_0-dirty)` の実行ファイルのハッシュを記録しています。
143 設計中 135 設計をコンパイルでき、全標準出力が一致するのは 110 設計です。

- ベクトル制御の 20 件が異なります。[独自の配列/スカラー縮小例 12 件](../measurements/2026-10-26/source-passive-control-shapes.json)
  では、Icarus 13.0 の明示的なスカラー選択・リテラル形は bit ごとの期待値と一致し、配列形が
  異なりました。内部原因は **未確認** です。記録した入力でデータ・制御の幅を変えて調べられます。
- 遅延の初期状態 4 件と混在 wired の 1 件は、承認済みの初期状態・局所解決の選択による差です。
- rank-two のプリミティブ配列 4 件を参照が拒否し、スカラー共有配列 4 件では参照の
  エラボレーションが異常終了しました。その終了から内部原因は推測しません。

参照の `-dirty` 表示は、公式ソースそのままのビルドの証明にはなりません。
変更内容を推測するためにソースを読んでいません。実測版と実行ファイルのハッシュで比較を
再現可能にしていますが、参照の全機能範囲は未証明です。

既存の独自 87 プローブを [Icarus 13.0](../measurements/2026-10-26/icarus13-source-passive-probes.json) と
[14.0 devel](../measurements/2026-10-26/icarus14-source-passive-probes.json) に対して再実行しました。
Icarus が通るのに native が通らない差は、どちらも 14 件から 8 件に減りました。
参照と期待値の不一致はそれぞれ 4 件と 7 件です。クラス、specify path、real net 拡張、
イベント制御付き NBA、部分の強度ポート、automatic event、dense UDP 実行などが残ります。
有限のプローブは機能網羅率や完全な同等性の証明ではありません。外部 sv-tests は再計測していません。
固定の 1,466 パスの母集団を [再計測](../measurements/2026-10-26/source-passive-population.json)し、
1,456 成功、失敗ゼロ、未対応 10（99.3%）でした。28 章の部分集合は 22/22 が通りました。
