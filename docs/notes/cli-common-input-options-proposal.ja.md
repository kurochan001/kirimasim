# 修正案：シミュレータで共通の入力オプション

[English](cli-common-input-options-proposal.md)。状態：**人が承認済み**（2026-10-29）。
ソースの基準点は`7eb9606e`です。英語版を正本とします。
承認した修正を[CLI 2.1](../spec/CLI.ja.md)に記録しています。

## 方針と最初の範囲

意味が共通する入力オプションは、定着した綴りでも受理します。引数の書き方、既定値、
探索規則の違いを明記し、コマンドライン全体の完全互換を約束するものにはしません。

最初に`-I`・`-D`を追加し、CLI 2.1に記載済みでもdriverの直接引数検査で拒否されていた
`-y`を接続します。既存の`+incdir+`・`+define+`・`+libext+`・`-f`・`--top`は維持します。

CLI 2.1に追加する具体的な規則は次のとおりです。

- `-I<dir>`・`-I <dir>`：インクルード先を追加します。複数回指定でき、`+incdir+`と
  混在したユーザー指定ディレクトリの順序を保ちます。既存のローカルinclude探索規則を
  維持し、`-I`によってモジュールライブラリの探索先は追加しません。
- `-D<name>[=<value>]`・`-D <name>[=<value>]`：マクロを定義します。値の省略時は、
  固定版slangと既存の`+define+`経路に合わせて`1`とします。明示した空の値は空のまま、
  値に含まれる`+`や2個目以降の`=`も保ちます。区切り文字の異なる`+define+`への
  文字列置換は行いません。
- 記載済みの`-y <dir>`・`--libdir=<dir>`に加え、連結形の`-y<dir>`も受理します。
  既存のslangのライブラリ探索と`+libext+`の規則を使います。他ツールの`-y`が持つ
  include探索への追加効果は取り込みません。
- 通常実行と`parse`の両方に適用します。ディレクトリ引数の不足・空文字列、空の
  マクロ名は入力エラー（終了コード2）です。空白を含む有効なパスを保ち、コンパイル時の
  マクロと実行時のプラス引数を区別します。

移植するコマンドではマクロの値を明記します。

```sh
kirimasim -Iinclude -DWIDTH=8 -DENABLE=1 -y rtl/lib -f sources.f
```

`-f`内の相対パスは、従来どおり実行時の作業ディレクトリを基準にします。
前処理だけを行うモードなどは、別途動作を検討します。同じ名前でも意味が異なる例として、
Icarusの`-v`は詳細表示、Verilatorとslangの`-v`はソースライブラリの指定です。

## 確認した根拠と限界

2026-10-29に確認した公式資料：

- [Icarusのオプション](https://steveicarus.github.io/iverilog/usage/command_line_flags.html)。
- [Verilatorのオプション](https://verilator.org/guide/latest/exe_verilator.html)。
- [LyraのREADME](https://github.com/hankhsu1996/lyra/blob/main/README.md)。
  フロントエンドのオプションはslangと共有すると記載しています。
- [slangのオプション](https://sv-lang.com/command-line-ref.html)。

他のシミュレータのソースを読まず、独自の一時入力で前処理を確認しました。

- 手元のIcarusは`14.0 (devel) (s20260301-411-gca6b8d376)`、Verilatorは`5.052`、
  ビルドのrevision表記は`vUNKNOWN-built20260905`です。
- 連結形の`-Iinc`・`-DVALUE=2+3`、明示値の`-DFLAG=1`、空の`-DFLAG=`は
  両方で受理され、値の`+`も保持しました。値なしの`-DFLAG`は、このIcarusでは`1`、
  このVerilatorでは空に展開されました。
- 分離形の`-I inc`・`-D FLAG`はIcarusで受理、手元のVerilatorでは拒否されました。
  案の分離形は追加の受理形式であり、すべての参照ツールに共通するとは主張しません。
- 修正前のkirimasim dev実行ファイルの版表記は`938d60c833a6`で、直接指定の`-Iinc`を
  拒否していました。一方、`parse -f`経由では同じ連結形・分離形と明示したマクロ値を受理しました。
  基準点のソースにも直接引数の制限は残っています。
- Lyraの実行結果とIcarus 13.0の同じ入力での動作は**未確認**です。厳密な3ツールの
  互換性を主張する前に、版を記録した独自プローブで確かめます。Lyraは手元に未導入で、
  新しいツールはインストールしていません。

## 実装と検証

driverは承認済みの形式を検査し、マクロ値を書き換えずに渡します。help、日英マニュアルと
対応機能一覧も更新しました。新しい`cli/common_input`は、両実行モードで計93項目を検査します。
連結形・分離形、ローカルとユーザー指定includeの探索順、空白、マクロ値の明示・省略・空文字列、
記号、既存形式との混在、ライブラリの順序・拡張子・トップ選択、includeとの探索先の区別、
実行時プラス引数、ファイルリストのパス、不正な引数を対象にしています。

同名マクロの新規テストは当初、後の事前定義が優先すると仮定していました。既存の`-f`経路と
固定版フロントエンドでは最初の事前定義が残ることを独自入力で確認し、新規テストの期待を
既存の挙動に訂正しました。実装で定義の並べ替えや置換は行っていません。
既存テストの本体と期待値は変更していません。

devのCTestは8,242件すべて成功し、失敗・スキップはありません。追加したテストの件数は
全件実行したJUnit結果から再生成しました。新規CLI回帰はrelease・ASan・UBSanでも成功しました。
format、変更した翻訳単位のclang-tidy、releaseフラグ、禁止API、SPDX、期待値ファイルの対応、
大域状態、README集計の検査も成功しています。マニュアルの明示マクロ値のカウンタ例は
`width=8 cycles=6`を表示し、期待どおり70 nsで終了しました。
新しい依存や言語の意味の変更は加えていません。上記のとおり、3ツールのCLI全体との
完全な互換性は未確認です。
