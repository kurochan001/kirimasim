# 多次元メモリへのバイナリ入力：契約の修正案

[English](fread-multidim-proposal.md)。2026-10-24提案。**2026-10-25承認、実装中**です。
以下の提案本文は決定の記録として残し、承認を求める文は提案当時の記録です。
SYSTEM_TASKS 6.3はメモリへの入力を定めていますが、多次元メモリとスカラーの
start・countの対応は定めていません。[P1_SCOPE](../spec/P1_SCOPE.ja.md)は、
不完全な意味規則の実装前レビューを要求します。依存やツールの追加は提案しません。

## SYSTEM_TASKS 6.3への修正案

- 一次元は既存どおり、startを宣言した実際の添字とし、省略時は数値上の下限から
  数値の増える方向へ読みます。
- 残るunpacked次元が2つ以上の固定整数メモリでは、各次元の要素数の積をNとして、
  0からN−1の平坦な番地を定義します。宣言の方向にかかわらず各次元を数値の下限から
  上限へ進め、右端の次元を最も速く動かします。startはこの番地空間の整数の末端要素を
  指し、countは行数でもバイト数でもなく、その末端要素の数です。
- start省略時は0、count省略時は残りを埋められる数とします。startが番地範囲外か
  countが0以下なら、入力を消費せず0を返し、メモリを保ちます。メモリ末尾、countの
  消費、要素を完全に読めなかった時点で止めます。引数の型・変換とfdの規則は既存のものを
  使い、一次元の動作と既存の不正入力の診断は変更しません。
- 各整数の末端は既存の共通入力処理で読みます。上位バイトからceil(幅/8)バイトを読み、
  幅より上を切り捨て、EOFで読めなかったバイトの旧値を保ちます。返すのは読んだ総バイト数で、
  部分要素の後では止めます。通常の要素書き込みの変更通知と2値・4値への変換を維持します。
- 受理できる部分メモリの添字は、fd・start・countより前に捕捉します。その後の引数は
  VALUE_SEMANTICS 3.1どおり左から1回評価します。選んだ部分の残る次元を使い、
  外側の実際の添字を平坦なstart番地とは混同しません。
- スロット、自動変数のフレーム、実際のrefの格納先で同じ契約を使います。frontの走査と
  既存の型付き要素命令で実装し、VMにソースの番地の意味を持たせたり、SIR・カーネルの
  命令を追加したりしません。SIRの格納域の既存の上限は引き続き適用します。
- 動的配列・キューのサイズ変更と多次元の構造体メモリは、別の未完成の機構として残します。
  P1の到達点から外したり、slangの厳格な受理を緩めたりする提案ではありません。

多次元の番地空間は**プロジェクトの明示的な解釈案**です。IEEE 1800-2023の本文を
引用したものではありません。7.4.4・21.3.4.4を手元で確認しました。前者は次元の優先順、
後者はバイト・要素単位の入力を定めていますが、確認したバイナリ入力の節は多次元の
スカラーstart番地との対応を明示していません。

## 独自入力による観測と承認後の検証

Icarusのコンパイラ・ランタイムはともに`14.0 (devel)
(s20260301-411-gca6b8d376)`です。バイトメモリの独自入力で、`[0:1][0:2]`、
`[1:0][2:0]`、`[2:3][5:7]`、`[3:2][7:5]`、`[-1:0][-2:0]`の各形は、
数値の小さい添字から6要素を読みました。各形でstart=1は5要素、start=2・count=2は
行の境界をまたぐ平坦な位置2・3の2要素を読みました。countの前のstartを空にする形は、
21.3.4.4では許されますが、手元のIcarusコンパイラは拒否しました。slangの厳格な
受理は維持します。13.0そのものの動作は未確認です。他のシミュレータのソースやテストは読んでいません。

承認後は独立したバイト単位のモデルで、昇順・降順、非ゼロ・負の範囲、2・3次元、
一次元の回帰対照、バイト・機械語の境界をまたぐ幅、2値・4値、部分EOF、start・countの
境界と副作用を検査します。共通の格納経路、ref、待機も検査し、意図的な走査・件数の
誤りをビルドして実際の出力検査で検出します。既存のプローブと期待値を変更せず、
確認した差分を比較一覧へ追加します。
