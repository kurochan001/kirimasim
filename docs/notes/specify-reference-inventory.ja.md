# specifyの参照棚卸し

[English](specify-reference-inventory.md)。2026-11-01。

[最初のmodule path契約案](specify-p1-proposal.ja.md)に向けた有限の棚卸しです。
時間処理の実装やP1基準の変更ではありません。176プローブ、必須範囲の差2件、既存テスト、
件数を保ちます。既存`specify_path`ソースもbyte単位で保持しました。
SHA-256は`e31603a4f262a52b5c942a3bfef807f20b15aa20a5f98ed4abf4517712e21669`です。

## 測定した範囲

[機械記録](../measurements/2026-11-01/specify-reference-inventory.json)に、独自102ソース、
適用できる場合の期待値草案、hash、コンパイラ引数、観測、版を記録します。
明示的に選んだ既存のcompiler/runtimeは、どちらもIcarus Verilog 13.0 stable `v13_0`です。
`-gspecify`を必ず渡します。省くと、タイミングを無効にした構文解析の測定になってしまいます。
参照の実装ソースと、生成したシミュレーションbytecodeは読んでいません。

**記述したトレースとの一致87件、参照の差6件、観測のみ9件**です。
従来のnative実行ファイルは`80859f34f0aa`を表示し、102ソースすべてのparseが通り、
コンパイル・実行では未対応specify blockとして終了2で拒否します。
nativeのタイミング実行と成功はともに0です。この102回の試行を固定P1母集団やゲートの分母に
加えていません。

1/2/3/6/12個の遅延式と12種類の異なる4値遷移、既存固定プローブ、min/typ/max、
スカラー完全接続、最新入力と同時入力の選択、分布遅延との混在、正/負エッジ、極性/データ注釈、
既定pulse、0/負/実数遅延の正規化、状態依存条件、ベクトル、選んだpulse/force/内外の読み/
timing checkの観測を含みます。

## 差と制限

参照の差6件を残し、native不具合とは数えません。

- `vector_parallel`・`vector_full`：runtime自身が複数bit pathの未完全対応と、全bitへのLSB遅延の
  適用を診断します。独立したbitの時間差による中間ベクトル値が出ません。
- `negative_path_delay`：草案の0への丸めと異なり、テストの最後の観測後、tick 4,294,967,293で
  イベントを観測しました。
- `condition_1_bx`・`condition_1_bz`・`condition_2_b1x`：観測ではfallback遅延を使います。
  確認した2017版の規則は、条件LSBがX/Zでも有効にします。

これらの規則と遅延の展開は、一次資料のIEEE 1800-2017と照合しました。
公式文書のendpointが利用できず、2023版との直接照合は未確認です。
明記した草案/2017版の期待値との差であり、すべてを2023版に対する参照の欠陥と確定したという
主張ではありません。[提案の版の注意](specify-p1-proposal.ja.md#9-根拠と版の制約)に、
参照元と確認の方法を示します。

観測のみの9件には移植可能な標準出力の期待値を固定せず、成功に数えません。
明示的なpulse style/取消の4宣言と`$setup`には、timing check未対応の診断があります。
意図的にsetup窓へ違反させてもnotifierは0のままで、コンパイルできることだけでは
チェックの実行を示しません。PATHPULSEの入力は、既定なら除去する短いpulseと、しきい値を
小さくすれば通るpulseを区別します。生の観測を残し、pulse制御への対応を主張しません。

保留期限をまたぐforce/releaseは`forced 0`、`released 1`を観測しました。
cell内外の読みは期限前に0、後に1です。提案する接続の根拠であり、任意の参照の順序を
標準の期待値にしてよいという意味ではありません。

## 期待値草案の訂正と判定器の確認

最初の未コミットの表は、2式に通常ゲートのturn-off選択を使い、Xから出る遷移にも最小値を
使っていました。初回の差6件は期待値草案の誤りでした。2017版30章を読んで、この記録より前に
訂正しました。0からZはR、1からZはF、省略したXから出る遷移には可能な最遅の遅延です。
その後、遷移60件、固定プローブ、min/typ/maxの3件がすべて一致します。
ソースは保持し、既存リポジトリのテスト期待値を移行したものではありません。

[外部判定器の6故障](../measurements/2026-11-01/specify-checker-controls.json)は、
独自ソースのignoredコピーを1点変え、コンパイル・実行し、記述した期待値による拒否を要求します。
path期限、2式のturn-off、Xから1、別入力の遅延、分布遅延、pulse幅を変えました。
全てコンパイル・実行して検出し、前後の元6ケースも通り、runnerのhashが変わらないことを
確認しました。参照判定器の確認であって、nativeシミュレータの変異や将来の実装の証明ではありません。

## 再実行と終了コード

明示的な実行ファイルとignored出力先を指定します。

```sh
python3 tools/specify_feature_probe.py \
  --iverilog <icarus-13-compiler> --vvp <icarus-13-runtime> \
  --kirimasim build/dev/src/driver/kirimasim \
  --export build/specify-inputs --output build/specify-inventory.json
```

`--case`で独自ケースを選び、`--source-dir`で明示的なソースのコピーを使えます。
正本の期待値は保持するため、故障を再現できます。既定の終了0は棚卸しを記録したことを示し、
全ケースの成功を意味しません。独立した実行不具合では終了1です。
期待値や故障入力を検査する時は`--fail-on-reference-mismatch`を追加します。
参照に一致しないケースで終了1となり、この全棚卸しでは記録した差6件が該当します。
結果をPASSへ書き換えたり、skipしたりしません。

本体ソース、ビルド依存、CI登録、既存期待値、測定したゲート件数は変更していません。
実行時実装の前にnative契約の承認が必要で、既存拒否の移行も後の別レビューです。
