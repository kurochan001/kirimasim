# kirimasim にあって kirimasim-tests にないテスト

[English](kirimasim-tests-port-survey.md) · 2026-11-07。日英で食い違う場合は英語版を正本とします。

**状態：** 調査と、保守者への提案です。テストの移動や変更はしておらず、期待値も変えていません。
テストを移すかどうか、いつ移すかは保守者が決めます。[TEST_SUITE.md](../spec/TEST_SUITE.ja.md)は
「テストスイートを別リポジトリに分ける時期」を未決定としており、[VALIDATION.md](../VALIDATION.ja.md)は
同じ刺激で複数のシミュレータを比べる検査を[kirimasim-tests](https://github.com/kurochan001/kirimasim-tests)の役割としています。

## 問いと答え

`tests/suite/` のテストのうち kirimasim-tests にないものは、kirimasim-tests に追加すべきか。

**すべてではありませんが、選んだものは追加する価値があります。** 11,604 本のほとんどは kirimasim-tests になく、
kirimasim-tests のテストが届かない kirimasim のコード 2,814 行に届きます。それでも一括で追加するのは、
あちらのリポジトリに合いません。大半のテストがコメントと期待値の規則を満たさず、大半は対照シミュレータが
期待値を出しません。差の多くは、もっと少ないテストで埋まります。kirimasim-tests が対照を数えるやり方で、対照シミュレータが
期待値を出すと数えられる 2,625 本が、そのうち 1,173 行に届きます。その中の 40 本で 1,173 行すべてに届き、
25 本で 1,149 行に届きます。末尾の提案はここから始めます。

条項は、テキストよりはるかに重なっています。`tests/suite/` が `:lrm:` で引用する条項のうち、kirimasim-tests の
どのテストも引用しないのは 6 つだけです（18.13、20.14、23.3.3.6、30.1、12.5.3.1、13。計 16 本）。一緒に引用される
章の組で新しいものも 4 つだけです（5 と 15、20 と 28、14 と 28、12 と 21）。テキストと引用は粗い尺度です。
違うテキストで同じ動作を検査することもあり、1 つの条項には多くの動作が含まれます。次の、kirimasim のコードに
どこまで届くかの方が多くを語ります。

## tests/suite/ だけが届くところ

kirimasim の `src/` を行カバレッジ付きでビルドし、それぞれのスイートを自分のランナーで実行しました。
`tests/suite/` は `tools/run_suite_test.py`、kirimasim-tests は kirimasim-tests の `tools/run_kirimasim.py`
です。このビルドで kirimasim-tests のランナーは、11,172 本のうち 8,700 本が一致し、2,343 本が kirimasim の
未対応の構文で止まると報告しました。失敗したテストも数えています。

| ライブラリ | 行 | 両方 | `tests/suite/` だけ | kirimasim-tests だけ | どちらも届かない |
| --- | ---: | ---: | ---: | ---: | ---: |
| `driver` | 543 | 225 | 46 | 6 | 266 |
| `front` | 13,122 | 10,449 | 927 | 691 | 1,055 |
| `kernel` | 12,397 | 7,583 | 757 | 511 | 3,546 |
| `sir` | 6,683 | 3,893 | 178 | 435 | 2,177 |
| `vm` | 8,687 | 6,048 | 906 | 228 | 1,505 |
| **合計** | **41,432** | **28,198** | **2,814** | **1,871** | **8,549** |

`tests/suite/` だけが届く行は、主に `src/vm/vm.cpp`（682）、`src/front/lower_net_array.cpp`（193）、
`src/kernel/sim.cpp`（149）、`src/vm/scoped_reference.cpp`（122）、`src/kernel/managed_event.cpp`（109）、
`src/front/lower_container.cpp`（101）、`src/kernel/nba_event.cpp`（92）、`src/front/lower_nba.cpp`（85）、
`src/front/lower_net_ports.cpp`（83）、`src/kernel/activation.cpp`（78）にあります。オブジェクトやコンテナに
保持した event、automatic なスコープが捕捉した参照、net の配列と net のポート、イベント制御付きの
ノンブロッキング代入です。2,814 行のうち 269 行には、移せないテスト（後述）しか届きません。主に
`src/vm/vm.cpp`（101）、`src/kernel/dump.cpp`（58、波形のオプション）、`src/driver/main.cpp`（46、
コマンドラインのオプション）です。

残る 2,545 行には移せるテストが届きます。移せるテストのうち、kirimasim-tests が対照を数えるやり方で確かめられる 2,625 本
（次の節以降）は、そのうち 1,173 行に届きます。その中の 40 本で 1,173 行すべてに届き、5 本で 936 行、10 本で
1,037 行、25 本で 1,149 行に届きます。Verilator をすべてのテストで数えると、4,561 本が 1,373 行に届き、
そのうち 62 本で 1,373 行すべてに届きます。40 本は、まだ届いていない行をいちばん多く足すテストを順に選んで
決めました。

逆に、kirimasim-tests は `tests/suite/` が届かない 1,871 行に届きます。kirimasim の夜間ジョブは
kirimasim-tests の全テストを実行しますが、固定した P1 母集団を除いて、結果を報告するだけです。

## 移すのに必要なこと

kirimasim-tests の規則は、README の [Contributing](https://github.com/kurochan001/kirimasim-tests#contributing)
と `tools/lint_metadata.py` が定めています。それと照らし合わせると次のとおりです。

| 項目 | `tests/suite/` のテスト数 | kirimasim-tests の規則 | 移すのに必要なこと |
| --- | ---: | --- | --- |
| ファイル名と置き場所 | 11,604 | `tests/chNN/` の `test_<検査内容>.sv`、`:tags: chNN` | 名前とディレクトリの変更（機械的） |
| 条項の要求を説明するコメント | 10,289 本は「Generated by」の行しかない | 必須 | テストか生成器ごとに書く |
| 行の幅 | 80 桁を超えるコメント行が 987 本、100 桁を超えるコード行が 2,752 本 | 80 桁と 100 桁 | 折り返す |
| `:generator:` | 11,498 | `generators/` の生成器を指す | 生成器を移すか、項目を外す |
| `:expected_stderr:`（警告とエラーの行の完全一致） | 3,977。ファイルは空 3,552、警告だけ 255、エラーか fatal の行あり 166 | ツールのメッセージの文面は比べない | 前の 2 種類は外せる |
| `:nondeterministic: yes` | 466（`.choice` 付き 418） | 該当するテストはない。ランナーは期待値を 1 つだけ比べ、`:oracle:` に `choice` を書けない | まず kirimasim-tests 側に規約が要る |
| 違法な設計 | 59（位置を書く `:expected_error:`） | `:type: elaboration` と `:expected_stderr_regex:` | 書き直す |
| エラーで止まる | 249（終了コード 2：230、6：14、5：2、1：1、エラー行だけ：2） | — | kirimasim に残す（後述） |
| `:args:` の kirimasim のオプション | 19（`--max-call-depth`、`--wave`、`--seed`） | — | kirimasim に残す |
| `:timeout:` | 4,267 | 拒否されないが、読まれない | 何もしない |
| `:oracle:` | `spec` だけが 11,089、`spec choice` が 418、シミュレータ付きが 97 | 可能な限り Icarus Verilog 13.0 か Verilator 5.052 で確かめる | 次の節を参照 |

エラーで止まる 249 本は、kirimasim 自身の実行時エラーと上限を検査します。Postponed 領域での書込みやイベント、
時刻の最大値を超える遅延、null の event での待ち、呼出しの深さの上限、時刻が進まないことです。終了コードと
メッセージは kirimasim のインターフェースです（[リファレンスマニュアル](../REFERENCE_MANUAL.ja.md)）。
ほかのシミュレータがこれらの設計をどう扱うかは測っていません。

まとめると、標準出力だけを比べるものが 10,811 本、複数の出力を許すものが 466 本、違法な設計が 59 本、
エラーで止まるものが 249 本、kirimasim のオプションが要るものが 19 本です。前の 2 つ、計 11,277 本は、
検査の中身を変えずに移せます。

## kirimasim-tests の要件で増える分

kirimasim-tests は、テストを `coverage/behaviors.json` の要件の行に紐づけます。12,298 行のうち 1,318 行には
紐づいたテストがありません。そのうち 250 行は `tests/suite/` のテストが引用する条項に、63 行は親の条項が引用される
条項に、17 行は子の条項が引用される条項にあります。残る 988 行は `tests/suite/` のどのテストも引用しない条項で、
多くは 34 章（209）、37 章（101）、38 章（88）、40 章（46）です。テストを読む前の段階で、`tests/suite/` が
増やせるのは最大 330 行（2.7%）で、読めばさらに減ります。

kirimasim-tests は一度これを試しています。`tests/suite/` が 2,818 本だった 2026-10-25 に 540 本を取り込み、
641 行の候補を見つけて 21 本のテストと 58 行を登録し、どの行にも数えられないテストを残さないよう、残りの 519 本を
外しました（[その記録](https://github.com/kurochan001/kirimasim-tests/blob/main/docs/existing-test-matching-unregistered-20261025.md)）。

## かかる費用

11,604 本をすべて加えると、kirimasim-tests の大きさも、夜間ジョブでの各シミュレータの分担も倍になります。
2026-11-03 から 2026-11-06 の夜間ジョブは 2 時間 13 分から 4 時間 43 分かかりました。2026-11-06（UTC）に始まった
回では、Lyra のジョブが GitHub のホストランナーでのジョブの上限である 6 時間 0 分で取り消され、Verilator の
ジョブは 1 時間 41 分かかりました。

## 提案

1. **`tests/suite/` を一括では追加しない。** 2026-10-25 の試みと上の数字は、同じ結果を示しています。
2. **最初の候補から移す。** [`first_candidates.txt`](../measurements/2026-11-07-suite-gap/first_candidates.txt)
   の 40 本で、増える行の多い順に並んでいます。すべて移せるテストで、kirimasim-tests が対照を数える
   やり方で確かめられており、合わせると、確かめられたテストが届き kirimasim-tests が届かない 1,173 行に
   届きます。それでも 1 本ずつ、あちらの確認が要ります。名前と章、コメント、要件の行への紐づけ、固定版での
   期待値の確認です。順番は 1 つの実装の行で決めたもので、動作で決めたものではないので、写す一覧ではなく
   読む順番です。生成器では、主に `gen_event_initializer_matrix`（1 本、398 行）、
   `gen_port_kind_matrix`（1 本、277 行）、手書きのテスト（5 本、162 行）、
   `gen_class_observer_matrix`（3 本、105 行）から来ています。
3. **次に、その背後の生成器を移す。行列全体ではなく。** kirimasim-tests は、制約付きの 2 因子網羅と境界の
   場合でケースを選んでいます。移した生成器も、すべての組合せではなく同じやり方で選びます。
4. **どの対照も確かめていない移せるテスト**（8,652 本。2,814 行のうち、さらに 1,372 行に
   届く）は、規格だけで期待値を確かめる必要があります。kirimasim-tests はそれを（`:oracle: spec` として）
   受け入れますが、確認の手間が増えます。最初の 2 段階の後にします。
5. **kirimasim に残す：** エラーで止まる 249 本、kirimasim のオプションが要る 19 本、非決定的な 466 本の
   `.choice` の部分（kirimasim-tests が許容集合の規約を採らない限り）、`tests/suite/` 以外の `tests/` 全体。
6. **どう決めても kirimasim で行うこと：** 上の移せる 55 本の期待値を読みます。最初は
   `gen_override_initial_matrix` の 24 本です。既存テストの `:oracle:` に対照を書き込むとそのテストを変えることになり、CLAUDE.md の
   「期待値の変更は別の PR にする」に従って独立した変更になります。また、この測定は固定版で行っていないので、
   ここから `:oracle:` に書くものはありません。

## 確認していないこと

- **対照の版。** Icarus Verilog は 13.0 の安定ブランチの `v13_0-25-g07dd50d37` で、13.0 のリリースそのものでは
  ありません。Verilator は 5.053 の開発版で、5.052 ではありません。固定版では数が変わる可能性があります。
- **どちらが正しいか。** 対照が実行してどれも一致しない、移せる 2,872 本について、どちらが規格に従っているかは
  確かめていません。上の 55 本のうち 8 本を読んだだけです。
- **行は動作ではない。** テストはある行に届いても、それについて何も判定しないことがあります。1 行に複数の
  動作が入ることもあり、失敗したテストも数えています。これは 1 つの実装の、1 つのコミットでの尺度です。
- **kirimasim-tests が届く範囲は小さめに出ている。** kirimasim-tests の kirimasim ランナーは `:dpi_c:` か
  `:vpi_c:` を持つ 684 本を実行せず、2,343 本は kirimasim がまだ対応していない構文で止まります。
  2,814 行は上限です。
- **ランナー。** `measure.py` は kirimasim-tests のランナーと同じオプションで各対照をビルド・実行し、
  同じように出力を正規化しますが、そのランナーそのものではありません。また、非決定的なテストでは許される出力の
  どれとも比べますが、あちらのランナーはそうしません。
- **粗い尺度。** テキストの類似と条項の引用は単語を数えるもので、動作を数えるものではありません。
- **時間。** 各実行は 60 秒までで、Icarus Verilog の 2 本と Verilator の 3 本が時間切れになりました。
