# 無効なキュー書き込み：診断期待値の分離修正

[English](queue-write-expectation-migration.md)

状態：**承認済み（2026-10-29）**。保守者が [Issue #67](https://github.com/kurochan001/kirimasim/issues/67)
について、この期待値修正を明示的に承認しました。[AI_POLICY](../spec/AI_POLICY.ja.md) の期待値保護規則に従い、
期待値だけの変更を実装と分けます。承認は、対応する単体テストの無診断のアサーションを
正確な警告比較へ変えることも含みます。値の検査はすべて保ちます。

IEEE 1800-2023 7.10.1 は、無効な添字へのキュー書き込みに実行時警告を要求します。
書き込みでキューは変わりません。既存の生成テストは、キューの範囲を超える 129 ビット添字と
X の添字へ各 1 回書き込みますが、stderr の正確な期待値が空です。値の検査は正しく、無警告の要求が誤りです。

既存の stderr 期待値 89 件を直します。実行場所 8 種類・要素幅 5 種類・値の領域 2 種類の
キューテスト 80 件には、位置付きの警告を各 2 件加えます。
診断は `write to an invalid queue index is ignored` です。位置は各代入式の先頭で、
変えないヘッダを加えた後のソースから求めます。2 式は同じ行の異なる列にあるため、
別々の警告位置として保ちます。

残る 9 件は、各実行場所のスカラー `$fread` 評価テストです。整数の代入先は要素 1 個のキューの
`q[99]` です。入力は 4 バイトなので、呼び出しは書き戻しを試み、7.10.1 により同じ警告が必要です。
値の結果は `invalid 4 17` のままです。4 バイトを読み、キュー要素は変わりません。
count 引数が 0 でも整数入力は抑制されません（21.3.4.4）。したがって、0 バイトの読み込みとは
異なり、この呼び出しの書き込みを無警告で省略できません。

スカラー入力の警告位置は、生成した書き戻しを所有する `$fread` 呼び出しの先頭です。
ジェネレータは変更していないソースから行・列を求めます。既存の slang のコンパイル警告は
バイト単位で内容・順序を維持し、その後に実行時警告を 1 件加えます。

`tools/gen_dynamic_container_matrix.py` と `tools/gen_scalar_fread_matrix.py` が診断を生成します。
生成する SystemVerilog は全バイト不変なので、版は 1 と 2 のままです。
全 393 ソースと stdout 期待値 393 件の SHA-256 を維持します。動的配列行列の全件と
スカラー入力の値ケースを含む、他の stderr 304 件も変えません。
削除・改名・スキップ・検査の緩和はなく、この提案に `src/` や性能期待値の変更はありません。

両ジェネレータの通常実行・`--check` と `git diff --check` は成功しています。
前後のハッシュはローカルの `build/queue-write-expectations/` に保存しています。
対応する実装は、独立に導いたこの診断に一致する必要があります。
既存のキューの値、合法な末尾挿入、無警告の読み込みは厳密に検査し続けます。
