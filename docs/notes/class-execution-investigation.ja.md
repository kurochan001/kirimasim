JSONには独自ソース、SHA-256、設定した場合の出力モデル、規格の節番号、コマンド、

正規化しています。他のシミュレータのソース・テストは読まず、ツール・依存の追加もありません。

nativeはモデル一致1本、未対応42本、出力不一致1本、違法な入力の拒否2本でした。

## 確認できた境界

プロパティを使わないstatic関数の`Helper::value(5)`はnativeで7を返しました。
両参照はこのソースを拒否します。この1例をクラス全体やstaticメンバーへの対応とは扱いません。

インスタンスを作らないクラスの`static int value=history::mark()`では、nativeが
初期化の副作用を落とします。`mark()`で増やすpackage内のカウンタは両参照では1ですが、
nativeでは0です。strictなparseは通り、実行も終了コード0でした。そのため、従来の
「未対応なら必ず診断し、黙って読み飛ばさない」という説明は修正しました。クラスのstatic
初期化には既知の不具合があり、実行の成功だけでは対応を確認できません。静的な生存期間と
共有プロパティの初期化にはIEEE 1800-2023の6.21・8.9が関係します。未使用クラスや
パラメータ特殊化を含む完全な初期化契約は、クラス実装前にレビューする必要があります。

コンストラクタ引数、フィールドの隠蔽、非virtual呼び出し、インスタンスconstプロパティ、
output書き戻し、`always_comb`のクラス参照を暗黙感度から除く形では、参照のモデル一致を
観測しましたが、nativeは未対応です。初期化段階の例は14.0で一致し、13.0は拒否します。
virtual dispatchではモデル`9 9`に対して両参照が`3 9`を出し、nativeは未対応です。
この参照出力を採用せず、8.20に照らして必要な対応を維持します。

nullへのメソッド呼び出しやnullのshallow copyは、承認済み期待値を置かない境界観測です。
`$cast`の実行失敗やプロパティNBAのbackend assertionも、失敗として記録し、期待値には
使いません。初期化済みconstへの書き込みとabstractクラスの生成は3実行系とも拒否します。

## 残る契約と検証

必要なP1の範囲には、型付きのオブジェクト識別・ルート、コンストラクタの段階、static初期化、
継承とdispatch、パラメータ化したレイアウト、shallow copy、null・cast、停止中のメソッドの
receiver、プロパティのref・書き戻し・NBA、event依存、オブジェクトの乱数状態が含まれます。
関係する節は8.4・8.7・8.9〜8.12・8.19〜8.21・9.2.2.2.1・18.14などです。
既存のSIR・runtimeの概要だけでは詳細が定まっていません。この調査は詳細仕様の修正案や
新しい方針の実装承認ではありません。

クラスの全面対応、Linuxでの結果、未検査の組み合わせは未確認です。詳細契約のレビューと、
独立したkernel・SIR検査、機構と組み合わせを覆う独自ソースの行列で確認する必要があります。
[現在のP1の状況](p1-icarus-progress.ja.md)を参照してください。
