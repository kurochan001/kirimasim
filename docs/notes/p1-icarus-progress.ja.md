# Icarusの機能範囲を目指すP1の拡張

[English](p1-icarus-progress.md)。状態：進行中、2026-10-24。

到達点は、Icarus Verilog 13.0以上の機能をP1で支えることです。
全面的な同等性は**未確認**です。従来の合格率や、下の小さなプローブだけでは
判定できません。P3・P4や対象外の機能を前倒しする
[範囲の修正](p1-icarus-scope-proposal.ja.md)は2026-10-23に承認され、
[P1_SCOPE](../spec/P1_SCOPE.ja.md)へ反映しました。

## 実行時の連結とキューの読み取りスライス（2026-10-24）

`919d11f`で、承認済みのコンテナ契約のunpacked連結とキューの読み取りスライスを
実装しました（7.10.1・7.10.4・10.10）。SIR命令やVM・カーネルの値の規則は追加せず、
`Lowerer::appendContainerRange`を共通の型付き構築ループにしています。
上限なしのバッファに変換した要素を保ち、実際の代入先で上限を適用します。
スカラー、固定配列、配列を返す関数、動的配列、キュー、入れ子の値を、ソース順に1回評価します。

スライスは、境界を左から1回ずつ評価する前にソースの値を捕捉し、`$`は捕捉した長さを
使います。広い符号なし境界の符号用ビットを保ち、負の下限と過大な上限を切り詰めます。
X/Z・逆順・範囲の重なりがない場合や空のソースは、要素を追加しません。
結果は独立したコピーで、キュー全体への代入をまたぐ既存のrefは承認済みの規則どおり
切り離したセルを保持します。スライスを代入先にする形は未対応です。

独自の行列を256件追加しました。8種類の実行場所、1・4・32・64・65・129ビット、
2値・4値、2種類の代入先と、機構の64件を組み合わせています。配列を返す関数、
入れ子の実際の上限、real・string、保持したref、ソースの呼び出し、境界式が元の要素を
直接変更する場合も検査します。別途、符号・X/Zを含む32→129ビットの変換も通過しました。
既存の本体・期待値・PerfCountは変えず、生成器自体もCTestへ登録しました。

意図的な9種類の誤りはすべてビルドに成功し、実際のソース出力の差で検出しました。
余分な要素、左右それぞれの符号欠落、X/Zを0にする誤り、末尾の欠落、負の境界、
ソース値の共有、ソースの重複評価、早すぎる上限適用です。復元後のソース・CLIの
257テストも通過しています。アンカーや判定ツール自身の失敗は、値の正しさの根拠から除外しました。

`919d11f`のローカルCIは、4構成のconfigure・build・testと、releaseフラグ、禁止事項、
SPDX、スイートのファイル、グローバル状態、未公開7コミットの期待値保護、README件数、
clang-format・clang-tidyがすべて通過しました。dev・ASan・UBSanは各2,672件中2,670件成功、
既知の2件がスキップです。releaseは2,673件中2,671件成功、同じ2件がスキップです。
文書の例も、記載した出力と警告なしの実行を確認しました。コンテナの基本行列と
連結・スライスの行列は合計496ソースで、従来のCLI診断11件も保持します。

`919d11f`と表示するバイナリで拡張比較も再実行し、59プローブにIcarusだけが通る

共通の変換で、構築・初期化・深いコピー代入、要素とpacked部分の書き込み、メソッド、
実際の上限を保つref、値引数・戻り値、入れ子、固定配列・unpacked構造体内のコンテナを

入れ子の同値なref型を通す場合も、実際の変数へ代入するときに上限を適用します。

package、program、generateです。引数の独立性、移動・切り離した参照、入れ子の上限、

## 型付きヒープの監視の土台（2026-10-24）

実装コミット`2c674a6`で、SCHEDULER_SPEC 9.5の動的な監視へ向けた読み取り・変更のフックを追加しました。
コンテナの要素列・サイズと、切り離したものを含む個々のセルの値を区別します。

## 承認済みの動的コンテナの共通ヒープ

2026-10-23に、利用者が本仕様の選択を含む動的配列・キューの修正案を承認しました。
実装前に、日英のSIR_SPEC 4.2.1とRUNTIME_ABI 6へ実行上の契約を反映しました。

`Context::heap()`が、世代を検査するコンテナと要素セルのトークンを持ちます。
`Heap::construct`・`copy`・`fromValues`と入れ子への書き込みは独立した値を作り、
キューの挿入・削除・移動は残るセルの識別子を保ちます。旧参照は切り離したセルを
読み書きできます。コピー・挿入には代入先のキューの上限を適用し、実行する層に
警告の種類を返します。平坦な要素配置は整数・実数・文字列・不透明なハンドルの語と
入れ子の型付きの辺を表し、slang・SIRへの依存はありません。

標準のメモリ資源を切り替えて確保します。確保失敗時は新しいコンテナ・セルをすべて
巻き戻し、変数・旧参照・出力用バッファを変更しません。公開操作はエラーを返し、確保の
例外を外へ漏らしません。コピー・回収は反復で行い、深い入れ子でもネイティブの呼び出しを
再帰させません。正確な回収は明示したコンテナ・セルのルートをたどり、到達する切り離した
セルも保ちます。解放した表は世代を変えて再利用し、印付けの失敗時は何も解放しません。
呼び出す層には、許された境界で全ルートを渡す義務があります。

15本の新しいカーネルテストで、整数の幅・2値/4値・上限の56通りを各450操作、
合計25,200操作確認しました。操作・回収ごとに、listを使う独立した
`valsem::ContainerValue`のモデルと比較します。2,500段の入れ子、実数・shortreal・
文字列・集約値の配置、同サイズへの再確保、自己コピー、上限での切り捨て、
構築・コピー・変更・印付けの各確保地点での失敗、4,096回の表の再利用、Context間の
分離も確認します。誤ったセル、入れ子の共有、巻き戻し時の漏れ、印付けの辺の欠落、
世代の無視、挿入位置の誤りの6つの変異を、補助ツールの検査を除く実テストですべて
検出しました。復元した実装も通過しています。`20261023`をシードにした100回の
独立した試行、合計2,520,000操作も通過し、nightlyの参照検査へ追加しました。
試行ごとに初期化することで、検査量を倍率に比例させています。

回収・巻き戻しは、先に大きさを確保した空き項目の格納域へ添字で戻すので、確保を
呼ばない構造です。追加の確保失敗テストでは、回収した項目を再利用し、途中でコピーを
失敗させ、回収前に再試行しても旧参照の値と古いトークンの拒否を保つことを確認します。
不明（X/Z）の構築サイズはInvalidSizeを返し、不正なルートの種類はトークンが0でも
拒否します。
