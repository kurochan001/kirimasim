# ソースの代入パターン形式の表示

[English](source-pattern-formatting.md)

承認済みのSYSTEM_TASKS 3.9（IEEE 1800-2023 21.2.1.6）に従い、ソースの`%p`・`%0p`を
既存の共有カーネルの描画処理と型付きSIR命令`pattern.format`へ接続します。
依存、互換モード、命令opcode、C ABIの版は追加しません。

## 対応する値と呼び出し

整数、real/shortreal、文字列、列挙型、packed構造体とpacked共用体の最初のメンバ、
対応する固定unpacked配列・構造体、型付き動的配列・キューと、対応済みの入れ子を扱います。
宣言順、packedメンバのオフセット、符号・状態・列挙名はslangのエラボレーション済みの型から取ります。
`%0p`は構造体の名前を再帰的に省きます。引用・escape・10進数・X/Zの表記は既存カーネルが定め、
frontやVMに別のformatterを作りません。1,024文字で打ち切りません。
`%p`の一般の幅・フラグ・精度は未対応で、今回は`%p`と`%0p`を受け付けます。

slangが暗黙の文字列と分類するリテラル由来の整数式は、既存のSV文字列変換を表示に使います。
元のpacked値も残し、通常の数値変換と監視の比較にはそれを使います。
`"ab"`や`{"a","b"}`の`%p`は引用付きですが、同じリテラルの`%0d`や明示的な整数キャストの
`%p`は整数の意味を保ちます。埋め込みNULには既存のSV文字列キャストの規則を適用し、
新しい表現上の方針は定めません。

`$display`・`$write`、ファイル・基数付きの形、`$swrite`、`$sformat`・`$sformatf`、
Postponedのstrobe・monitorとファイル付きの形を同じ経路に通します。
実行時の書式は文字列・packed値の両方を使え、packed代入先の書き戻しも既存の意味を保ちます。
遅延表示でのautomatic変数の制限は保ちます。programのテストはPostponedの表示までprogramを生存させ、
暗黙のprogram終了による即時のシミュレーション終了の契約は変更しません。

## 値の保持と共有表現

実引数の式はソース順に一度だけ評価します。定数書式の`%p`引数は、その時点で不変の文字列へ描画し、
対応する書式を`%s`へ置き換えます。後の引数が前の描画を変えることはありません。
実行時の書式では、元のスカラー値（該当する場合）と、名前付き・位置形式の両方の文字列を保持します。
書式自体も引数の評価前に保持します。

`$sformatf.runtime.pattern`は、名前の後にscope、cell、tick倍率、書式を持ちます。
続く4項目組は、元の値のPatternId、元のスカラー（集約値なら空のmarker）、名前付き文字列、
位置形式の文字列です。空引数は空marker4個です。検証器はprefix、4項目組の個数、元の型、
layout ID、文字列2個の型を確かめます。暗黙の文字列表示では、元の値と描画のlayoutが異なることがあります。
VMはこの明示的な型付き表現をkernelの`FormatValue`へ渡し、通常の数値・文字列変換は元の値を使います。
型付き表示情報のないnative SIRの`%p`は、ビットから推測せず拒否します。

パターンのmonitorは、出力を準備するのと同じ評価で元の引数を保持します。
コンテナは値を切り離して保存し、入れ子も辿り、整数の末端はcase equalityで比較します。
描画結果ではなく元の値を比較するので、同じ文字列を表示する別の値も区別します。
`$time`だけの変化では表示しません。既存のheap読み取りの捕捉処理でセルと置き換わるbindingを追い、
監視の情報は弱い参照のままです。パターン以外の従来のmonitor経路は変更しません。

activeなオブジェクトメソッド内の合法なスカラーのプロパティ読み取りも、この経路を使います。
通常の関数を経由するものも含め、オブジェクトのプロパティ依存の監視は引き続き未対応です。
対応済みの別の値の表示は、同じ設計がオブジェクトを確保するだけでは拒否しません。
class/event/chandle全体の識別表示、連想配列の格納、未対応のtagged/unpacked共用体の格納は残る境界です。
`%p`全体やP1の完成を主張するものではありません。

## 検証と期待値の移行

独自の[生成器](../../tools/gen_pattern_format_matrix.py)は、12文脈・17 APIから
合法な196ソース・4,312変換を作ります。[CLIの判定](../../tests/cli/run_pattern_format_tests.py)は
文字列・escaped名を保った字句tokenを比べ、フィールドの空白は無視します。
実装に依存する`%p`の空白をsuiteのstdout goldenへ入れません。
ソース・VMの単体検査は、幅広い列挙値とpacked window、引数による変更、集約値の戻り値・参照、
入れ子・空・縮小したコンテナ、長い出力、暗黙の文字列の元の値、遅延表示、オブジェクトの境界、
不正なSIRも調べます。

登録したコンパイル変異8件は、モード、メンバのオフセット、評価回数、切り離した監視の値、4値の比較、
元のスカラー値、表示引数の型、無関係なオブジェクトとの併用を対象にします。
実行結果と構成ごとの確認範囲は[検証記録](source-pattern-validation.ja.md)へ分けます。
[期待値だけの移行](source-pattern-expectations.ja.md)では元の入力と、残る拒否の検査を保ちます。
P1母集団、外部合格率、元の有限のIcarus一覧、既存の処理回数の予算は変更しません。
slangへの投稿は引き続き保留です。
