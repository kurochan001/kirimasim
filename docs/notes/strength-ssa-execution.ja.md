# 所有するstrength SSA値とMOSの実行

[English](strength-ssa-execution.md)が正。状態：実装・検証済み、2026-10-26。
内部SIR値の接続であり、ソースのMOS/スイッチ対応は残作業です。

## 根拠と境界

承認済みの[MOS/スイッチ契約](mos-switch-proposal.ja.md)1/2/7と
[正式仕様への対応](p1-execution-contracts-2026-10-25.ja.md)、SIR_SPEC 4.1/5.1/10、
VALUE_SEMANTICS 5、IEEE 1800-2023 28.7・28.9・28.13・28.14が根拠です。
実装とテストは独自で、他のシミュレータの実装・テストは読んでいません。
[純粋演算](mos-strength-operations.ja.md)のカーネル側スカラー素子の意味を保ち、`valsem`と照合します。

新しい内部型`strength<w>`は、各ビットの完全な区間を所有します。
幅は正で、descriptorや算術の符号は持ちません。SSAのメタデータであり、
SystemVerilogの記憶域の型やhandleではありません。現在の検証器は命令の結果とblock引数に認め、
slot・定数・frame・ref・型descriptor・サブルーチンの引数/戻り値には認めません。
専用の命令と型付き分岐引数だけが使用でき、通常の算術・変換・select・system task・builtinで
4値やhandleとして解釈することはできません。既存SSAの定義前使用・支配関係・
待機をまたぐ使用の禁止はそのまま適用します。

次の3命令をSIRから実行まで接続しました。

- `strength.make`：捕捉済みの幅wの4値、定数rank 0..7を2個、任意の幅2wの捕捉済み2値side maskから
  `strength<w>`を作ります。表現可能な任意幅の既知の符号付き/符号なしrankを認め、負数・X/Zは拒否します。
  maskの下位w bitが1側、上位w bitが0側で、幅33/65/129などワード境界に合わない半分も保ちます。
- `strength.mos`：`nmos`・`pmos`・`rnmos`・`rpmos`・`cmos`・`rcmos`、一致するstrength値、
  スカラー制御1個（CMOSは2個）から、同じstrength型を作ります。制御は両状態域・両符号に対応します。
  素子名は読み込み時に1回解決し、区間の意味はVMで作り直さず、共有カーネルの既存MOS演算へ渡します。
- `strength.value`：既存の射影で、完全なstrength値を符号なし`i4<w>`にします。
  ここで明示的に端点を捨てます。

契約の残りの`strength.load`・`strength.drive`・その遅延形には、net/driver記憶域と
所有する登録が必要で、この段階では実装していません。frontのソース構文も有効にしていません。

## 転送と共有カーネル

`kernel/strength_value.h`はSIR・slang・LLVMから独立したC++20の公開APIで、
確保せず、例外も投げません。W4と同じ大きさの1ワードに、`a`へloの符号付きbyteを8個、
`b`へhiを8個、明示的なshiftで最下位byteから格納します。この2フィールドは端点の記憶域で、
aval/bvalではありません。ホストのbyte順序への依存、pointerやGC rootの符号化はありません。

入力の全区間・形状・rank・素子種別を、出力の変更より前に確認します。
出力と入力のspanは重ねない契約です。成功時は末尾の未使用byte/bitを0にし、余分な出力ワードは保ちます。
非導通の制御でも、最後のbitを含め入力の端点を確認します。
公開ヘッダの検査と、例外/RTTIを無効にした単独コンパイルでC++20との互換性を確認します。

VMはstrengthの一時値に通常の整数の`ceil(w/64)`ではなく`ceil(w/8)`ワードを割り当て、
一時値offsetの加算も検査します。入力を捕捉し、別の所有する結果へ書きます。
分岐は全引数を読んでから全ワードを各parameterへコピーします。
入れ子の関数実行も同じ型付きの一時値配置を使います。純粋命令内でソースのcallbackや予約は行いません。
VMの入力の捕捉には現在確保があり、その最適化とソースMOS全体の速度測定は残作業です。

formatは0、C関数表のABIも維持します。新しい型と命令名を決定的に出力します。
パーサはまだなく、print/parse/printの保証はP2の作業です。同じ出力を繰り返すテストを
往復の証拠とは扱いません。

## 検証

`0ec3cc57`で独自13テストを追加しました。カーネルでは全120区間を32配置（3,840ケース）、
11幅のmake/rank/side 1,408ベクトル、packed MOS 12,384件を独立した点/制御の参照実装と照合します。
末尾の消去・余分なワードの保持・不正なrank/形状/端点と、出力を部分的に変える前の失敗を検査します。
SIRでは、言語の記憶域/インターフェースと通常の消費命令への混入、不正なrank/mask/素子種別、
射影の型、範囲指定の付いたSSAと待機をまたぐ使用を拒否します。

VMは手書きSIRの2,034設計を実行します。幅/素子/mask/制御1,920、符号/状態域96、
分岐の並行コピー12、通常/scopedのinput fieldを持つ入れ子関数6です。
交換した両方の引数を観測します。既存dump全29件を含む対象67件が通りました。

[コンパイルした故障9件](../measurements/2026-10-26/strength-sir-controls.json)を検出しました。
端点の欠落、side半分の位置ずれ、不完全な事前検査、射影のX/Z欠落、VMのワード数、p素子の解決、
system taskへの混入、分岐コピーの切り捨て、mask幅検査の欠落です。
全体ビルドはC++20のprobeも含め全件成功し、その後の実際のテストで失敗しています。
コンパイル失敗を検出とは数えません。元と復元後は新規13件が通り、登録済み677故障すべてが適用できます。

[全local CI](../measurements/2026-10-26/strength-sir-validation.json)は全21確認成功です。
dev/ASan/UBSanは5,152/5,154、releaseは5,153/5,155で、各失敗0・既知スキップ2件です。
既存dump・PerfCount・静的検査・生成件数も通ります。実装だけのコミットの期待値変更検査も成功し、
既存の期待値は変えていません。README件数は新しいdev全件JUnitから生成しました。
ローカルmacOS arm64での結果です。

## 残る実行の接続

独立した強さの通知・完全な区間の公開を実装します。スカラー単位の慣性遅延、world間の相関を保つ受動solver、
force/release・portの対応・強さの書式も必要です。プリミティブ配列でも、保留状態はスカラーごとに所有します。

既存の期待値・ソースと性能予算は保護します。
