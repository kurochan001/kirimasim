対象は通常の ABI write に到達した 236,569,230 回。すべて 64 ビット以下の変数で、今回の事前除外条件に該当した書き込みは 0 回だった。部分選択のうち動的な範囲は同値 145.14、変化 15.35 回／サイクル。固定範囲の部分選択は同値 32.02、変化 8.02 回／サイクル。初版の固定箇所は全幅込みで **385.61 回／サイクル**となる。これとは別に 3 プロセスの既存のループ変数一括処理が 165.54 書き込み／サイクル、165.54 変化／サイクルを処理済み。合わせた論理件数は **711.64 書き込み、276.84 変化／サイクル**。このループ変数分を新しい W の節約に含めない。

**購読があるスロットも、同値のときに打ち切れることが重要である。** 同値 434.80 回のうち普通の感度購読があるのは 367.88 回、ないのは 66.92 回。変化した 111.30 回のうち 94.77 回には購読があった。初版では変化時に必ず旧値が残った状態で元の write を呼ぶ。エッジ、同期ガード、再入するコールバックは元の位置で旧値と新値を見る。購読がないスロットだけを候補とすると、同値側の削減余地の約 85% を失う。

## 提案する契約と照合

f28d6fe8 では、狭い整数の同値による戻りがすべての観測処理より前にある。強度所有と保持の分岐は [Scheduler::write](../../src/kernel/sim.cpp#L2582)、初期化・表の追従・両プレーン比較は [writeRaw](../../src/kernel/sim.cpp#L2811) にある。Release カーネルにガード付きの変化待ちを登録して直接呼び出すと、全幅・部分選択 × 4 値・2 値近似の 4 条件すべてで false を返した。記憶・登録数・全カウンタの差は slot.writes の +1 だけで、直後の実際の変化では各条件ともガードと待機プロセスが一度ずつ動いた。波形・VPI・競合などを含む受入試験はパッチに記載した。

- 固定要素の全幅と範囲内の固定部分選択を対象にする。右辺、添字、実行順、待機登録はそのままに、物理スロットと選択範囲で判定する。多出力のプロセスや SCC 内でも各書き込みを現在の順で実行する。ネット、ドライバの裏記憶、NBA、動的範囲は従来経路へ送る。
- 検証済みの箇所を Context・設計ごとに一度束縛する。初期化と表の追従後、4 値では両プレーンを、2 値近似では X/Z 正規化後の値を比較する。同値なら書き込みを一度計数し、元の ending 呼び出しを維持する。保持対象・強度所有、値の変化、束縛の失効時は格納・計数前に通常経路に渡す。検証する世代は Context 共通の記憶・適格性の世代だけであり、購読・監視・VPI・グリッチ・競合観測では失効しない。観測者別の適格性は変化時も直接書く後続版で検討する。
- レビュー用パッチは融合用サービス 19 版 1 と独立した任意サービス 20 版 1 と、その C レイアウトを示す。照合版は最適化した影と VM の双方で同値を含む全試行を記録し、要素、範囲、正規化値、書き込み列、観測、カウンタ、終了位置を比較する。同期ガードが後続の読み出しや停止を変える場合は同じ観測を影に再生するか、比較できるところまで辞退する。実体への反映は 1 回。あふれは照合失敗。通常実行には記録を生成しない。
- 受入試験は全幅・部分・重なる部分の連続書き込み、A→B→A、X/Z 同値とエッジ、同じ値を force 中に書いた後の release、動的な購読追加、SCC・別 Context・再入、同期終了、SIGINT の順序を組み合わせる。直接と辞退の両方が実行されたことを独立に確認する。

読み出しはアドレス取得、ending は呼び出しとフラグ取得までを数えた。読み出した値の演算、呼び出し後の終了分岐は各欄の外にある。最適化後 IR では通常本体・特殊化計 79 関数に t 配列の実体が 0 個。生成ソースの 76 配列を個別の同型変数にした対照でも、コード領域 261,028 バイトが完全一致した。ヘッダの 4,849 命令には必要な値演算がある。レジスタの全スピルを W4 の費用に帰属させる根拠はない。

以前の **65,248 命令／サイクル** はカーネル書き込みなどを除いた、サービスを含む生成呼び出し範囲の標本推計。今回の生成モジュール内の動的命令は約 27,224／サイクル。読み出しと ending は以前の推計の約 13.0%、5.9% に相当する。残りには制御、値演算、checkpoint、他サービス、以前の帰属誤差が含まれる。4 値や他の CPU へは外挿しない。

## 順序と関門までの距離

現在の低負荷の基準ペアは 9.706963 秒と 0.102895 秒。1.40% の関門は **7.34964 秒以下**。今回の通常実行は 509,389 命令／サイクル（5 回の中央値）。時間と命令数が比例するという仮定なら約 **123,704 命令／サイクル**の短縮が要る。

| 実験順序 | 最初に必要な作業 | Ibex に対する条件付き見積もり |
|---|---|---|
| **推奨　変数 W → 島 4 の S/WS** | 書き込み箇所の束縛・同値比較、失効、影の照合。島の編成を変えず通常生成本体で有効化できる | 固定箇所の同値呼び出しは約 42,937 命令。固定の全 385.61 回に 16〜32 命令の検証・比較・計数費用を課すと **30,597〜36,767 命令（6.01〜7.22%）**削減。約 **1.13〜1.14%**、関門まで残り **86,937〜93,107** |
| 島 4 の 00/W/S/WS → 変数 W | 大規模 dirty 集合、複数領域、世代検証、待機順と Wire の証明、4 本の比較ビルド | 現行計画の係数なら島 4 の WS は **51,835〜91,980 命令**、約 **1.18〜1.29%**。残り **31,725〜71,870**。島 4 の書き込みだけの総費用は 59,946 |

**本体呼び出しと初期化の費用。** 表は束縛関連の費用を引く前の書き込み箇所の削減見積もり。従来の 16〜32 命令／試行には resume ごとの束縛・検証は含めていなかった。版 1 ではその呼び出しをなくす。事前に選んだ束縛ポインタを渡す追加費用を **1〜3 命令／resume** と仮定すると、CombAt の 56.98 回／サイクルで 57〜171 命令を引き、初期費用の配賦前で **30,426〜36,710 命令／サイクル**となる。引数渡しの命令数は実装後の逆アセンブルで確認する。一度の検証・束縛・破棄の実測命令数を 433,198 で割ってさらに引き、失効の費用と失効後の適用回数も測り直す。束縛回数と resume 時のサービス呼び出し数を別々に計数し、書き込み箇所以外の費用はウォーム実行全体の差でも照合する。

直接読み出しで、読み出しごとのアドレス検証・取得が 4〜8 命令で済めば、別に **4,701〜6,594 命令（0.92〜1.29%）**削減できる。比較・計数に要する 16〜32 命令と同様に、これは仮定である。固定 W と読み出しの費用が重ならない場合で約 **1.14〜1.16%**。動的な部分選択も元の境界・丸め・無効時動作を証明し、固定と同じ単価で判定できた場合、W 単独で **47,212〜55,949 命令（9.27〜10.98%）**、読み出し込みで約 **1.18〜1.21%**。これは初版を越える感度分析である。W の計算では変化時の通知を丸ごと残し、ending の削減益も加えていない。留保・失効時の辞退率、照合費用、命令当たりの時間は実装後に測る。

作業量の違いは最初の判定までの範囲にある。通常の変数 W は比較する実行条件が 2 つ（従来・固定箇所 W）で、解析グラフや待機キューの変更を要しない。島 4 から始める場合は W と S の 2 系統を用意して初めて 4 条件を比較でき、Wire、起床順、世代、影の記憶域をまとめて検証する。どちらの順序でも、関門判定前に島 4 の 4 条件を実測する。工数日数は未計測。

判断順序は、まず通常生成本体の W を独立した対照と比べ、次に読み出しを独立に比較し、同じ W 設定に固定して島 4 の 00/W/S/WS で Wire と S の寄与・相互作用を分離する。結果が関門まで届かなければ島 0 のスケジューリングと NBA へ進む。島をまたぐ起床や同じ変更の費用を二重に足さない。各候補は同じ SIR・キャッシュ準備後に順序を交互にして 5 回以上計時し、1.40% と 4 値 1.05 倍上限を絶対時間で判定する。切替は計測用ビルドに限る。

4 値では固定した P4 入口ビルドに対する 1.05 倍上限も確認する。

1. 通常本体の固定範囲 W を固定し、基準、固定範囲の右辺の直接読み出しだけ、
   書き込み後の終了確認の軽量化だけを比較する。両方を有効にした第 4 条件で
   相互作用を測る。実際の直接読み出し数、終了確認の呼び出し・判定回数、辞退数を記録し、
   各条件で同期的な終了と SIGINT の順序を照合する。
2. 読み出し、終了確認、島などを同条件にし、固定 W と動的な部分選択を加えた W を比較する。

3. 値が変化した書き込みを全幅・部分選択別に採取する。基準の包含費用は 419.6・441.6 命令／回。

4. 通常 W、W に島 4 WS を足した増分、さらに島 0 を足した増分、基準に対する合計、

## 測定条件と再現

133995a745d7、Apple M5 Max、macOS 27.2.1、Apple Clang 21。Release は -O3、生成側は -O2、どちらも FP contraction 無効、生成側は fast-math 無効。433,198 サイクル、終了 0、CRC は e9f5/e714/1fd7/8e3a/e714。以下は [Ibex の再現手順](p4-performance-profile.ja.md)で取得した保存 SIR とファームウェアに対する実行形。実行前後の負荷、入力ハッシュ、3 標本系列、5 対照、コード領域ハッシュは [JSON](../measurements/2026-11-28/ibex-variable-sites.json) にある。

```sh
/usr/bin/time -lp "$K" --tier=native --state=2 --cxx=/usr/bin/c++ \
  --load-sir="$SIR" --cache-dir="$CACHE" --max-scc-iter=65536 \
  +image="$RAM" +cycles=443198
```

診断では使い捨てキャッシュで CombAt 呼び出し時だけ関数表をラップした。write の戻り値で変化を数え、約 1/1,024 の呼び出しで thread_selfcounts の前後差から同じ引数の空呼び出し費用を引いた。乱数種 3 通りで各欄の平均を取り、その中央値を示した。変化時の命令数には同期通知と起床を含むため、以前の排他的な 87,201 と足し合わせない。別の診断で書き込み時の監視条件を検査し、生成された動的選択の各箇所にも通過カウンタを置いた。静的には 5 箇所ある動的書き込みのうち 3 宛先で発行があった。動的要素を参照する読み出しは今回 0 回。生成側は元の最適化済み arm64 命令を基本ブロックの通過回数で重み付けし、共有ヘルパーは CombAt からの呼び出し中だけ数えた。サービス側は Release の分岐のない命令列（読み出し 12、ending 3）を実呼び出し数に掛けた。計装の命令や所要時間を関門の実測に使っていない。
