# 配列の最小・最大メソッド：実行契約の修正案

[English](array-extrema-proposal.md)。2026-10-24提案。**2026-10-25承認**。実装済みの範囲は[実行の記録](runtime-array-methods.ja.md)を参照してください。
以下の提案本文は決定の記録として残し、承認を求める文や未来形は提案当時の記録です。
承認待ちの縮約・並べ替え案、多次元バイナリ入力案とは別の提案です。依存は追加しません。

## レビューが必要な理由

[P1_SCOPE](../spec/P1_SCOPE.ja.md)は、不完全・矛盾する意味規則の実装前レビューを要求します。
承認済みのコンテナ契約はコピー・識別子を定めますが、要素を選ぶメソッドの走査順、
同値の選択、不明な比較、副作用を持つwithの評価は決めていません。
IEEE 1800-2023の7.12・7.12.1を手元で確認し、規格の要約とプロジェクトの選択を
以下で区別します。他のシミュレータのソース・テストは読んでいません。
承認後は規則をVALUE_SEMANTICSへ反映し、SIR_SPEC 5.8と対応メソッド一覧から参照してから
変換を有効にします。

## 提案する規則

- `min()`・`max()`はソースの要素型の上限なしキューを返します。空の入力は空のキュー、
  空でない入力は最小・最大のキーが重複していても**1要素だけ**返します（7.12.1）。
  手元のIcarusが同値の全要素を返す動作は取り込みません。
- withなしでは要素の値、with付きではキーを比較し、返すのはキーでなく元の要素です。
  キー式の型・幅・符号・既存の値演算の意味を保ちます。比較可能な型と構文の検査はslangに従います。
- **走査・同値の選択案：** 残る最初の固定次元を宣言の左端から右端へ、
  動的配列・キューは添字0から進めます。入れ子の配列は1つの要素で、平坦なスカラー候補へ
  分解しません。最初の要素を候補とし、厳密に小さい・大きいキーの
  ときだけ置換します。同値では先の候補を保ちます。7.12.1で走査順は未規定なので、
  これは決定的な動作を選ぶ案で、規格が順序を定めると主張するものではありません。
- **不明・順序を持たない比較の選択案：** 既存の関係比較が確実に真のときだけ候補を
  置換します。X/Zの比較や、NaNを含む実数の偽の比較では候補を保ちます。不明値の
  数値上の全順序を作ったり、共有する演算を変更したりしません。
- **捕捉・評価の選択案：** レシーバを1回評価し、キー評価の前に値をスナップショットします。
  最初の要素も含め、各キーを走査順に1回ずつ評価します。空ならキーを評価しません。
  キーの副作用もこの順序で実行しますが、捕捉したソースの長さ・値は変えず、キーを再評価しません。
  7.12で副作用付きwithの結果は予測不能とされるため、その未確定部分に対する明示的な選択案です。
- 選んだ要素は既存のコピー・上限の規則で独立した値として返します。入れ子のコンテナも
  コピーし、将来のオブジェクトハンドルは確定した代入の意味を保ちます。レシーバを
  暗黙には変更せず、セルを並べ替えたり、既存の参照を無効にしたりしません。
  キー式が明示的に実行した、生きているプログラム状態への副作用は保持します。
- スロット、自動変数、ref、返された値、各実行場所で共通のfront変換を使います。
  既存のsize・read・snapshot・キュー命令と共有の関係演算を使い、VMは型付きオペランドの
  転送に徹します。カーネルの最小・最大APIやSIR命令は追加しません。
- 連想配列・class・固定複合型など、要素の表現が未実装の形は段階的な未対応として
  明示し、P1の到達点からは外しません。定数・parameterの形も固定したslangで確認するまで
  同等の対応を主張しません。定数評価との衝突があれば、実行時と黙って意味を変えずレビューします。

## 独自の観測と承認後の検証

Icarusのコンパイラ・ランタイムはともに`14.0 (devel)
(s20260301-411-gca6b8d376)`です。動的配列とキューの`[4,7,6]`は最小4・最大7を
それぞれ1要素返しますが、`[4,7,4]`の最小と`[4,7,7]`の最大は同値の2要素を返します。
これは7.12.1で確認した1要素の規則と食い違います。空の動的配列・キューは空の結果です。
固定したslangのMIT実装は空でないmin/maxの定数評価で1要素を返す構造ですが、
コードの確認であって、定数の入力を検証し終えた意味ではありません。13.0そのものは未確認です。

独自の`[4,7,6]`に対する`min() with (-item)`は、手元のIcarusで4を返しました。
キーで選ぶ規則では元の要素7を返す必要があり、キーの意味の期待値としては使わず、参照側の
結果不一致として記録します。4値の独自入力でXを先頭・途中に置くと、それぞれX・1を
返しましたが、これだけで不明なキーと副作用の全組み合わせを確定するものではありません。

承認後は独立モデルで、単独・重複・空・1要素、機械語をまたぐ幅と符号、X/Zの位置、
real・shortreal・stringのキー、withの射影と副作用、入れ子のコピー、固定・動的配列・
キュー、レシーバの呼び出し、選んだref、実行場所を検査します。同値をすべて返す、
キーを無視する、キー・ソースを再評価する、符号を失う、結果を共有する誤りもビルドして
検出します。既存の期待値は維持し、Icarusが規格の期待値を通す差分と、参照側の不一致を
比較記録で分けます。
