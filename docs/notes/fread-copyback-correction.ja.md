# 整数への`$fread`：承認済みの書き戻し契約へ戻す訂正

[English](fread-copyback-correction.md)。2026-10-24。既存の承認済み規則へ戻す訂正であり、
代入先を早期捕捉する新たな例外の提案ではありません。

## 契約と誤り

[SIR_SPEC 8](../spec/SIR_SPEC.ja.md)はシステム関数の出力フレームをブロッキング代入として
書き戻します。2026-10-18承認済みの引数規則では、output/inoutの実引数の添字を
書き戻し時に評価し、inoutはコピー入力時にも評価します。これは4.9.7のプロジェクトの
解釈であり、規格がシステム関数の全タイミングを明示すると主張するものではありません。
[SYSTEM_TASKS 6.3](../spec/SYSTEM_TASKS.ja.md)の部分入力では読めなかったビットの旧値を
保つ規則（21.3.4.4）があるため、整数のコピー入力値も必要です。

`db40e27`は整数にstart・countを付ける対応に加え、コピー入力の代入先をそのまま
書き戻し先に固定してしまいました。この変更は未承認で、SIR_SPEC 8と衝突します。
追加した機構9ケースの期待値も誤った規則を使っており、通過しても契約適合の根拠には
なりません。7種類のmutationの検証記録も訂正が必要です。書き戻しで対象を再評価することや、
置換後の代入先を選ぶことは、承認済み規則では意味の誤りに分類できません。

任意引数の評価は維持し、以下へ戻します。

1. コピー入力のため、整数の実引数を評価して読みます。
2. fd・指定したstart/countを左から1回評価します。整数への読み取りはその値で制限しません。
3. フレームへ読み、未入力ビットはコピー入力の旧値を保ちます。
4. 読めたバイト数が正なら、対象を再評価して書き戻します。0バイトなら出力を書いておらず、
   書き戻しをしません。

`$fgets`・scan・plusargsは変更しません。出力のみの実引数は実際の書き戻し時に対象を
求めるため、EOFなど代入がない場合は添字を評価しない動作になります。スカラー、packed部分、
連結、固定配列、自動変数、ref、動的要素の各格納先で同じ規則を使います。実際のrefは
既存の参照規則を保ち、キュー要素を直接書いた式は書き戻し時の変数の現在値から選びます。

## 独立した根拠と期待値の訂正

自動taskのinoutへ`change(a[i++])`を渡す独自入力は、手元のIcarus・kirimasimとも
iを2回増やし、2番目の要素へ書き戻します。`$sscanf("1 7","%d %d",i,a[i])`も、
両方でi=1にした後に`a[1]`へ書きます。Icarusは今回の機構ケースで使う選択された整数を
`$fread`・`$fgets`のVPI代入先として拒否するため、直接の比較は未確認です。
コンパイラ・ランタイムはともに`14.0 (devel) (s20260301-411-gca6b8d376)`です。
Icarus・Verilatorのソース・テストは読んでいません。

幅・状態・実行場所の144組の期待値は維持し、位相に依存する9ケースの誤った期待値を
訂正します。ジェネレータの版を2へ上げ、既存のケースと厳格な位置付き警告は保持します。
新たに、書き戻しで選び直した有効なヒープ要素への代入と、部分入力より前の引数の副作用を
またいでコピー入力値を保つ検査も追加します。アサーションは弱めません。

ネイティブ実装の修正前は、訂正した機構9ケースがすべてstdoutの差で失敗し、144組と
ジェネレータ検査は通過しました。訂正後の期待値が誤実装を検出することを確認しています。

## レビューの分離

CLAUDE.md（「期待値を変える変更は別の PR にする」）は既存の期待値の訂正とsrcを別PRにする一方、
新しいテストは実装と同じPRでよいと定めます。AGENTS.mdはリポジトリに含まれません。公開基準の`origin/main`（`aae29de`）にはscalar-fread行列のファイルは0件で、
ローカルの459ファイル・153ケースはすべて新規追加でした。そのため、今回の未公開機能では
公開済みの期待値を変更せず、新規テストを訂正した実装と同じPRへ含められます。
公開基準からの全差分も`check_expected_change.py`を通過します。

レビュー用には、以下のブランチで訂正コミットを分けています。

- `codex/fread-copyback-expectations`：ジェネレータ・スイートの訂正・この理由だけを含み、srcは変更しません。
  固定したbase `70c7fb3`との差分をレビューします。
- `codex/fread-copyback-implementation`：上の期待値ブランチをベースにします。実装PRも
  このブランチに対して実装修正をレビューすれば、既存スイートの本体・期待値を
  実装だけの差分へ混ぜずに確認できます。

PRのbaseにすでにこの行列が存在する場合は、訂正をsrcのPRから分けます。元の公開基準から
見る場合は新規テストの例外が適用されます。4.9.7と承認済みSIR_SPEC 8に照らして期待値を
確認し、実装をその検査へ通します。既存の承認済み規則を戻すための新たな意味の承認は不要で、
レビュー用ブランチを作ったことが、検証済み変更のローカルmainへの統合を妨げるものではありません。
