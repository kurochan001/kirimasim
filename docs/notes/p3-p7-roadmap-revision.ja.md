## P3 の速度目標と計測条件

速度比は「参照シミュレータの実行時間 ÷ kirimasim の実行時間」（大きいほど kirimasim が速い）に統一します。

- **完了条件①：** Ibex/CoreMark の 4 値 native で、Icarus Verilog（`vvp` 実行時間）の **3.0 倍以上**。
- **完了条件②：** Ibex/CoreMark の 2 値 native で、シングルスレッド Verilator の **1%（0.01 倍）以上**（実行時間が Verilator の 100 倍以内）。
- **CVA6 合成向け構成：** 継続測定し、2 値で Verilator 比 **0.2%** を次の改善目標とする（P3 の合否判定は Ibex の上記 2 件で行う）。
- **P3 の計測条件**。同一ホスト・同一 RTL・テストベンチ・ファームウェア・反復数で CRC と最終サイクル数を照合し、コンパイルとキャッシュの準備後に処理系ごとに最低 5 回実行して中央値を比べた。処理系の版・コミット・コンパイラ・実効オプションを記録した。

0.3.0 で P3 の両目標を達成しました。[完了時の実測](../BENCHMARKS.ja.md#p3-performance-targets)と[公開時の検証](../VALIDATION.ja.md)に結果を記録しています。

## 新 P4 の範囲と受入テスト

SIR v1、カーネル ABI、P3 の静的アイランド、`--tier-check` を出発点とする。3 つの柱を通常の実行経路で動かし、以下の 8 件の受入テストを揃える。全 SIR 命令の AOT 化と UVM 全体は後続段階の作業とする。

1. **待機をまたぐ VM・native 間の呼び出し：**
   - **1a（基本の中断・再開と NBA）：** `automatic` タスクがローカル値を保持したまま `#delay` またはイベント待ちで中断し、再開後に NBA を発行する例（生成 C++ 呼び出し元から VM 側の待機タスクを呼ぶ経路を最低 1 件含む）。VM 参照実行と再開時刻・保持値・復帰時点・NBA の順序と結果を照合し、意図した native 経路が実際に動いたことを確認する。
   - **1b（`fork` による多重同時待機）：** 同一の `automatic` タスクを 2 系統で同時に異なるローカル値で中断し、別順で再開してコールフレームの独立性を確認する。
   - **1c（待機中の `disable` / `disable fork`）：** 生成 C++ 呼び出し元を含む待機チェーンを途中で強制破棄し、フレーム巻き戻し・待機解除・リークなしを確認する。
2. **中間信号を観測する組み合わせ回路：**
   - **2a（静的観測者のあり／なし）：** 同一の組み合わせ回路で中間信号に観測者がある場合とない場合を用意し、観測ありでは 4 値遷移とイベント順を VM 参照実行と照合、観測なしでは適格区間のまとめ評価を確認する。将来の SVA・VPI からも利用できるよう、観測対象・タイミングと同値性を証明できないときに従来経路を選ぶ条件を明記する。
   - **2b（実行時の `force`/`release` または既存 VPI 介入）：** 候補区間の中間信号に実行時の `force`/`release` または既存 VPI 読み書きが入った際、安全に従来経路へフォールバックし VM 参照実行と一致することを確認する。

3. **静的アイランドの融合評価と直接の読み書き**
   - **3a** は非巡回区間を実際に融合し、途中の外部入力、ファンアウト、無変化、X/Z、時刻 0 で VM と評価・書き込みの列を照合する。
   - **3b** は同期観測、実行時の観測者の追加と終了要求で、既に公開した効果を重ねずに従来経路へ移ることを確認する。
   - **3c** は同じスライスや外部プロセスの NBA を含む連続発行区間を照合し、発行順・反映順・観測位置を確認する。

全ケースで既存カウンタと `--tier-check` を照合する。強連結成分、
独立した Context、生成キャッシュの再利用も検査する。

柱 1 では通常の `initial` / `always` の時間待ちループと単純イベント待ち
で、生成 C++ の再開を各 1 件以上確認し、対象プロセスの VM 命令の減少を
示す。固定入力の `proc_wait` と `comb_chain` で再開、SIR 命令数、実行時間を
報告し、`fork_join` と `func_call` も対照として測る。未対応のフレーム、
待ち、呼び出しは従来経路を選ぶ。

P4 の速度関門は Ibex/CoreMark の 2 値 native が同一ホストで単一スレッド
Verilator 5.054（P3 と同じオプション）の **1.40% 以上**、かつ 4 値 native の時間が固定した P4 開始時の
ビルドの **1.05 倍以内**とする。CVA6 合成ビューの **0.30%** と、固定 25 回路の
native/VM 幾何平均が低負荷で採った基準の **1.05 倍**に達するかは参考値として追う。

## P5〜P7 の範囲と性能管理

P5 は最小 UVM、DPI-C、制約付きランダム化、並行 SVA、カバレッジ、残り VPI
の順で完了条件を設定する。各項目の正しさ、各機能の有効・無効時の時間、
トランザクション当たり時間または対応したスループットを記録し、P5 の完了時に
145 項目を規格と照合する。実 RTL を止める SVA の小範囲は先行候補とする。

RTL 性能は P4 から継続改善し、P5 のサンプリング、カバレッジ、VPI、DPI-C は
P4 で定めた観測とコミットの境界を使う。P5 前に限定した VM バイトコード実験を
行い、移行の判断は P5 のプロファイル取得後に行う。P6 は並列実行のスケーリング、
P7 は実用 UVM・テストベンチの高速化と総合調整を中心にする。旧 RTL 目標
（4 値で Icarus 比 10 倍、2 値で Verilator 比 0.5〜1 倍）と UVM 目標
（CIRCT ベース参照比 100 倍以上）は長期候補として扱う。
