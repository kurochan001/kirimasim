# P1 のフロントエンドのエラボレーション上限

[English](elaboration-limits-execution.md) · 2026-11-03。

承認済みの CLI 2.1・UNSPECIFIED_BEHAVIOR A11〜A12 の4種を、従来の引数ファイル経由に加え、
固定版 slang へ直接渡せます。`--max-hierarchy-depth=<n>`、`--max-generate-steps=<n>`、
`--max-constexpr-depth=<n>`、`--max-constexpr-steps=<n>` です。
言語の仕組みは階層・generate のエラボレーション（IEEE 1800 の27章）と定数関数（13.4.3）に
対応しますが、数値の上限はフロントエンドの方針で、IEEE が定める値ではありません。

## 共通の転送の境界

`parseArgs` の1分岐で、仕様にある `=<n>` の4形式を認識し、引数全体をそのまま渡します。
既存の `front::setUpDriver` が、実行・`parse`・`--dump-sir` の共通の slang driver へ渡します。
実行時の上限・scheduler・SIR 命令・ABI・依存は変えません。既定の引数も追加しません。
slang は未改変の固定版 `e2d1021661f78b3f17d1edf7ea17f9d6f95fb168` のままで、既定値は
階層の深さ128、generate の手順数131072、定数関数の呼出しの深さ128、定数評価の手順数1000000です。
`--help` に4種を追加しました。単独・空白区切りの新しい別名は設けません。

数値の構文・範囲・重複・ソース診断は slang に任せます。拒否されたコンパイルは、設計の
stdout や SIR を出さず、シミュレーション前に終了2になります。実行中の `--max-steps`・
`--max-call-depth`・時刻・資源の上限とは独立しています。特に0はそのまま0として渡し、
**無制限にする別名ではありません**。通常の厳格な受理と、既存テストの期待値は保ちます。

## 独自の仕組みの行列と変異

`tools/gen_elaboration_limit_matrix.py` が独自ソース21件を生成します。各上限4件の有限入力
16件、明示した上限で止まる無限処理4件、正常な小入力1件です。階層は通常・generate・instance 配列・
interface の入れ子、generate は module・interface・program・入れ子の generate を検査します。
定数関数は module/package/interface の宣言と、generate 内の定数からの呼出しを扱います。
再帰する階層は、同一インスタンスの循環を先に検出されるだけにならないよう、異なるパラメータの特殊化を使います。

`cli/elaboration_limits` は**871項目**が成功しました。既定・高い値・低い値、ソースの前後、
3モード、直接/引数ファイル、0、数値の境界、不正・不足した値、重複、独立した同時指定、
無限処理の打切り、help を検査します。失敗側では終了2・stdout なし・該当する理由とソース位置を
要求し、クラッシュ・ハング・内部エラーは失敗です。`tools/gen_elaboration_limit_matrix` は再生成を検査します。
既存 CLI・ソースの警告・新規テストを合わせても成功しました。

各上限を大きい値に置き換える4件と、実行時だけ転送しない1件をコンパイルし、5件とも意味の不一致
（コンパイル拒否を期待した入力が実行成功してしまう）で検出しました。ビルド失敗や時間切れは検出数に加えません。
ソース hash と CTest の正常系4件を復元済みです。変異カタログ**全1,141件**の anchor が適用できます。
[変異の記録](../measurements/2026-11-03/elaboration-limit-controls.json)と
[検証記録](../measurements/2026-11-03/elaboration-limits-validation.json)を参照してください。

## 固定版フロントエンドで観測した境界

以下はフロントエンドの動作を保つ観測であり、受理を緩めたり、未対応の設計を成功扱いにしたりするものではありません。

- 直接の同一オプションの重複指定は入力エラーです。検査した平坦な引数ファイル内では最初の指定を保ちます。
  kirimasim 側で優先規則の補正を加えません。
- `--max-hierarchy-depth=4294967295` は数値としては受理しますが、記録した浅い階層でも拒否します。
  直接/引数ファイルの両方で終了2の診断を保ちます。固定版は符号なしの階層の許容値に1を加えるため、
  この値で overflow します。これは上流側の境界であり、**階層の実行成功ではありません**。
  実用的な有限値を使ってください。依存の修正・版の更新・上流への投稿は行っていません。
- ほかの uint32 最大値の検査も、あらゆる workload の動作を証明するものではありません。
  全面的な互換性と P1 の機能範囲の完了は未確認です。

既存期待値の移行は不要です。固定母集団、任意の `wire real` の分類、Icarus/sv-tests の比較結果、
nightly fuzz の記録は変えません。P1 は進行中です。dev 全体と最終 local CI の結果は、完了後に検証記録へ追加します。
