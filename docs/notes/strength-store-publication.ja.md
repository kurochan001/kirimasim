# 完全なネット強さの一括公開と記憶域サイズの計算

[English](strength-store-publication.md)が正。状態：カーネルの実装・検証済み、2026-10-26。
ソースのMOS/スイッチ実行は残作業です。

## 根拠と範囲

承認済みの[MOS/スイッチ契約](mos-switch-proposal.ja.md)1/6/7と
[正式仕様への対応](p1-execution-contracts-2026-10-25.ja.md)、VALUE_SEMANTICS 5、
SCHEDULER_SPEC 9/12、SIR_SPEC 3.2/4.1、RUNTIME_ABI 4/5が根拠です。
実装・テスト・小規模測定のソースは独自で、他のシミュレータの実装・テストは読んでいません。
依存・外部C ABI・formatの版・性能予算・管理eventの回収時点は変えていません。

`49bd3069`で各Contextに`StrengthStorage`を追加し、実際のSchedulerとStoreへ接続しました。
`enableStrengths`は全ビット・配列要素の公開区間をコピーし、現在のStore値と射影が一致することを
要求します。登録時はnetの解決・書き込み・予約・process生成・通知をせず、実際の解決まで初期Xを保ちます。
公開されたnet状態を持つAPIであり、通常の物理originやside maskの取り込みは実装していません。
`read`と`readPacked`はslot/要素/bitの数値IDで完全な区間を読み、
[強さのSSA](strength-ssa-execution.ja.md)と同じpacked表現も使えます。

`publishStrengths`は、計算済みのコンポーネント全体の結果を受け取ります。

- 対象の域・範囲・入力サイズ・端点を確認し、全入力と対象情報をコピーします。
  slot/要素/bit順に並べて重複範囲を拒否し、要素ごとの変更前/後の値を用意します。
- 通常通知とその所有するバッファも、公開値を変える前に確保します。
  全区間と全射影値を更新してから、初めてcallbackを呼びます。
- 区間変更の内部通知を分けます。強さだけの変更は素子へ伝えられ、通常の値event・
  値変更カウンタ・VCD遷移にはしません。通常通知の辺と値の規則は保ちます。
- 外側の通知走査中に公開する場合も、別々に確定した遷移を残します。
  遅れて送る通常通知は値を所有し、終了済みの公開処理の一時バッファを借りません。

callbackはコンポーネント全体が整った状態を見ます。内部callbackは後の依存処理を予約し、
同期的な再公開には`Reentrant`を返します。callback中の登録・解除・表の拡張に対応し、
開始時の通し番号より新しい購読や再利用した行は、進行中の公開では呼びません。
解除した行は64bit世代番号を更新して再利用し、上限では巡回せず退役します。
通知中に停止した場合は、完全な公開結果を保ったまま後続callbackを止めます。

資源不足の結果には、全体を公開済みかどうかを含めます。準備中の失敗なら公開値は全て不変です。
callbackの確保失敗では、全体の公開後に停止する場合があり、その公開を再試行してはいけません。
失敗時は通知走査の状態を戻して未配信通知を破棄し、部分的な公開を成功として返しません。

カーネルのインターフェースはSIR・slang・LLVMから独立したC++20です。
登録slotへの通常のScheduler書き込みを拒否し、既存のholdがあるslotの登録も拒否します。
登録済みslotを従来のhold対象にすることも失敗します。force/releaseの接続は未実装です。
登録slotを`Store::element`経由で直接書くことは認めず、今後のSIR loader/verifierでも
指定publisherの所有を守る必要があります。現在ソース経路からは登録せず、既存forceは従来経路です。

## レビューで見つかった幅の切り上げ

従来の`(width + 63) / 64`と`(width + 7) / 8`は、32bit幅の加算が先に巡回する可能性がありました。
`UINT32_MAX`では、ワード数67,108,864、byte数536,870,912が必要なのに0となり、
検証器がワードの欠けた巨大幅の整数定数を受理する場合もありました。

`99dafab4`でkernel・VM・front・verifier・書式・メモリファイル・参照変換を同じ仕組みとして修正しました。
kernelの`wordsFor`/`bytesFor`、独立したSIRの`integralWords`/`integralBytes`へまとめ、
`wide::chunks`もkernelの共通計算を使います。SIRへkernel依存は追加しません。
参照側は独立した剰余/広い整数の計算です。もともと64bitへ昇格していたactivation/patternの計算は保ち、
別の32bitワードの書式処理も、今回の64bit対象では`size_t`への昇格で保護されています。

新規3テストは、kernel/wide/SIRのワード境界10件、kernel/SIRのbyte境界12件、
64bit演算による必要十分な容量、両状態域・両符号の不正な定数8設計を検査します。
巨大な配列は確保しておらず、数十億bitの設計の実行成功や、新しい実用上限を保証するものではありません。

## 検証

公開の独自16テストは、全120区間を各bit/配列要素に置く6幅の88,200検査、初期packed配置、
slot/購読表の拡張中のcallback整合性、解除/再利用、全16論理遷移と4辺種別、glitch有無のVCD、
不正/重複batch、停止、Contextの独立性を確認します。登録と公開準備には各32箇所の確保失敗を試し、
公開後のcallback失敗も検査します。購読行の再利用は512回です。幅計算の3件を合わせ新規19テストです。

[コンパイルした16故障](../measurements/2026-10-26/strength-store-controls.json)を検出しました。
公開10件、危険な切り上げ4件、共通関数への移動後も保った既存wide force/既定値2件です。
C++20のprobeを含む全体ビルドは全件成功し、その後の実際のテストで失敗します。
コンパイル失敗は検出に数えません。元と復元後は376件が通り、既存dump29件とwide/forceソース328件を含みます。
登録済み691故障すべてが適用でき、別の広い対象確認141件も通ります。

[最終local CI](../measurements/2026-10-26/strength-store-validation.json)は全21確認成功で、
dev/ASan/UBSanは5,171/5,173、releaseは5,172/5,174、各失敗0・既知スキップ2件です。
PerfCount・既存dump・静的検査・生成件数も通ります。実装2コミットの期待値変更検査も成功し、
既存の期待値は変えていません。幅境界の追加検証より前の、`49bd3069`の全CI成功も残しています。
旧計算が追加検証に失敗することは、コンパイルした故障で確認しました。
有限のCIが通るだけで、全機能や全境界を保証するものではありません。

[小規模なコスト測定](../measurements/2026-10-26/strength-store-speed.json)は、保存したreleaseの
`0ec3cc57`と`99dafab4`を、同じmacOS arm64で交互5組・各200,000反復で比較しました。
起動時間を推定して除いたframeアクセスは0.260349→0.258658秒（−0.6%）、
名前付きeventの往復は0.047821→0.046906秒（−1.9%）です。全カウンタが一致し、
両実装/両負荷のpeak RSS中央値は9.203125 MiBです。この小標本では追加の悪化は見えませんが、
改善の断定や時間による合否判定はしません。afterには両方の修正を含み、どちらの負荷も強さメタデータを登録しません。
公開処理/ソースMOSのコストは未測定です。baselineに含まれる従来の名前付きeventコストを解消した証拠でもありません。
性能の閾値・予算は変えていません。
