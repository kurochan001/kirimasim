# class の実行：カーネルの実装段階

[English](class-runtime-kernel.md) · 英語版が正です。

[承認済みの class の契約](class-runtime-proposal.ja.md)の 1、3〜6、8〜10 節について、
カーネルの部分を実装しました。**ソースの class の実行はまだ有効にしていません。**
オブジェクトの構築はフロントエンドで未対応のままで、Icarus との同等性を達成したという意味ではありません。

## 表現と寿命

`Heap::addClasses` が class の記述をまとめて検証してから登録します。
再帰的なフィールド型、基底・interface との互換性、フィールドの宣言元、全体で共通の仮想スロット番号を保持します。
番号が継承順でなくてもよく、interface の菱形や深い継承は反復で辿ります。
循環、不適合な宣言、不正なレイアウトがある場合は公開しません。

オブジェクトは既存のコンテナと同じ型付きヒープを使い、プロパティは安定したセルに置きます。
型付きの辺だけを参照として辿り、整数のビット列から推測しません。
ハンドルのコピーは同じオブジェクトを参照します。浅いコピーでは、値として持つコンテナを複製し、
オブジェクトへの参照と const の初期化状態、乱数状態を引き継ぎます。
新しい識別子と class ごとの作成番号を与えますが、コンストラクタは実行せず、親の乱数も消費しません。

トークンは世代と所有ヒープを持ち、別の生存 Context の値や再利用前の値を拒みます。
所有元は C++ の境界での検証用で、識別子やメソッド選択には使いません。
automatic の格納域には Context 内のトークンの数値だけを入れ、登録済みの class の型で書き込みと参照の列挙を検証します。
ネイティブのアドレスをソースの値にはしません。

移動だけができる pin が、公開前の値や実行時の処理を保護します。
プロパティのセルを保持すると所有オブジェクト全体が生存し、オブジェクトとコンテナを跨ぐ循環や文字列も辿ります。
監視情報自体は強い参照にしません。マークに失敗した場合は回収しません。
弱参照からの取得は次の安全点より前に pin し、死んだ参照先への弱い辺は格納域を再利用する前にすべて消します。
論理識別子は格納域の番号と別で、再利用しません。

## 構築とプロパティ

公開前に、すべてのフィールドに型ごとの安全な既定値を入れます。
カーネルが管理する、複製できない構築権限により、基底から順に宣言初期化と本体を実行する段階を区別します。
必要な初期化を検証し、const フィールドへの代入を一度に制限します。
構築を途中で終えた場合も、外へ渡されたオブジェクトや実行済みの副作用を取り消しませんが、その段階を再開させません。

プロパティの参照は、選択時のオブジェクトと宣言元を保持します。
ただし参照自体は寿命を所有せず、安全点を跨ぐ呼び出し側は pin か型付きルートを持つ必要があります。
`ObjectRef` をコピーしただけでは寿命は延びません。
語とビットの選択は親の境界を越えず、選択しない値を変えません。型付きハンドルのビット選択は拒みます。
書き込みを正規化してから変更を通知します。
キャストは代入可能な静的型、動的な派生・interface 型、型付き null、リテラル null を区別し、失敗時には書き込みません。

## 検証と残り

新規のカーネルテストは20件です。1・32・65・129・257 bit、二値・四値、
独立した `valsem` モデルとのコピー・参照グラフの照合、既定値、仮想呼び出し、キャスト、構築権限、
弱参照、Context 間の分離、古いトークン、割り当て失敗、乱数消費、繰り返す回収、automatic フレームの保持を扱います。
これらの規則を壊す17件の変異を追加しました。
専用の実行ファイルは kernel、valsem、GoogleTest だけにリンクし、公開ヘッダは C++20 でも検証します。

SIR の記述・命令と検証器、slang の型の収集、構築とメソッドの変換、VM の操作とルートの接続が残っています。
event フィールド、ソースの監視・ref・NBA の寿命、キャスト、書式、ソースの配置を跨ぐ行列も、その後の作業です。
既存の拒否テストと期待値は変えていません。この段階で class の契約や P1 の要件が完了したとは扱いません。
