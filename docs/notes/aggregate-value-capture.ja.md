# 集約代入で右辺の値を先に保持する

[English](aggregate-value-capture.md)。実装`917c715`、2026-10-24。
承認済みVALUE_SEMANTICS 3.1・3.13とSIR_SPEC 7.3の規則へ戻す修正です。
IEEE 1800-2023 10.4.1・10.4.2は左右の相対的な評価順を未規定とし、
kirimasimは右辺を先に、代入先の添字を後に評価する方針を承認済みです。

## 修正した動作

独自の構造体配列の入力では、右辺の関数が記録へ1を足して添字を1にし、
代入先の関数が2を足して添字を増やします。`a[choose()] = source_value()`と
その遅延付きNBAは、従来は`21`、添字1となり、`a[0]`へ書いていました。
修正後は`12`、添字2となり、`a[1]`へ書きます。

集約値の右辺の全leafを、代入先の実行時の添字より先に保持します。
コンテナのleafは直ちに独立した値を捕捉し、後のパターンのメンバーや代入先の関数が
元の値を変えても、保持した値は変わりません。遅延付きNBAは既存のスカラーと同じ
右辺・遅延1回・代入先の順を保ちます。NBAはNBA/Re-NBAで更新し、ブロッキング代入は
値の保持と代入先の選択の後にすぐ書きます。不正な選択でも式の副作用は保ち、
有効な隣の要素を変えません。

固定された代入先の配置は実行時の選択がなく、保留中の格納先をそのまま使います。
実行時に選ぶ場合は、私有の型付き配置で右辺を評価し、その格納先を捨て、
保持したSSAの値を実際の格納先へ渡します。SIR命令、kernel・VMの方針、C ABI、依存、
インストールの追加はありません。既存のSIR出力の期待値も変えていません。

実行時に選ぶ固定の部分配列全体と、構造体要素の配列メンバーにも同じ走査を使います。
自動・static functionの隠れた戻り値にも、固定配列のメンバーを持つunpacked構造体を
保持できます。明示的なautomaticの配列メンバー付き構造体、構造体配列の引数、
構造体refには既存の未対応の形が残ります。この版で未対応だった集約値全体への
ブロッキング代入内時間制御は、[後続の実装](blocking-aggregate-timing.ja.md)で対応しました。
イベント制御付きNBAは引き続き残作業です。

## ソースでの検証

[独自のジェネレータ](../../tools/gen_aggregate_nba_capture_matrix.py)でソース72件を追加しました。
64件は実行場所8種類、1・32・65・129ビット、2値・4値を横断し、通常代入、NBA、
ゼロ遅延・副作用のある遅延、不正な対象、右辺と対象の順序、値の保持、領域を検査します。
実数・文字列のメンバーも含みます。追加8件は配列メンバー、異なる宣言境界、
実行時の部分配列、構造体配列、キューのleafと入力パターン、元の値の変更、
自動・static functionの戻り値を確認します。

保持した旧バイナリ（`87ae3a27b904`と表示）では、64件が標準出力の差で失敗し、
8件が未対応で止まります。修正後は72件とジェネレータ検査が通過します。
既存のスイート本体・期待値・性能の回数は変えず、SIR出力の既存29件も通過しました。

`917c715`のローカルCIはdev・release・ASan・UBSanと全静的検査を通過しました。
clang-format・clang-tidy・期待値保護・README件数も含みます。dev・ASan・UBSanは
各2,980件中2,978件成功、既知の2件がスキップです。releaseは2,981件中2,979件成功で、
同じ2件がスキップです。ユニット298件・スイート2,493件・道具130件・ジェネレータ125個です。

集約値に関する9種類のmutationはすべてビルドでき、アンカー・判定ツール自身の検査を
除いた全体で検出しました。新規6件は、早い対象選択、4経路でコンテナを借用する誤り、
遅延の再評価で、すべて新しいソースの標準出力の差で失敗します。更新した遅延を落とす
検査と、既存の番地違いのコピーの検査も、新しいソースで失敗しました。
既存の等価比較の検査は従来のテストで検出し、復元後も再ビルドしました。
実行した9件と、全489件のアンカーの適用検査は区別します。

## 比較の範囲

独自の比較を3本追加し、有限の一覧を72本から75本へ広げました。
右辺順序の2本は`project_policy`と明記し、承認済みのkirimasimの順序を期待値にします。
実行時の部分配列の1本は規格の仕組みです。手元のIcarus 13.0・14.0 develは
3本ともコンパイルできず、kirimasimは通過します。Icarusだけが通る差分は減らしていません。
[版ごとの比較記録](icarus-13-comparison.ja.md)で13.0と開発版を分けます。
全面的な同等性は未確認です。

```sh
ctest --preset dev -R 'aggregate_nba_capture|dump_sir' --output-on-failure
python3 tools/gen_aggregate_nba_capture_matrix.py --check
python3 tools/mutants.py --only aggregate
```

mutationの実行は`src/`がクリーンであることを要求し、変更したファイルは復元します。
