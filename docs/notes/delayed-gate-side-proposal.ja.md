# 遅延付き三状態ゲートの強さ情報の伝播案

[English](delayed-gate-side-proposal.md)。**提案中・未承認・未有効化**です。
2026-10-24に作成しました。英語版が正本で、新たな依存・インストールは選びません。

## レビューが必要な理由

VALUE_SEMANTICS 5.8はL/Hを片側の強さを抑えたX、SIR_SPEC 3.5は初期状態が
未駆動の非公開2値sideフィールドとして定義しています。SCHEDULER_SPEC 12には
X/L/Hへの最小遅延と、値が変わるときの慣性遅延の取消しがあります。一方、4値の投影が
XのままLからHへ変わる場合に、伝播を予約するか、sideだけ直ちに変えるかは明記されて
いません。IEEE 1800-2023 28.16の表28-9にもL/H同士の別の行はありません。
この不足は、別ドライバと解決した値に観測可能な違いを生じます。

[P1_SCOPE](../spec/P1_SCOPE.ja.md)は不足する詳細な意味を実装前にレビューするよう求めています。遅延sideの
実験経路は、承認待ちとして作業実装から取り除きました。別の広いマスクの受け渡し修正は、
定義済みの遅延なし5.8の実装なので独立して進めます。MOS・スイッチの強さの伝播、
P1全範囲の対応は引き続き残作業です。

## 修正案

SCHEDULER_SPEC 12とVALUE_SEMANTICS 5.8に、次を追加します。

1. 三状態出力の慣性状態は値と両sideフィールドの組です。4値投影がXのままでも、
   sideが違えば新しい出力状態とします。新たなL/H状態には既存の立ち上がり・立ち下がり・
   ターンオフの最小遅延を選び、0なら既存規則どおりInactiveで確定します。それまでは
   古い出力状態全体を保持します。
2. ゲート評価時に全フィールドを捕捉します。保留状態と違えば取消し、現在の確定状態と
   同じなら新規予約しません。保留状態と同じ再評価なら元の期限を保ち、それ以外は
   全体を1回で伝播します。短いsideのみのパルス、X/Z制御による変更にも適用します。
3. 初期sideはSIR_SPEC 3.5どおり未駆動のまま、対応する全体の伝播時に確定します。
   rawのドライバスロットが既にXでも、新しいsideを先に公開しません。
4. rawの値と全sideを更新してから変更コールバックを呼び、解決プロセスを起こします。
   更新がフィールドをコピー所有し、後のソース変更・取消し・コールバックからの
   ドライバ追加で借用値やポインタが壊れないようにします。利用者の信号の通常の
   イベント待機は、5.6どおり解決済み4値が変わるときだけ起こします。

これはレビュー対象のプロジェクトの解釈です。Icarusで観測したsideのみの時刻を、
IEEE違反と断定しません。通常の値遷移の時刻と、遅延なしのL/H解決規則は変更しません。

SIR_SPEC 5.4には、次の機械的な表現を追加します。

- 既存の`drive.delay target, value, rise, fall, off`を保ち、末尾に任意の
  `(sideビットの対象, 値)`の組を付けます。組全体が1つの保留伝播に属し、
  独立した遅延命令にはしません。
- 対象はスカラーの2値スロットの1ビットで、値の型が一致し、write集合に含まれ、
  主対象と分離されている必要があります。重複や不完全な組は不正です。
  オペランドは登録より前に定義し、SSA値を借用せずコピーします。
- ゲート入力の短絡式からの関数呼び出しもあるため、side計算の実際の制御フローブロックを
  保ち、その後へ遅延命令を置いて支配関係を維持します。

完全な状態の比較、1つの保留世代、捕捉値、同時の公開は共有カーネルが所有し、VMは
型付きオペランドの受け渡しだけを行います。C++20のAPIは既存値に加えて1ビットのside
更新のspanをコピー所有できます。sideはヒープ参照を持たず、GCルートの新しい種類は
不要です。全フィールドを書き終えるまで走査の外へコールバックを出さず、レコードの
再確保より前に対象情報をコピーします。この内部拡張ではC ABI 0.3の変更は提案しません。
全実行層が同じ経路を使う必要があります。

## 独自の観測と受入に必要な証拠

[元のソースと版付き観測](../measurements/2026-10-24/delayed-gate-side-design-probes.json)に、
既存の13.0 stable・14.0開発版のコンパイラ/runtimeと、未コミットの実験を明示して
記録しました。他シミュレータのソース・テストは読んでいません。観測は承認済み期待値では
ありません。

弱い1を併駆動するsideのみのプローブでは、案は`first 1`・`L x`・`H_pending x`・
`H 1`となります。Icarusの両版は`first x`・`L x`・`H_pending 1`・`H 1`です。
十分待った0からHへの別のプローブは、3実行とも`0, 0, 1`です。この通常遷移の一致だけで、
投影が変わらない場合の不足は解消しません。

受入にはbufif/notifの4種、遅延1/2/3個と0、L/H/X/Z、現在/保留との一致と取消し、
同じ再評価で期限が延びないこと、値とマスクの同時変更、所有権、コールバックの再入と
レコード再確保、広く非整列なsideの両半分、短絡する制御フロー、不正SIR・write集合外の
書き込みを検証します。独立したカーネル/SIR検査、独自ソース、方針の不一致を明示する
参照比較、コンパイル済みの誤実装対照を使い、既存期待値を保ち、全ローカルCIを実行します。
この機構が通ってもMOS・スイッチ全体やP1の完了とは扱いません。
