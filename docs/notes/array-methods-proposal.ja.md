# 実行時の配列の縮約・並べ替えの仕様修正案

[English](array-methods-proposal.md)。状態：**承認済み（2026-10-25）**。実装済みの範囲は[実行の記録](runtime-array-methods.ja.md)を参照。
以下の提案本文は決定の記録として残し、承認を求める文や未来形は提案当時の記録です。

## 目的と承認が必要な理由

P1_SCOPEはIcarusが対応する機構を必要とし、比較で`dynamic_array_sum`と`queue_sort`の
差分を確認しました。ただし範囲の承認だけでは、欠けている意味は決まりません。
P1_SCOPEには「Detailed semantic amendments must be reviewed before implementation
where specifications are incomplete or conflicting.」とあります。

手元で7.12・7.12.2・7.12.3・13.5.2を確認しました。以下は自分の言葉による要約と、
明記したプロジェクトの選択です。Icarus・Verilatorのソースやテストは読んでいません。

## 値の規則の提案

- `sum`・`product`・`and`・`or`・`xor`は、unpacked配列をcardinality順に縮約します。
  非空なら最初の値を累積値にし、1要素のX/Zをそのまま保ちます。2要素目以降は既存の
  VALUE_SEMANTICSの算術・ビット演算を使います。`with`があれば、その値・型・幅・符号に従います。
- **空入力のプロジェクトの選択：** sum・or・xorは0、productは数値の1、andは結果幅の
  全ビット1を返します。空ならwith式を評価しません。非空の先頭に初期値を追加する規則ではありません。
- 確認した縮約の節には空の結果が明記されていないため、この選択は承認が必要です。
  独自入力で測ったIcarusのコンパイラ・ランタイムは、ともに
  `14.0 (devel) (s20260301-411-gca6b8d376)`です。空のint/logicのsumは0、productは1でした。
  and・or・xorのメソッド表記はそのコンパイラが拒否したため、空の結果は未確認です。
  固定版slangの定数評価は、productを含む空の縮約をすべて0にします。
  承認後は、既存の定数評価の例外方針に差と検査を記載し、実行時と黙って食い違わせません。
  この方針でまだ変換できないパラメータの形は制限として明記します。

## 並べ替えと参照の規則の提案

- 固定配列・動的配列・キューのreverse・sort・rsortを実装します。
  比較には通常の式と同じ`<`・`>`を使い、数値・文字列の意味を共有します。
- **プロジェクトの選択：** 同値のキーは安定な順序を保ち、比較結果がXなら、その比較対象を
  越えて移動しません。X/Zや実数の順序不定にも、独自の数値の全順序を作りません。
- **プロジェクトの選択：** 副作用のないwithキーを、移動前にcardinality順で各要素1回評価します。
  キーより先に対象変数の結び付きを捕捉します。副作用のあるキーは、規格が許す未規定の動作を
  完全に実装するまで位置付きの未対応診断にします。P1の範囲から外す意味ではありません。
- **参照についてのプロジェクトの解釈：** 既存の要素変数の値を交換し、配列のサイズ変更・削除や
  変数全体への代入はしません。各添字のセルを保ち、要素のrefは並べ替え後の値を読みます。
  固定配列と動的配列で要素への参照の意味をそろえます。入れ子の所有値は言語のコピーをせずに
  移動し、その内部のrefはセルを保持します。insert・push・eraseのキュー移動の規則は保ちます。
  この解釈と入れ子の参照の扱いは、明示的なレビューが必要な点です。

## 共通の実装契約

SIR_SPEC 5.8へ`container.swap.values !T, ref<!T>, first, second`を追加します。
添字の整数幅を保ち、実際の対象の2値を交換します。不正な添字なら両方を変えません。
空・同一の添字は何もしません。C++20の`Heap::swapValues`と独立した`valsem`のセルモデルを
追加します。確定前に検証し、セルの識別子を保持し、新しいヒープの物体を作りません。
正規化後に変わったセルだけを確定後に通知し、入れ子のグラフ・GCの記録も更新します。
通知用メタデータの確保失敗は既存の位置付きResourceLimitとし、不完全な通知集合を受け入れません。

frontが縮約・並べ替えの型付きループを作り、VMは新命令を機械的に共通ヒープへ渡します。
VMに並べ替えやソースの形による判断を置きません。固定領域でも同じ値の比較を使い、既存の
placeから交換します。依存・インストール・C ABI変更はなく、kernelをslang/SIRへ依存させません。

承認後、有効化する前にVALUE_SEMANTICS・SIR_SPEC・RUNTIME_ABIと実装状況の文書へ反映します。
shuffle・検索メソッドなど、ほかの未対応の形もP1の全体目標に残します。このメソッドだけに
完成条件を縮める案ではありません。

## 必要な検証

独自の行列で、固定・動的・キュー、module・automatic・refと呼び出し、空・1・多数、符号、
2値・4値、1・32・64・65・129ビット、非空のX/Z、real・stringキー、名前付き・入れ子のwith、
実際のキュー上限、入れ子の値、保持したref、正確な変更通知、確保失敗、両方の実行群を横断します。
Icarusは独自入力の実行結果だけで比較し、拒否や不一致も記録します。意図的な誤りをコンパイルし、
値・診断の不一致を検出した後で復元し、全ローカルCIを通します。既存の本体・期待値・PerfCountを
保ち、期待値の変更が必要な場合はリポジトリの規則どおり別のレビュー対象PRにします。
