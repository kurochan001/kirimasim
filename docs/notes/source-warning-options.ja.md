# ソースの警告オプション

[English](source-warning-options.md) · 英語版が正です。CLI.md 2.1に沿った実装です。

`kirimasim -Wwidth-trunc design.sv`と`kirimasim parse -Wwidth-trunc design.sv`から
警告オプションをslangに渡せます。以前は直接の指定が不明なオプションになりました。
引数ファイルの中では以前からslangに届いていました。既定の診断設定は変えていません。

`parseArgs`で、名前の付いた各`-W`引数を指定順に渡します。警告名・グループ・
有効化・抑制・エラー化・未知の名前の診断はslangが担当します。単独の`-W`は入力エラーです。
ドライバに警告名の別の一覧は持ちません。実行時の診断は従来の各オプションで制御します。
計画中のkirima接頭辞の実行時診断の制御を追加したものではありません。

`tools/gen_slang_warning_matrix.py`が独自の12例を生成します。
`cli/slang_warnings`で、parse・実行、直接・引数ファイル、ソースの前・後の組を調べ、
空の名前とhelpの検査も合わせて99項目を確認します。終了コード・標準出力・重大度・
診断グループ・幅変換のソース位置を検査します。オプションを捨てる変異と、順序を逆にする変異を加えました。
既存の期待出力とソース入力は変更していません。

## 作業中に見つかった互換モードの境界

`--compat`は引き続きドライバから直接指定できません。既存の引数ファイル経由で、
native `7eab335e`、固定版slang `e2d102166`に次の不整合が見つかりました。
`--compat=all`ではinitialとalways_ffから同じ変数へ書く形をslangが許します。
parseは通りますが、実行はSIRの厳格な書き込み制限で内部エラー（終了コード3）になります。
既定とvcsでは入力エラー（終了コード2）です。
[独自のソースと6件の観測](../measurements/2026-10-31/slang-compat-sir-boundary.json)は不具合の記録で、回帰テストの期待値ではありません。

互換モードの実装を完了とする前に、明示した緩和とSIR_SPEC 7.1・10、承認済みのCLI方針を
整合させる必要があります。今回の変更ではその契約を改定せず、新しい互換モードも有効にしていません。
