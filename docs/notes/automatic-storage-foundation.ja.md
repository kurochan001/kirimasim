## 承認された契約と範囲

2026-10-25に[automatic捕捉の契約1–8節](automatic-capture-proposal.ja.md)が承認され、
[SIR_SPEC 3/7/8・SCHEDULER_SPEC 9/10・RUNTIME_ABI 4/6への対応](p1-execution-contracts-2026-10-25.ja.md)を記録しています。
IEEE 1800-2023 6.21/9.3.2の変数同一性と字句スコープの保持に基づき、
所有・トークンの詳細は承認されたプロジェクトの方針です。他のシミュレータの実装・テストは
読んでいません。依存・インストール・大域状態・外部ABIの入口も追加していません。

Contextが持つ再利用可能な記憶域と型付きルート公開を実装しました。
ソースのfork捕捉、activation命令、管理されたautomatic event、refの結び付き、
クラス・オブジェクトの格納はまだ有効にしていません。既存の拒否と期待値は維持しています。
承認された契約の完成には、これらの層とソースの行列による検証も必要です。

## 保持されたactivationごとに実体は1つ

`Context::activations()`が`ActivationStore`を持ちます。不変の配置表に要素の種類・幅・
固定次元・検査済みの位置を記録し、種類・次元・位置をすべて検査してから表を確保します。
二状態・四状態整数、real/shortreal、不変string/chandleハンドル、明示的なcontainer・cell
ルートを扱います。不明な種類は拒否し、object/event/refを安全な未追跡整数とは扱いません。
内部の安全なゼロ値は言語の初期化ではなく、front側で宣言の既定値・初期化を1回ずつ出す必要があります。

行番号32ビットと世代32ビットの数値トークンでスコープを識別します。
所有者と子孫のleaseは、子が明示的に読まないフィールドも含む同じ実体を保持します。
古い子が生きたまま再入すれば別の実体を確保し、最後のleaseが終わると値を解放して
世代を変えて行を再利用します。世代が尽きた行は折り返さず引退させます。
clearも世代を初期化せずに古い所有者・結び付きを無効化します。空の字句スコープも同じ所有規則です。

bindingにはフィールドの同一性、権限、C++上のstoreの同一性を持たせます。
これは実行用メタデータで、SystemVerilogの値にネイティブなアドレスを入れるものではありません。
bindingのコピーは所有を取得せず、明示的なretainとmove専用leaseで寿命を管理します。
C++のleaseはContextより長生きできません。readonlyはretain・move・再bindingでも維持し、
数値トークンが同じ別Contextのbindingも拒否します。

読み書きでは世代・フィールド・要素・ビット範囲・バッファ寸法を検査します。
全語を正規化してから通知し、二状態変換は既存のkernel/valsem規則を使います。
失敗・不正・readonly・値が変わらない書き込みは通知しません。フックは数値の
フィールド・要素・範囲を示し、確保・例外・storeの変更やresetを行えません。
スケジューラ購読への接続は残作業で、ここでは記憶域側の境界を作っています。
確保失敗は状態で返し、部分的な行を公開せず、既存の結び付きを変えません。
leaseの解放は確保もソースのコールバックも実行しません。

## インタプリタのフレームと独立した型付きルート

宣言されたcontainer・切り離されたcellだけを列挙し、同じビットの整数・string・chandleを
ヒープのルートにはしません。leaseが複数あっても物理フィールドを1回だけ追跡します。
値の置き換えと最後のleaseの解放も、ルート集合の変更として記録します。
stringは既存のContext内の不変表現を使います。

VMの既存の安全点でも、生存中のインタプリタフレームとは独立にこのstoreを列挙します。
個数を数えて呼び出し側の領域を整えてから、確保しないvisitorで埋めます。
回収・失敗・保留値は既存の共通ヒープ処理を使います。発行元のフレーム終了後の保持と、
ヒープ変更を伴わないlease解放後の回収を実際のVMで検査しています。
kernelはslang・SIR・LLVMに依存しません。公開ヘッダと単独ストレスプローブはC++20で通り、
C ABIは0.3のまま、第1層は引き続きC++を直接呼びます。

## 検証

[独自14テスト](../../tests/unit/activation_test.cpp)は二状態・四状態、幅1〜257の10種類、
単一値・昇順・降順・二次元の80配置を検査します。要素の独立性、packedの隣接ビットの保持、
入れ子lease、再入、reset、Context分離、readonly、正規化、通知、型付きルート、
切り離されたcell、確保失敗、実VMの安全点2経路も含みます。
完了した10万スコープを繰り返してもメタデータは1行です。11種類の誤りを実際に
コンパイルし、4・2・1・1・2・1・1・1・2・2・2件の失敗で検出して、復元後も通過しました。
事前に領域を整える最後のルートvisitorも、公開を省く対照で再検査しています。
全547個の置換位置も適用可能です。[記録](../measurements/2026-10-25/activation-foundation-focused-validation.json)を保存します。
devは4,557件中4,555件成功、失敗0・既知の2件のみスキップで、変更箇所のclang-tidyも通過しました。

[明示的なストレス検査](../../tools/check_activation_generations.py)では、実際の
32ビット世代を小さくせず、全4,294,967,295世代、行の引退、新しい行と古いbindingの拒否を検査しました。
[実測](../measurements/2026-10-25/activation-generation-exhaustion.json)は35.684秒で成功し、
実際のカーネルソースをC++20でコンパイルしています。通常のCTestには含めず、次で再現できます。

```sh
python3 tools/check_activation_generations.py --output build/activation-generations.json
```

これは記憶域のストレス結果で、シミュレーション速度の比較ではありません。
PerfCountの既存期待値は変えません。実時間のシミュレーションへの影響は別途未計測で、
ソースとの接続を評価するときにPERFORMANCEの既存手順で確認します。
この基盤や有限の棚卸しだけではP1全体の同等性を証明できません。
