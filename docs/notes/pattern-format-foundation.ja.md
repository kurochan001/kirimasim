# 共有カーネルの代入パターン表示API

[English](pattern-format-foundation.md)。本体実装は`156e65c`、2026-10-24です。
カーネルAPIの基盤です。後続の`4c69843`で[SIR・実行処理](pattern-sir-execution.ja.md)も接続しました。
frontの接続が残るためソース`%p`は未対応で、比較の差分解消とは数えません。

SYSTEM_TASKS 3.9には`%p`・`%0p`の表示規則が既にあります（IEEE 1800-2023 21.2.1.6）。
新しい公開C++20ヘッダ`pattern.h`は、rootで保護された型付きの借用値を表示し、slang・SIRに
依存しません。依存の追加や、既存の書式parser・syscallの変更はありません。

## 値と走査

`PatternValue`は整数・実数・文字列・enum、record、配列、連想配列の組、union、tag付きpayload、
表示用ハンドルを表します。呼び出す側がフィールド・enum・tagのソース識別子、宣言順、連想配列の
キー順、Contextが割り当てた表示番号を渡します。予約語・escaped identifierにはfrontが表示用情報を
付け、カーネルが字句解析やソース型の選択を行う形にはしません。ハンドルはスカラーの末端で、
オブジェクトをたどったり、アドレスやtokenを表示したりしません。

recordには名前を付け、positionalでは入れ子も名前を除きます。配列は位置順、連想配列は渡された
意味上のキー順で表示します。unionは最初のメンバー、tag付き値はtagとpayloadを示します。
enumは2値・4値の格納形式をまたぎ、X/Zと全有効bitを照合し、paddingを無視します。一致しない値は
元の整数型で表示します。数値は既存の共有formatterを使います。文字列はSVの引用符付きliteralとし、
規定のescapeと3桁8進表現を使います。Cの`\b`・`\r`はSVではbackspace・carriage returnに
ならないため（5.9）、そのbyteの表現には使いません。

明示的な作業stackで入れ子を処理し、現在の経路で循環を検出します。同じ非循環な部分値を
複数回使うことは許します。1,024文字での打ち切りはありません。形の不正、循環、確保失敗は
別の状態として返し、途中の出力を返しません。一時確保には呼び出し側のmemory resourceを使い、
戻す文字列は独立した記憶域を持ちます。値を借用するAPIで、rootや書き換え可能な大域状態を作りません。

このAPIは、未実装のソース型のレイアウトを決めるものではありません。連想配列の順序は呼び出し側の
前提で、tag付き値にはpayloadのview、ハンドルには表示用の番号が必要です。実際のclass・event識別は、
2026-10-25に承認したクラス・eventの契約に依存します。型付きSIRの書式情報と実行処理は`4c69843`に
あります。frontの変換、ソース引数の保持、runtime書式の引数受け渡しは、ソース対応を
有効にする前に接続する必要があります。クラス・eventの契約の実装は残作業です。

## 独立した検査

新規ユニット14件で、入れ子とpositional、escaped identifier、unionの最初のメンバー、tag付きpayload、
順序を与えた連想配列、null・番号付きハンドル、不正なview、確保失敗時の解放を検査します。
enumの照合は幅257bitまでの7種類・112組をvalsemのcase等値と比較し、表示器自身の照合関数を
期待値には使いません。独立したSV literalの読み取り器で全256byteと8進数字の境界を字句として往復し、
2万段の入れ子、16KiBを超える出力も確認しました。SV stringが実行時にNULを保持する
という主張ではありません（7.6）。ソース型への対応を証明する検査ではありません。
ユニットでは承認済みの表記を検査しますが、suiteの期待値へ参照依存の`%p`の空白を採用しません。

[コンパイルした誤実装6種類の記録](../measurements/2026-10-24/pattern-format-negative-controls.json)には、
buildの成否と失敗した新テストを残しています。上位ワードの省略、X/Z無視、positionalの名前、
unionの余分なメンバー、完了経路の保持、Cのescapeへの取り違えを検出します。数える条件は、
コンパイルが通り、古いFormat 22件をすべて通り、Patternのassertionで失敗することです。
アンカー・判定器の自己検査は証拠にしません。復元後に再buildし、選択した36件が成功しています。

## 残作業

SIR表・検証器・text・VMの接続は後続の`4c69843`で実装しました。次はfrontで型・
フィールド・enum情報と引数を捕捉し、定数とruntimeの書式を同じAPIへ渡す必要があります。評価順、snapshot、コンテナのroot、Postponedの報告、書き戻しを
守り、既存の各ソースコンテキストで動かします。ソース対応を実装した時点で、古い`%p`の未対応
期待値を別のレビューへ分け、元のソース本体を保ちます。P1全体、ソース`%p`実行、新しいLinuxの
結果は引き続き未確認です。
