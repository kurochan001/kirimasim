# 広い三状態ゲートの強さマスク

[English](wide-gate-strength.md)。実装`37a2726`と境界の修正`57a64ef`を、
2026-10-24に検証した記録です。

## 対応した動作と境界

`bufif0`・`bufif1`・`notif0`・`notif1`で、32ビットを超える解決対象ネットでも
L/Hのsideマスクを保持します。VALUE_SEMANTICS 5.4/5.8とSIR_SPEC 3.5の
既存契約の実装で、意味の新しい選択・命令・依存・カーネルAPIは追加しません。
値は検証済みの共有カーネルの区間解決器が決め、VMはドライバ値とマスクを受け渡します。

sideはネット幅の2倍で、0側の半分はネット全幅の位置から始まり、64ビット語の途中に
来ることもあります。そのため結果が1語の33～64ビットでも、sideは複数語になります。
VMはマスク付き・なしのドライバを混在して読み、各結果語の両半分を絶対ビット位置で
抽出します。frontの32ビット制限も除き、side計算の実際のブロックを保持します。
短絡式で関数を呼ぶゲート制御は、入口と別のブロックで計算を終えることがあります。

この版（2026-10-24）では、解決対象ネットの遅延付き三状態ゲートは有効にしません。投影が同じL/Hの時刻には
明示的な契約が必要なため、[遅延sideの修正案](delayed-gate-side-proposal.ja.md)は承認待ちです。
実験経路は取り除き、実装には従来の未対応診断を残します。この修正案は2026-10-25に承認され、
現在は[実装済みです](delayed-gate-state-execution.ja.md)。MOS・スイッチ、部分的な
ポート接続での強さの保持、`%v`も残作業です。今回の静的強さのsideマスクで、MOS網を
通る任意の解決済み強さ区間の受け渡しまで実現したとは扱いません。

```systemverilog
module top;
  logic [64:0] data = '0;
  logic control = 'x;
  wire [64:0] q0, q1;
  bufif1 g0[64:0](q0, data, control);
  bufif1 g1[64:0](q1, data, control);
  assign (weak1, weak0) q0 = '0;
  assign (weak1, weak0) q1 = '1;
  initial begin
    #1; $display("%0d %0d", q0 === '0, q1 === 'x);
    data = '1;
    #1; $display("%0d %0d", q0 === 'x, q1 === '1);
  end
endmodule
```

出力は`1 1`・`1 1`です。L/Hを両側が有効なXとして扱うと、弱い併駆動との組み合わせで
既知になる0または1を失います。

## 独自の検証

[`gen_wide_gate_side_matrix.py`](../../tools/gen_wide_gate_side_matrix.py)が独自73ソースを
生成します。72件はゲート4種、幅33/63/64/65/129/257、module・generate・interfaceが
所有する信号です。全データ/制御値、弱い0/1、語をまたぐ異なるビット、昇順・降順の
ネット範囲を検査します。プリミティブはmoduleに置き、interfaceの信号へ直接接続します。
別の1件はゲート制御の短絡式から関数を呼びます。

[ソース・期待値・出力のハッシュと各エンジンの結果](../measurements/2026-10-24/wide-gate-source-validation.json)に、
現在のnative、既存のIcarus 13.0 stable・14.0開発版で73件すべて成功したことを記録します。
保持した旧バイナリ（表示版`396131e016eb`）は73件とも未対応でした。この作業のために
既存ソース本体・期待出力は変更していません。

独立した[SIRテスト](../../tests/unit/wide_strength_sir_test.cpp)は1～257ビットの8幅、
弱い背景値2種、ドライバの両順序を検査します。周期3・5のマスクで、ソース行列の
ビット模様とは独立に両半分と離れた語を区別します。コンパイル済みの誤実装4種類、
固定された0側の位置、1側マスクの無視、先頭マスク語の反復、誤った制御フローブロックを、
新しいstdout期待値で検出しました。最初の3種類は独立SIRのアサーションでも検出します。
アンカー・判定器の自己検査は証拠から除き、終了後はソースを復元・再ビルドしています。

境界の修正は、全ブロックで遅延付き書き込みを調べます。この版では、独立したCLIテスト
（Toolsテストの[`check_delayed_gate_boundary.py`](../../tests/tools/check_delayed_gate_boundary.py)）が、関数の
制御式と幅1/65/257で、位置付きの遅延拒否6件と、解決不要な遅延なしの受理6件を検査しました。
使わないside計算を実際のブロックから取り除く経路も確認できます。入口だけを調べる
誤実装へ戻した別のコンパイル済み対照も、このCLI検査が検出しました。短絡式を使っても、
承認待ちの遅延解釈が偶然有効になることはありません。2026-10-25の`2b38b984`で、
遅延拒否6件を完全な状態の伝播の検査に置き換え、遅延なしの6件は残しました。

全ローカルCIと版付きの有限の機能比較は[最新進捗](p1-icarus-progress.ja.md)に記録します。
新しい比較項目はこの仕組みの測定で、P1全範囲の証明ではありません。性能は未再測定です。
