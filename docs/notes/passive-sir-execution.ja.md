## 静的な表現と所有

`Design::strengthEdges` が正規化済みのスカラー端点、種類、任意の制御プロセス、遅延形の
フラグとソース位置を持ちます。表の順序が安定した型付き `StrengthEdgeId` で、`!eN` と
表示します。種類は identity、tran、rtran、tranif0、tranif1、rtranif0、rtranif1 です。
identity と無条件スイッチは制御所有者や遅延を持たず、導通状態で始まります。
条件付きの辺は非導通で始まり、宣言した静的 cont 所有者を一つ必要とします。
伝達写像と極性は種類で決まります。

プロセスの `strengthEdgeWrites` は、物理 origin の書き込みや通常の net 書き込みとは
別です。`strength.edge !eN, control` と `strength.edge.delay !eN, control, on, off`
は所有する辺だけを更新します。制御は捕捉済みの整数スカラーで、両方の状態領域と符号に
対応します。遅延は任意幅の捕捉済み整数 tick です。既存の遅延規則を使い、X/Z はゼロ、
既知で時刻範囲を超える値は実行時の誤りになります。命令は値を作らず、待ちません。
遅延はカーネルが所有するスカラータイマーで、利用者のプロセスや発行 frame へのポインタに
しません。

verifier は、不正な端点・種類・位置、異なる成分間の辺、他者や非静的な所有者、重複・不足した
書き込み宣言、偽装したオペランド形、非スカラー・未捕捉の制御、遅延形の不一致、通常命令での
辺 ID 使用を拒否します。uwire の可能な接続は、最初に非導通の辺も含めて異なる物理 origin を
数え、重複経路を別 driver にしません。不正な網は kernel 登録前に拒否します。
net の各 bit は引き続き成分 publisher だけが書きます。

テキスト出力は辺の行と所有を決定的に表示し、形式は 0 のままです。
パーサや print/parse の往復を実装したという意味ではなく、それらは P2 の残作業です。

## 共通実行と独立した証拠

VM は node・origin・edge を Context が所有する既存の網にコピーし、辺の更新を
`setStrengthEdge` / `setStrengthEdgeDelayed` に渡します。
`kernel::strengthConduction` がスカラー制御を非導通・導通・不確定に変換し、
`valsem::passiveConduction` が独立して参照を定義します。VM にソースの形による条件や
グラフ解法、近似は置きません。world の相関、物理 origin の同一性、Active の公開と
慣性の取り消し・確定は、既存のカーネルで実行します。

新規 7 テストで、次を確認しました。

- 妥当な SIR 4,560 実行：全 120 区間、全種類の辺、適用する全 4 値制御、反対の物理根と
  伝搬の両方向。宛先の全 9,120 区間が独立した world/経路の参照と一致しました。
  期待する種類や極性の選択では実装の schema 補助関数を呼びません。
- 不正な宣言・オペランドの 30 変種（うち 27 件は VM 入口で登録前に拒否）、
  最初は非導通の辺や重複経路を通る uwire の物理根、形式 0 の決定的な出力。
- 明示ゼロ遅延での符号・状態領域・制御 48 件、幅広遅延のオーバーフロー拒否と X/Z の
  ゼロへの正規化。時間を進める制御・データの実行では、取り消し、同じ保留値の期限維持、
  turn-off 保留中の現在のデータ、不確定状態の遅延選択を確認します。

dev 全 CTest は 5,391 本で、5,389 成功、失敗ゼロ、既知のスキップ 2 本
（`suite/cb/input_sample_1step`、`suite/nets/net_port_drivers_part`）です。
既存の dump 期待 29 件と PerfCount も変更せず通りました。README 集計はこの実行から
再生成し、外部母集団とプローブの計測日は変更していません。
