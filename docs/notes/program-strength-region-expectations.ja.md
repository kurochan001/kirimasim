# program の強度解決領域に関する単体期待値の分離移行

[English](program-strength-region-expectations.md)

この移行は、[program-net の修正案](p1-scheduling-corrections-proposal.ja.md) の第 1 節で
保守者が 2026-10-29 に承認したスケジューリングの改定に対応します。
独立した PR とし、実装も別にレビューします。

既存の単体テスト 2 件は、初期の解決、プロセスの再開 2 回、dirty な成分の解決 1 回を数えます。
Reactive 側の分岐は、従来 Active 2 イベント・Reactive 2 イベントを期待していました。
承認した改定では、初期解決が Active の 1 イベント、Reactive での再開 2 回と解決 1 回が
Reactive の 3 イベントになります。Active だけの分岐の既存回数は変えません。

解決領域を表すようテストを改名します。値、コールバックの順序、Inactive イベント、
プロセス件数に対する正確なアサーションは保ちます。領域別の回数も等値で比較し、合計件数も維持します。
スケジューリングの根拠は IEEE 1800-2023 4.5 と 24.3.2 です。
内部成分をどの領域に置くかの明示的な選択は、承認済みのプロジェクト改定によります。

独立したソース回帰テストは program の駆動・解放、Re-NBA、遅延したネット更新を検査します。
新しいカーネル検査は、根、導通、初期状態、慣性遅延の保持、確定した遷移を検査します。
統合前に実装とこの移行を組み合わせて検証します。
