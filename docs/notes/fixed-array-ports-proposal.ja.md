# 固定長配列全体のポート接続と要素ごとのネット解決

[English](fixed-array-ports-proposal.md)。状態：**承認済み（2026-10-25）、実装中**。
2026-10-24の提案本文は決定の記録として残します。下の承認要求・未来形・未承認の記述は
提案時点のものです。人は2026-10-25に6案をまとめて承認しました。
[仕様への対応](p1-execution-contracts-2026-10-25.ja.md)を参照してください。
承認は実装完了を意味せず、既存期待値の変更や新しい依存の追加は含みません。

## 修正が必要な理由

独自の固定長unpacked配列の入力・出力ポートは、Icarusの両参照で実行できます。
現nativeでは接続されたunpacked配列ポートと、複数ドライバのネット配列を拒否します。
SIR_SPEC 3.5のスカラー向けのcollapse・連続代入だけでは、異なる添字の別名ビュー、
要素ごとのドライバ、未接続配列のpullを具体化できません。VALUE_SEMANTICS 5.8も
未接続の配列ポートを未対応としています。P1_SCOPEは対応範囲を前倒ししましたが、
不足する詳細契約には実装前のレビューが必要です。

SIR_SPEC 3.1〜3.5・4.2・5.3・7.1・10、VALUE_SEMANTICS 3.13・5.3・5.5・5.8、
SCHEDULER_SPEC 6.1・12の実装説明を改める提案です。値、強度、実行領域、連続代入、
force、感度、初期化の既存規則を保ちます。依存・インストール・外部ABI変更は選びません。

## 1. 型・次元・対応順

厳格なslangのエラボレーション結果の方向・種別・型・接続を使います。`var`を省略した
明示型のinputを勝手に変数へ変えず、23.2.2.3の入力ネット推論と診断を保ちます。
暗黙のreal/string入力の受理を、一般の明示的な`wire real`などの受理へ広げません。

葉は実行可能な値表現のある整数（enum・packed複合型を含む）、real/shortreal、string、
chandleを対象にします。強度の解決が必要なネットの要素には、対応済みの整数ネット型が
必要です。eventの所有、classのルート、unpacked構造体のポート配置、動的コンテナの
暗黙の感度は別契約に従い、未対応の型を位置付き診断のまま残します。

各次元の要素数を一致させ、宣言の左端同士から再帰的に対応させます。添字の数値や
昇順/降順は異なって構いません。最右次元を最速で進め、各宣言の添字・foreach・型/配列
問い合わせは元の境界を保ちます。数値が同じ添字を対応させたり、rankが違う配列を
総要素数だけで同じにしたりしません（6.22.2、7.6、23.3.3.5）。

型適合と変換はエラボレーションに従います。配列全体の代入には7.6の等価な要素型が
必要で、一般の数値拡幅を要素ごとに発明しません。幅・符号・2/4値性が不適合な例は
違法入力の検査で、未実装機能ではありません。等価な2値出力の例は別に検査します。
各葉の正規化と既定値は既存規則です。

## 2. ネット全体の接続と別名ビュー

rank、各次元の要素数、葉の幅・符号・2/4値性が一致する固定長ネット配列全体へ、既存の
collapse規則を拡張します。input・output・inoutで対応する物理要素を共有し、Table 23-1の
既存のネット種別統合、slangの警告、uwire検査を保ちます。親・子・多段の別名を通じて
各物理要素の解決先は1つです。コピーや、4値から強いドライバを再構成する経路ではありません。

正準slotは1つの配列配置を持ち、frontが各別名の不変ビューを保持して、宣言した座標から
正準座標へSIRで変換します。変換より前に元ビューの境界と不明bitを検査します。
広い・X/Zを含む・範囲外の添字が、オフセット計算で隣の有効な要素へ回り込みません。
十分な幅の順序位置計算を使い、既定値の読みと無効書込みの規則を保ちます。
読み・書き・選択・ref・force・範囲情報・さらに先の接続が同じ変換を使います。

名前・診断・型問い合わせには元の宣言を残し、実行時の識別は数値です。VPIのオブジェクト
モデルやVCDの配列拡張は選びません。既存WAVEFORMの配列省略を保ちます。
物理的な変更は1回だけ発行し、別名ごとの重複通知や余分な解決ループを作りません。

任意のbit部分接続・ネット連結・動的トポロジー・MOS区間伝搬は有効化しません。
非collapse経路が運べない強度を必要とする接続は、従来の位置付き未対応診断を保ちます。
[MOS・ポート網の案](mos-switch-proposal.ja.md)は別レビューで、この配列案の承認を
その案の承認とは扱いません。

## 3. 非collapseのinput/output値接続

変数や対応済みの式への接続は、4.9.6・23.3.3.2〜3の暗黙の連続代入にします。
宣言順、文字列/値の独立性、既存の右辺を先に評価する方針を含め、集約代入と同じ
型付きコピーを使います。配列全体の式を評価・保持してから宛先へ書き込み、
後のソースの副作用を先の宛先要素への書込みと混ぜません。SSA一時値を借用のまま残しません。

変更した要素・packed bitや、条件式で静的に読む全分岐を含め、対応済みの読み範囲で
再評価します。他要素を古いままにせず、宛先の各要素のためにソースを再評価しません。
最長の静的prefixと型付き変更通知を保ちます。明示`var`の入力も連続的に更新します。
参照がその例をX/Xにした観測を、初期化だけでよいという方針にはしません。

暗黙のプロセスは既存のinstance・領域規則で所有します。programポートはprogramの
同一性とreactive側を保ち、module/interfaceは現在の領域規則です。要素ごとの余分な
利用者プロセスやRNGを作らず、更新・解決を共有カーネルで行います。

refポートは別の束縛契約が必要で、ここでは実装しません。inoutの両側は適合するネットが
必要で、変数は違法のままです。未対応の部分配列ビューやinstance配列への分配・複製は、
23.3.3.5に基づく配置変換と検証まで明示的に拒否し、接続を黙って飛ばしません。
必要な範囲は引き続きP1の対象で、今回の参照例の失敗だけで全面的な非対応とは断定しません。

## 4. 要素ごとのドライバと解決

解決対象のネット配列は、同じ要素配置のドライバ記憶域を持ち、各ドライバの強度と
対応済みside表現を保ちます。共有のVALUE_SEMANTICS 5とvalsem参照を使って物理要素・
bitごとに解決し、配列全体を1本のpackedワードにしたり、隣要素のドライバを混ぜたりしません。
要素/bit範囲で駆動部分を区別し、覆う部分の初期状態は承認済みのX/強度、覆わない部分はZです。
組込みpull/supplyも既存のネット種別のまま要素ごとに適用します。

SIRの不変配置と範囲で対象を特定します。ポート全体の代入はビュー全体、定数要素・bitの
書込みはその範囲を覆います。実行時に対象を選ぶ経路には現在の駆動範囲が必要で、以前の
要素への余分なドライバを残しません。その機構を実装するまでは、全要素への恒久的な
書込みで近似せず位置付き未対応診断にします。遅延付きドライバは既存の値保持・遅延選択・
inertial取消しに従い、配列独自のタイマーやside時刻の意味は選びません。

変更した範囲の既存の解決処理を起動し、解決後の実際の値変化を待機/エッジへ通知します。
対応済みside変化、初期順序、不変書込み、決定的な起床順も既存契約です。
遅延/不明な三状態sideと完全なMOS/ソース網の境界は別案の未対応状態を保ちます。

対応済みの定数要素/packed選択のforceは、すべてのcollapse別名を通じて同じ物理要素へ
作用し、releaseはその要素の実ドライバから解決し直します。変数の部分force、実行時の
ネット選択、未対応の集約forceに関する制限を保ちます。

## 5. 未接続とpull

通常の未接続ネット要素はoutput/inoutも含めZ、変数入力は型の既定値です。
23.2.2.4のinput既定値は宣言側のスコープで定数評価し、実引数がないときの入力接続に
挿入します。通常のポートプロセス/領域でその配列をコピーし、別のstatic初期化段階を
発明しません。既定値がある接続をpullや0で置き換えません。

`unconnected_drive`が適用される未接続inputネット配列には、各整数要素の全bitへ、
既存の承認済み強度5のpullを加えます（22.9、VALUE_SEMANTICS 5.8）。定義位置の指示と
宣言した方向を使います。pull0/pull1は内部のweak等と解決し、変数への初期値の埋込みには
しません。output/inout・変数入力はpullせず、変数入力の既存警告も保ちます。

非整数の暗黙入力ネットや、pullの対応が未定の複合ポート式へ一般化しません。
その境界は詳細契約まで未対応とし、配列pullをprogramを存続させる隠れたプロセスにしません。

## 6. 表現・検証・リソース

frontが形状・別名対応・コピー順・駆動/依存範囲を選び、型付き配置/範囲と明示的なSIRで
表します。VMは名前や構文から意味を補いません。テキスト形式に別名ビューとドライバを
決定的に残し、範囲・型・物理対象・演算のオーバーフロー・実行起源・読み/書き/駆動範囲を
検証します。roundtripでそれらを保ちます。

共有カーネルが実体、ドライバ、解決、変更通知、forceを所有し、slang/SIR/LLVMを持ちません。
将来のC++層も例外/RTTIなしの同じC++20 APIを使い、公開ヘッダを増やす場合は既存の
コンパイル検査へ加えます。大域レジストリ、実行時環境読み、名前引き、VM専用解決器を作りません。

要素数・stride・バイト数・ドライバごとの積を事前検査します。確保失敗とオーバーフローは
既存のresource_limitへ渡し、独自の配列上限や部分置換を作りません。疎な駆動範囲に対し、
巨大なドライバ数×配列長の確保を費用の計算なしに行いません。新しい依存は不要です。

## 証拠・受入条件・残作業

[独自ソースと観測](../measurements/2026-10-24/fixed-array-port-design-observations.json)は
59プログラム、nativeソース`c6d9c3d`（バイナリ表示`392687e`）、macOS/arm64、
13.0 stableと14.0 develの対応するcompiler/runtimeを記録します。違法入力7本を厳格な
slangが拒否し、ほか52本はparseが通ります。合法52本では両参照とも提案モデル36本一致、
コンパイル失敗15本、出力不一致1本です。nativeは4本成功、48本実行拒否で、参照と
モデルが一致する34本が未対応です。この設計用の集まりは機能一覧とは別で、比率で完成度を示しません。

不一致は明示input `var`の例です。提案モデルの7/9に対して両参照はX/Xでした。
違法な書込みの2本を参照が受理しても、slangの拒否を未実装機能としません。
型の不適合も数値配列キャストへ変えません。参照backendのassertionは終了値のみを残し、
実装式を転載しません。他のシミュレータのソース・テストを読まず、規格の例もコピーしていません。

受入条件は、幅1/32/65/129とさらに広い境界、2/4値、rank/方向/添字、入出力/inout、
module/generate/interface/program/多段階層、値の変更、葉の型、値/強度の解決、
部分的な駆動範囲、force/release、未接続/既定/pull、不正接続です。独立したkernel/値/SIRの
検査でビュー境界、X/Z添字、ドライバ分離、reset/Context分離、確保失敗、変更/エッジ通知も確認します。

対応順・境界・連続更新・右辺保持・要素の分離・pull強度・force共有の誤実装を、実際の
新出力や有効性検査で検出し、判定器の自己検査は別扱いにします。既存のスカラー対照・
SIR出力・suite期待値を保ち、CLI拒否の移行があれば理由付きの期待値専用ブランチ/PRへ分離します。
実装PRはその上に置き、push前は完全なローカルCIを通します。

この案で対応済み機能は増えません。class、VPI、specify/タイミング、動的コンテナ感度、
さらに広い接続や他の承認待ち契約はP1の残作業です。この観測や有限の一覧だけでIcarus 13.0の
全機能対応やLinuxの結果を達成とはしません。
