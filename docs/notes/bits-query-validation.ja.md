# `$bits` 内の関数呼び出しのコンパイル時検証

[English](bits-query-validation.md)

[Issue #53](https://github.com/kurochan001/kirimasim/issues/53) で検査の不足が判明しました。
動的配列を返す呼び出しを `$bits` で囲むと、固定版フロントエンドが評価し、見かけ上のサイズを
返す場合がありました。IEEE 1800-2023 20.6.2 は、囲まれた式に動的サイズの関数戻り値が
ある場合に診断を要求します。これは既存の[変換・問い合わせの契約](../spec/SYSTEM_TASKS.ja.md#8-変換と問い合わせ)
を補う検証で、契約や依存の固定版を変更しません。

共通のフロント検査は、エラボレーションと解析が成功してから、lowering の前に実行します。
`parseAndElaborate` と `compile` は、どちらもこれを言語エラーとして数えます。
CLI の parse・実行・SIR 出力は終了コード 2 となり、設計の実行や SIR の生成はしません。
同じ位置を複数インスタンスが共有する場合や、1 つの問い合わせに複数の動的呼び出しがある場合も、
問題のある問い合わせのソース位置ごとに 1 回だけ報告します。

検査は代わりのサイズを計算せず、型を使います。問い合わせの引数式を、入れ子の関数・
システム関数呼び出しを含めて調べます。呼ばれた関数の本体は、その式に含めません。
string、動的配列、キュー、連想配列の戻り値は動的です。固定配列、構造体、共用体、
class のプロパティは再帰的に調べます。class の走査は継承と循環に対応します。
event、chandle、interface のハンドルは、動的配列や文字列には分類しません。

エラボレーションが保持する元の式により、初期化式、サブルーチン本体、パラメータの上書き、
defparam、generate 制御を検査します。境界値で元の式が置き換えられた次元やサイズキャストは、
型を復元するために問い合わせの引数だけを束縛します。問い合わせ全体も引数の値も、
この検査では評価しません。宣言の字句スコープを保ち、上書きするパラメータには
インスタンス化のスコープを使います。

独自の回帰テストは、3 種類の CLI 経路のエラーと位置、評価しない固定サイズの問い合わせ、
入れ子の呼び出し、不透明なハンドル、class、定数化された文脈、呼び出し元と先の名前の隠蔽を
確認します。API テストは言語エラーと未対応 lowering を区別し、位置ごとの診断件数を検査します。
既存ソースの本体、出力期待値、性能期待値は維持します。動的変数に対する実行時の問い合わせは、
従来の対応範囲を保ちます。
