## 起動形式と表記

```text
kirimasim [options] <file>... [+plusarg]...
kirimasim parse [options] <file>...
kirimasim --help | -h
kirimasim --version
```

| 形式 | 動作 |
| --- | --- |
| サブコマンドなし | ソースの読み込みとエラボレーション、SIRへの変換と検証の後、デザインを解釈実行 |
| `parse` | 前処理・構文解析・型検査・エラボレーション。SIRへの変換とシミュレーションは行わない |
| サブコマンドなしで`--dump-sir` | SIRを生成・検証し、テキストを出力してシミュレーション前に終了 |
| `--help`、`-h` | 起動形式と受理するオプションを標準出力へ表示。入力ファイルは不要 |
| `--version` | バージョン、ソースのコミット、コンパイラの識別情報を標準出力へ表示。入力ファイルは不要 |

`parse`は入力オプションやソースパスより前に置いてください。成功が示すのは
フロントエンドでの受理であり、すべての構文が実行できるという意味ではありません。
シミュレーションを行わないモードでは、実行用オプションに実行時の効果はありません。
`parse`と併用した`--dump-sir`は、処理をSIR生成へ切り替えません。

本書の`<name>`は置き換える値、`a|b`は選択肢を表します。山括弧や縦棒をそのまま
入力しません。短いオプション`-I`・`-D`・`-y`は引数の連結形・分離形を受理します。
`-f`は分離形、`--top`は`--top=name`・`--top name`の両方に対応します。
以下の、それ以外の値付き長形式オプションは`=`が必要です。

空白・引用符・ワイルドカードを含むシェル引数は、引数全体を引用符で囲んでください。
未知のオプションや不正な引数は入力エラーで、通常は終了コード2です。
オプション終端を表す`--`には未対応です。`-`で始まるソース名には`./-design.sv`のような
パスを使ってください。

特記しない限り、整数の上限値・シードには`0`から`18446744073709551615`までの
10進整数を指定します。符号、小数、単位、区切り文字は受理しません。
`--max-time`には別の時刻値の書式があります。

## コマンドラインオプション

### 入力オプション

| 書式 | 既定値 | 意味 |
| --- | --- | --- |
| `-f <file>` | 指定なし | コマンドファイルからフロントエンド向けの引数を読む |
| `-I<dir>`、`-I <dir>` | ユーザーパスの追加なし | インクルードの探索先を追加 |
| `+incdir+<dir>` | ユーザーパスの追加なし | 既存のインクルードパス指定形式 |
| `-D<name>[=<value>]`、`-D <name>[=<value>]` | マクロの追加なし | マクロを事前定義。値の省略は`1` |
| `+define+<name>[=<value>]` | マクロの追加なし | 既存のマクロ定義形式 |
| `-y<dir>`、`-y <dir>`、`--libdir=<dir>` | ライブラリパスの追加なし | 未解決の定義をライブラリファイルから探索 |
| `+libext+<ext>` | `.v`と`.sv` | `+libext+.custom`のように探索する拡張子を追加 |
| `--top=<name>`、`--top <name>` | 自動選択 | トップモジュールまたはソース内のconfigを選択。複数回指定可能 |
| `--timescale=<unit>/<precision>` | `1ns/1ns` | timescaleを持たないデザイン要素に既定値を設定 |

これらの入力オプションは、通常実行と`parse`の両方に適用します。

**パスとコマンドファイル。** `-f`内のパスは、ファイルリスト自身の配置先ではなく、
プロセスの作業ディレクトリが基準です。内容はフロントエンド向けの引数であり、
シェルコマンドではありません。kirimasimの実行オプションと実行時プラス引数は、
実際のコマンドラインに置いてください。実行時のファイルタスクも作業ディレクトリを
基準にします。インクルードパスは`$fopen`や`$readmemh`の探索先を変えません。

**includeの探索。** includeを書くソース自身のディレクトリを先に探索し、その後で
ユーザーの指定順に探索します。`-I`と`+incdir+`を混在させても順序を保ちます。
`-I`はモジュールライブラリの探索先を追加しません。ディレクトリ引数の不足・空文字列は
入力エラーです。

**マクロ。** `-DFLAG`は`-DFLAG=1`と同じで、`-DFLAG=`は空の置換文字列を明示します。
`-D`の値に含まれる`+`や2個目以降の`=`は保持します。空のマクロ名はエラーです。
固定版フロントエンドは、指定形式が混在しても同名マクロの最初の事前定義を保持します。
値なしの定義の既定値はシミュレータ間で共通ではないため、共有するコマンドでは
`-DFLAG=1`など、値を明記してください。

**ライブラリ。** ライブラリのディレクトリはインクルードパスを追加しません。
たとえば、未解決のモジュール`counter`に対して`-y`のディレクトリから`counter.sv`を
読み込めます。ライブラリのソースは、追加のトップとして自動インスタンス化されません。
既存のフロントエンドの解決規則と`+libext+`に従って探索します。
拡張子を追加しても、組み込みの`.v`と`.sv`は探索対象に残ります。

**トップ選択。** `--top`なしでは、ソース内にconfigが1つあればそれを選び、複数なら
明示的な選択を求めます。configがなければ、ほかからインスタンス化されていない
モジュールをフロントエンドが選びます。同名のモジュールがある場合も含め、configを
明示するには`--top=cfg:config`を使います。選択とバインディングにはフロントエンドの
制約が適用されます。

**言語の版。** フロントエンドはIEEE 1800-2023に固定しています。言語の版を選ぶ
オプションは未実装です。ソースの`timeunit`・`timeprecision`・`` `timescale``は、
コマンドラインで指定する既定値より優先します。

### シミュレーション時刻と値の選択

| 書式 | 既定値 | 意味 |
| --- | --- | --- |
| `--max-time=<time>` | ユーザー指定の時刻上限なし | 境界時刻以下のイベントを処理した後、`time_limit`で終了 |
| `--max-time-ok` | 無効 | `time_limit`の終了コードを4から0へ変更 |
| `--mintypmax=min\|typ\|max` | `typ` | 遅延を含む`min:typ:max`式の分岐を選択 |
| `--seed=<n>` | `0` | `$urandom`・`$urandom_range`・`randcase`と独立した初期値乱数の既定シード |
| `--init-values=x\|zero\|one\|random` | `x` | 初期値のない4値整数のソース変数と新規メモリ要素の既定値 |
| `--stop=finish\|ignore\|error` | `finish` | `$stop`の動作を選択 |
| `--autoflush` | 無効 | stdout向けのdisplay・write・strobe・monitorタスクごとにフラッシュ |

`--max-time`には、0以上の10進数と、直後に`s`・`ms`・`us`・`ns`・`ps`・`fs`のいずれかを
指定します。小数も使え、例は`10us`・`1.5ns`・`0ns`です。数値と単位の間に空白は置きません。
デザイン全体の時間精度で最近傍に丸め、ちょうど半分は0から遠い方向へ丸めます。
桁あふれは入力エラーです。`0ns`は時刻境界であり、上限の無効化ではありません。
境界の前にデザインが終了したり、イベントが尽きたりする場合もあります。

`--max-time-ok`が変えるのは`time_limit`の終了コードだけです。実時間、時刻が進まない処理、
資源上限、設計エラーの終了結果は変えません。

`--stop=finish`は理由`stop`・終了コード0で終了し、`ignore`は呼び出し元へ戻り、
`error`は理由`stop`・終了コード1で終了します。`--seed`はソースで明示したシードや、
別に定めた`$random`・`$dist_*`のシード規則を置き換えません。

`--init-values`は変数・メンバーの明示初期値、ネット、2値変数、不正な読み出し・
空のpop・条件式のfallbackの既定値を保ちます。static記憶域は1回、自動変数は宣言時、
automatic outputと関数の戻り値変数は呼出しごとに初期化します。動的配列の構築では
コピーした先頭部分を保ち、新規の末尾だけを初期化します。`random`は`--seed`から
始める専用のSplitMix64系列を使い、`$random`・`$urandom`を消費しません。
X以外を選ぶと版の行の直後に[規定の注記](spec/CLI.ja.md#4-kirimasim-自身のメッセージ)を出します。
`parse`はエラボレーションだけを行い、`--dump-sir`は初期化命令を実行せず表示します。
どちらも注記は出しません。

### 実行と資源の上限

| 書式 | 既定値 | 数えるもの・結果 |
| --- | --- | --- |
| `--max-zero-delay=<n>` | `1000000` | 1タイムスロット内でActive・Reactiveへイベントを移した回数。`zero_time_limit`・終了コード5 |
| `--max-slot-events=<n>` | `100000000` | 1タイムスロット内の全領域で実行したイベント。`zero_time_limit`・終了コード5 |
| `--max-steps=<n>` | `1000000000` | 1プロセスが待機せず連続実行した第1層の命令。`zero_time_limit`・終了コード5 |
| `--max-procs=<n>` | `1000000` | 未終了のruntime child。`resource_limit`・終了コード6 |
| `--max-call-depth=<n>` | `10000` | プロセスごとのtask/function呼び出しの深さ。`resource_limit`・終了コード6 |
| `--max-wall-time=<seconds>` | `0` | コンパイルを除く実行中の経過秒数。整数秒。`wall_time_limit`・終了コード4 |
| `--max-scc-iter=<n>` | `0` | 受理するが、第2層の静的アイランドが実装されるまで効果なし |

最初の4つの回数上限と実時間の上限は、0で無効になります。`--max-call-depth`は正の値が
必要です。要求するスタック量を確保できなければ起動時に終了コード2となる場合もあり、
実行中に残りのスタックを使い切る場合は資源上限です。`--max-steps`は実行全体の
命令数予算ではありません。

`--max-procs`は、登録済みでまだ動いていないものや待機中のものを含む、未終了のruntime childを
数えます。エラボレーション時の静的プロセスや、子の終了後に保持する記録は除外します。
上限を超える子は、実行を開始する前に登録を拒否します。

実時間の上限は静的初期化を含む実行中の安全な地点で検査し、ホスト側で止まった処理を
強制的に中断するものではありません。`final`は期限切れの実時間予算を適用せず完了させます。
上限を増やしたり無効化したりしても、未実装の言語機能は有効になりません。

### 診断と内部の確認

| 書式 | 既定値 | 意味 |
| --- | --- | --- |
| `--bounds-check=off\|warn` | `off` | 不正なpacked選択と固定unpacked配列の添字を実行時に検査 |
| `--cond-x=off\|warn\|error` | `off` | 実行時の`if`・`?:`条件と`case`選択式に含むX/Zを検査 |
| `--dump-sir` | 無効 | シミュレーションの代わりに検証済みSIRを標準出力へ表示 |
| `--stats=json` | 無効 | 標準出力の最終行にカウンタのJSONを追加 |

範囲の警告はソース位置ごとに1回出し、最後にアクセス回数を表示します。読み・書き・NBAの
値を変えず、すべてのコンテナ操作を検査するものでもありません。不正なキュー要素への
書き込みには別の必須警告があり、`--bounds-check=off`でも出ます。不正な書き込みで
記憶域の値は変わりません。

`--cond-x=warn`はソース位置ごとに1回報告して評価回数を数え、`error`は最初の報告を
設計の実行時エラーとして終了コード2で停止します。式の値と分岐の選択は維持します。

SIRのformat 0は開発中の診断形式で、安定した交換形式ではありません。ダンプを読み戻して
コンパイル済みモデルとして実行する機能はありません。`parse`・`--dump-sir`でも
カウンタを出せますが、示すのはそのモードの処理量です。

### 波形のオプション

| 書式 | 既定値 | 意味 |
| --- | --- | --- |
| `--wave=<file>.vcd` | CLIでのダンプ指定なし | コマンドラインの選択で時刻0からVCDを生成 |
| `--wave-scope=<pattern>[,<pattern>...]` | 対応する全スコープ | 一致した階層スコープとその子孫を選択。複数回指定可能 |
| `--wave-glitches` | 無効 | タイムスロット内の途中の変化も記録 |

波形名は本体部分が空でなく、末尾が`.vcd`である必要があります。`.fst`は現在拒否します。
スコープのパターンでは`*`が任意の文字列、`?`が1文字を表します。空のパターンは入力エラーです。
ワイルドカードを含む引数は引用符で囲んでください。`--wave`なしでは、スコープと途中変化の
指定をデザイン自身のダンプへ適用します。対応するデータと制御は
[波形のリファレンス](#波形のリファレンス)を参照してください。

### 実行時のプラス引数

`+name`・`+name=value`を、コマンドラインの順序でデザインの`$test$plusargs`・
`$value$plusargs`へ渡します。予約したフロントエンド用の接頭辞`+incdir+`・`+define+`・
`+libext+`は、実行時のプラス引数ではありません。

プラス引数は前処理マクロを定義せず、モジュールパラメータも上書きしません。
`$value$plusargs`は最初の一致を使い、一致しなければ代入先を保ちます。デザイン自身が
引数を読み取って使う必要があります。`parse`はこれらの呼び出しを実行しません。

## 言語と実行のリファレンス

実行にはSIRインタプリタと共有カーネルを使います。実行できるソースの形は、
フロントエンドが受理するSystemVerilogの一部です。記憶域、仮引数、ソースの形ごとの
正確な制限は[P1対応機能](P1_SUPPORT.ja.md)を参照してください。

### 値・式・集約値

- 整数値には符号付き・符号なし、64ビット超の幅を使えます。4値は0・1・X・Zを保持し、
  2値への変換ではX/Zのビットを0にします。
- 初期化していない対応済みの4値整数変数はX、2値変数は0、実数は0.0、文字列は空で始まります。
  通常の未駆動wire netはZに解決しますが、netの種類とほかのドライバの影響を受けます。
  対応するevent宣言は同期用のobjectを生成します。
- `real`・`shortreal`・`realtime`・文字列・enum・packed/unpacked構造体・packed union・
  固定多次元配列には実装済みの部分集合があります。
- 算術、論理、ビット、縮約、比較、シフト、条件、連結、キャスト、`inside`、代入パターン、
  選択の演算には、型の幅と状態の規則を適用します。case等価と通常の等価は別で、
  `case`・`casez`・`casex`・`case inside`も一致規則が異なります。
- 固定集約値のコピー・比較・ストリーミングは、対応する表現で使えます。
  ストリーミングのスライス幅は定数が必要で、`with`、文字列の代入先、入れ子の
  ストリーミング代入先は未対応です。

演算ごとの規則は[値の意味](spec/VALUE_SEMANTICS.ja.md)を参照してください。
仕様書内の未実装の表現に関する記載は、対応済みの宣言ではありません。

### 階層・手続き・スケジューリング

モジュール、パッケージ、対応済みのinterface/modport、generate、パラメータ、ソース内configは、
固定版で改変しないフロントエンドがエラボレーションします。パラメータ化やオブジェクトを
使う言語機能全体への対応を意味するものではありません。

実行する形には`initial`・`always`・`always_comb`・`always_latch`・`always_ff`・`final`、
名前付きprogram、static/automaticのtask/function、対応する`input`・`output`・`inout`・
`ref`・`const ref`引数があります。`final`は待機できません。分岐とループには対応範囲内の
`for`・`while`・`do`・`repeat`・`forever`・`foreach`・`break`・`continue`・`return`、
`unique`・`unique0`・`priority`・`randcase`があります。

モジュールのプロセスはActive側、programのプロセスはReactive側の評価領域を使います。
遅延、イベント待機、ノンブロッキング代入、forkした処理は、それぞれのスケジューリングと
寿命の規則を保ちます。Observedでの報告やPostponedでの出力は、assertionや右辺を評価する
処理とは別です。ゼロ遅延制御はシミュレーション時刻を進めません。デザインの局所的な
時間単位と全体で最も細かい時間精度でスケジューリングと丸めを決め、`$timeformat`は
表示だけを変えます。

対応する並行処理には`fork`・`join`・`join_any`・`join_none`、`wait fork`、`disable fork`、
名前付きイベント、対応する名前付きblock/taskのdisableがあります。静的な整数記憶域を使う
対象では、既定または明示した`#1step`と`@(cb)`を持つ入力専用clocking blockを実装しています。
ほかのスキューとoutput/inoutのclockvarは未対応です。

即時・遅延即時アサーションは記載した形に対応しています。並行アサーションは未対応です。
[スケジューラ](spec/SCHEDULER_SPEC.ja.md)と
[クロッキング入力の範囲](notes/clocking-input-1step-proposal.ja.md)を参照してください。

### 動的コンテナ・クラス・ネット

対応済みの動的配列・キューには、生成、値の深いコピー、添字、参照、明示待機、対象となる
代入・NBA経路があります。キューのメソッドには`size`・`delete`・`insert`・`push_front`・
`push_back`・`pop_front`・`pop_back`、動的配列には`size`・`delete`があります。
配列の縮約・整列は後の索引に示します。キュースライスへの書き込み、連想配列、未対応の
集約値・class・event要素、コンテナへの暗黙感度は残作業です。

非パラメータ化クラスのstaticプロパティとstaticメソッドは、対象の記憶域型について、
オブジェクトを生成せずに使えます。クラスオブジェクト、コンストラクタ、instance dispatch、
パラメータ付きstatic記憶域は未対応です。staticプロパティの対応だけではUVMは動きません。

通常の解決net、wired net、pull、駆動強度を扱い、ゲート、UDP、6種の方向付きMOSと
6種の受動スイッチは、記載した端子の形で実行できます。静的なinput/outputの部分ポートには
駆動強度を保持する形があります。より広いport・alias・force、電荷保持、UDPの未接続ポート、
specifyパス・タイミングチェックは、制限付きまたは未対応です。密なUDPソース処理には
実行上限に達する未解決例があり、UDP全体の対応は未確認です。

## システムタスク・関数・メソッド

以下は実装済みの名前の索引です。引数型と組み合わせには
[P1対応機能](P1_SUPPORT.ja.md#システムタスク関数メソッド)と
[システムタスク仕様](spec/SYSTEM_TASKS.ja.md)の制限があります。
仕様書に名前があるだけでは、ソースから対応済みとは判断できません。

### 出力・書式・報告

| 分類 | 名前・動作 |
| --- | --- |
| 即時のコンソール出力 | `$display`、`$write` |
| Postponedでの出力 | `$strobe`、`$monitor`、`$monitoron`、`$monitoroff` |
| ファイル出力 | `$fdisplay`、`$fwrite`、`$fstrobe`、`$fmonitor` |
| 文字列出力 | `$swrite`、`$sformat`、`$sformatf`、`$psprintf`（`$sformatf`の別名） |
| severity | `$fatal`、`$error`、`$warning`、`$info` |
| 実行制御 | `$finish`、`$stop`、`$exit`、`$stacktrace` |

display・write・strobe・monitor系は、ファイル向けと`$swrite`を含めて、末尾に`b`・`o`・`h`を
付ける形式にも対応します。`$strobe`・`$monitor`の引数はautomatic変数を読めません。
実行時の文字列やpacked値を使う書式式は、記載した形で使えます。

| 出力変換 | 用途 |
| --- | --- |
| `%b`、`%o`、`%h`・`%x`、`%d` | 整数の2進・8進・16進・10進 |
| `%c`、`%s` | 文字・文字列 |
| `%e`、`%f`、`%g` | 実数の書式 |
| `%t` | `$timeformat`で書式化した時刻 |
| `%m`、`%l` | 階層スコープ名とライブラリ・セル名 |
| `%u`、`%z` | 下位の語からネイティブのバイト順で出す32ビットの生データ。`%u`はX/Zを0にする |
| `%%` | パーセント記号そのもの |

幅と対応するフラグにはそれぞれの規則があります。実数の精度・フラグを、同じまま整数に
使えるという意味ではありません。バイナリのpacked出力先ではNULを保持し、文字列では
取り除きます。内部のpattern描画基盤があっても、ソースの`%p`と解決した強度の`%v`は未実装です。

`$error`・`$warning`は診断を出しますが、それだけで終了コードを失敗にはしません。
自動実行を失敗させる自己検査には`$fatal`を使います。`$finish`・`$stop`の引数は報告レベルで、
OSの終了コードではありません。0は終了報告を抑止、1は既定、2はstderrへのカウンタJSONも
要求します。`$exit`は呼び出し元の起源にあるprogramの処理を終了し、program起源でなければ
無視します。

### ファイルとメモリの操作

| 分類 | 名前 |
| --- | --- |
| オープン・クローズ・フラッシュ | `$fopen`、`$fclose`、`$fflush` |
| 文字・文字列入力 | `$fgetc`、`$ungetc`、`$fgets` |
| 書式付き入力 | `$fscanf`、`$sscanf` |
| バイナリ入力 | `$fread` |
| 位置と状態 | `$ftell`、`$fseek`、`$rewind`、`$feof`、`$ferror` |
| メモリファイル | `$readmemb`、`$readmemh`、`$writememb`、`$writememh` |

ファイル記述子には、対応する標準入力・標準出力の形式もあります。相対ファイル名は
プロセスの作業ディレクトリが基準です。appendモードの出力はseek後もファイル末尾に書き、
seek可能なファイルでは書き込んだデータに位置を合わせます。メモリ操作は、記載した
固定整数メモリ、多次元の形、refの転送に対応します。動的メモリや未対応の集約値配置は
その範囲に含みません。

書式付き入力には、記載した整数・文字列・実数変換、幅、代入抑止、`%u`・`%z`の生の語を
使えます。入力変換の`%t`・`%v`・`%m`は未実装です。`$fread`の整数代入先とメモリ代入先は、
個数、添字、書き戻しの規則が別です。部分読み取りや副作用を持つ代入先に依存する前に、
詳細なタスク仕様を確認してください。

### クエリ・数学・乱数

| 分類 | 名前 |
| --- | --- |
| 時刻 | `$time`、`$stime`、`$realtime`、`$timeunit`、`$timeprecision`、`$timeformat`、`$printtimescale` |
| 変換 | `$signed`、`$unsigned`、`$rtoi`、`$itor`、`$realtobits`、`$bitstoreal`、`$shortrealtobits`、`$bitstoshortreal` |
| 型と次元 | `$bits`、`$typename`、`$isunbounded`、`$dimensions`、`$unpacked_dimensions`、`$left`、`$right`、`$low`、`$high`、`$increment`、`$size` |
| ビットの性質 | `$countbits`、`$countones`、`$onehot`、`$onehot0`、`$isunknown` |
| 整数の数学 | `$clog2` |
| 実数の数学 | `$ln`、`$log10`、`$exp`、`$sqrt`、`$pow`、`$floor`、`$ceil`、`$sin`、`$cos`、`$tan`、`$asin`、`$acos`、`$atan`、`$atan2`、`$hypot`、`$sinh`、`$cosh`、`$tanh`、`$asinh`、`$acosh`、`$atanh` |
| 従来の乱数 | `$random`、`$dist_uniform`、`$dist_normal`、`$dist_exponential`、`$dist_poisson`、`$dist_chi_square`、`$dist_t`、`$dist_erlang` |
| プロセスごとの乱数 | `$urandom`、`$urandom_range`、`randcase`。CLIの既定シードは`--seed` |
| 実行時引数 | `$test$plusargs`、`$value$plusargs` |

クエリは対応する型・次元が対象です。実数と整数の変換の丸め、不定ビット、広い幅、乱数分布の
範囲には個別の規則があり、単なるキャストやホストライブラリの呼び出しとは扱いません。

### 組み込みメソッド

| 対象 | 実装済みのメソッドの部分集合 |
| --- | --- |
| 文字列 | `len`、`getc`、`putc`、`toupper`、`tolower`、`compare`、`icompare`、`substr`、`atoi`、`atohex`、`atooct`、`atobin`、`atoreal`、`itoa`、`hextoa`、`octtoa`、`bintoa`、`realtoa`、文字の添字 |
| enum | `first`、`last`、`num`、`name`、`next`、`prev` |
| 動的配列・キュー | 前述の生成・サイズ取得・変更の部分集合 |
| 固定配列・対応する動的配列・キュー | `sum`、`product`、`and`、`or`、`xor`、`reverse`、`sort`、`rsort`、`min`、`max`と、対応する`with`式 |
| 名前付きイベント | `.triggered`と、記載したtrigger・waitの形 |

対応するキーの整列は安定ですが、副作用を持つキーや、純粋性を確認できない関数を
すべて受理するものではありません。min/maxは元の要素を最大1個含む独立したキューを返し、
入力が空なら結果も空です。ほかの検索メソッドとshuffleは未実装です。

## 波形のリファレンス

VCDの制御タスクは`$dumpfile`・`$dumpvars`・`$dumpoff`・`$dumpon`・`$dumpall`・
`$dumplimit`・`$dumpflush`です。`$dumpvars(0, scope)`はそのスコープと子孫を選択します。
CLIの`--wave`はファイルと初期選択を指定し、その場合はデザインの`$dumpfile`・`$dumpvars`を
警告付きで無視します。ほかの制御タスクは引き続き有効です。

対応する静的なnetと変数を4値で記録します。既定はタイムスロット境界で落ち着いた値を出し、
`--wave-glitches`は途中の遷移も記録します。途中で打ち切る実行やfinal手続きを含め、
終了時にファイルをフラッシュして閉じます。

unpacked配列、automatic変数、文字列やキューなどの動的データは省略します。
program/interfaceスコープの対応は未完です。FSTと`$dumpports`は未実装です。
ダンプファイルを開けない場合は警告を出し、それだけでシミュレーションを失敗にはしないため、
ファイルが生成されたことも確認してください。出力の相対パスは作業ディレクトリが基準で、
既存ファイルはダンプ開始時に上書きします。[波形仕様](spec/WAVEFORM.ja.md)も参照してください。

## 出力・診断・統計

| 出力先 | 内容 |
| --- | --- |
| stdout | 標準出力向けのデザイン出力、`--dump-sir`のSIR、`--stats=json`の最終カウンタ行 |
| stderr | 通常実行の版・シード・引数の表示、診断、severityの報告、終了報告 |
| 指定したファイル | ファイルタスクの出力と波形 |

通常の位置付き診断は、ファイル・行・列を示します。未対応構文は原則として位置付きの
`error: unsupported:`と終了コード2で停止します。警告だけで終わった場合でも、
要求した出力がすべて生成されたと判断することはできません。

`--stats=json`は必要なら改行を挿入し、stdoutの最終行にJSON objectを1つ追加します。
その前にはデザインやSIRの出力が残るため、ストリーム全体がJSON文書になるわけではありません。
通常のカウンタは符号なしの回数で、`sim.end_reason`は文字列です。出るキーは実行モードで異なります。

| カウンタの分類 | 意味 |
| --- | --- |
| `front.*` | フロントエンドの処理と診断。そのモードで出るキーを確認 |
| `sir.*` | slot・process・block・命令など、変換後のデザインの大きさ |
| `sched.events.<region>`、`sched.time_slots` | 領域ごとの実行イベントとタイムスロット |
| `proc.*` | プロセスの生成・終了・起床・保持記録 |
| `slot.*`、`nba.*`、`wait.*`、`vm.instrs` | 値の更新、保留更新、購読、解釈した命令 |
| `sim.end_time`、`sim.end_reason` | 全体の時間精度のtickで表す終了時刻と終了理由 |

これらは処理回数であり、CPU時間・経過秒数・RSSではありません。比較するときはソースの版、
オプション、シードを保存してください。詳細は[性能仕様](spec/PERFORMANCE.ja.md)にあります。

## 終了と終了コード

| コード | 理由・意味 |
| --- | --- |
| `0` | `finish`・`quiescent`・通常の`stop`、確認モードの成功、`--max-time-ok`付きの`time_limit` |
| `1` | `fatal`、または`--stop=error`付きの`stop` |
| `2` | 不正な入力・CLI、未対応ソース、設計の実行時エラー |
| `3` | 検証器の失敗など、コンパイラ・ランタイム内部の失敗 |
| `4` | `time_limit`・`wall_time_limit` |
| `5` | `zero_time_limit` |
| `6` | 呼び出し・スタック・runtime childの上限などの`resource_limit` |
| `130` | SIGINTによる中断 |

イベントキューが空になれば`quiescent`で終了します。対応する通常のシミュレーション終了経路は
`final`を実行し、`final`内では待機できません。コンパイル・入力の失敗や、プロセスの強制終了には
同じシミュレーションの後処理の保証はありません。

シミュレーション中の最初のSIGINTは、安全な地点での終了を要求し、2回目は直ちに
プロセスを終了します。コンパイル中はOSの通常のSIGINTの動作に従います。終了理由名と
OSの終了コードは別のインターフェースで、`--max-time-ok`はコードだけを変え、
`sim.end_reason`は変えません。

## 未実装のインターフェース

詳細な計画に記載されていたり、単体のslangで使えたりしても、以下はこの版のdriverが
受理する公開オプションではありません。

- 仕様にはあるが未完のもの：`--report-pulses`・`--log`・`--diag-format=json`。
- driverが直接公開していないフロントエンドの指定：`-W...`・`--compat`・`--max-hierarchy-depth`・
  `--max-generate-steps`・`--max-constexpr-depth`・`--max-constexpr-steps`。
  一覧にない`-U`などの別名も有効にはしていません。
- 後続の実行・開発オプション：`--tier`・`--tier-check`・`--state`・`--report-state-opt`・
  `--race-check`・`--race-seed`・`--race-nba`・`--public`・`--preserve`・`--disable-pass`・
  `--cxx`・`--cache-dir`・`--randomize-fail`・`--assert-incomplete`。
- コンパイル済みモデル向けの`build`・`run <model>`・`lib-create`は、予定のインターフェースで、
  現在のサブコマンドではありません。

クラスオブジェクト、連想配列、より広い乱数化・UVM、並行アサーション、coverage、
virtual interface、より広いclocking、specifyのタイミング、VPI/DPI-Cなどは未対応または部分対応です。
VPIに依存するcocotb連携とFST出力は使えません。Icarusが対応する必要な機構は、
[P1の範囲](spec/P1_SCOPE.ja.md)に従って引き続きP1の対象であり、段階の分類で除外しません。
IEEE・Icarusの全機能との同等性は未確認です。[残る機能の一覧](P1_SUPPORT.ja.md#残っている作業と対象範囲)と
[完了条件の監査](P1_CRITERIA_GAPS_2026-10-28.md)に日付付きの根拠があります。

## コマンドの実行例

開発用ビルドの後、リポジトリのルートから実行します。添付の例の時間単位は1 ns、
時間精度は1 psです。準備の詳細は[ユーザーマニュアル](USER_MANUAL.ja.md)を参照してください。

### include・マクロ・ライブラリ・実行時引数

```sh
build/dev/src/driver/kirimasim --top=tb \
  -Idocs/examples/user_manual/include -DCOUNTER_WIDTH=8 \
  -y docs/examples/user_manual docs/examples/user_manual/tb.sv +cycles=6
```

先頭は`width=8 cycles=6`、サンプルは`t=20 ns q=1`から`t=70 ns q=6`までで、終了コードは0です。
`counter.sv`はライブラリパスから解決します。

### フロントエンドだけの検査

```sh
build/dev/src/driver/kirimasim parse --top=tb \
  -f docs/examples/user_manual/files.f
```

成功すれば終了コード0で、デザインの出力はありません。

### 検証済みSIRの出力

```sh
build/dev/src/driver/kirimasim --dump-sir --top=tb \
  -f docs/examples/user_manual/files.f > counter.sir
```

診断用のSIRダンプを生成し、再利用可能な実行ファイルを作るものではありません。

### 時刻上限と機械可読なカウンタ

```sh
build/dev/src/driver/kirimasim --max-time=25ns --max-time-ok --stats=json \
  --top=tb -f docs/examples/user_manual/files.f > bounded.out 2> bounded.log
```

終了コードは0です。最終JSON行の`sim.end_reason`は`time_limit`、`sim.end_time`は
`25000` tickです。その前のstdoutにはデザインのヘッダと20 nsのサンプルが残ります。

### スコープを絞った波形

```sh
build/dev/src/driver/kirimasim --wave=counter.vcd '--wave-scope=tb.dut' \
  --wave-glitches --top=tb -f docs/examples/user_manual/files.f
```

counterインスタンスの対象となる信号を選びます。ワイルドカードを使う場合は、
`'--wave-scope=tb.dut*'`のようにオプション全体を引用符で囲んでください。
