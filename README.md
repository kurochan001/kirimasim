# haremasim

[日本語](README.ja.md)

haremasim is an open-source SystemVerilog simulator in early development.
Its goal is a simulator that does not give up any of the following:

- **Four-state values** (0, 1, X, Z) by default, with no optimization that
  changes four-state meaning.
- **Scheduling as IEEE 1800-2023 defines it**, with every region of the
  time slot and the standard's reference algorithm.
- **Practical speed**, by running two-state code whenever it can be shown
  or checked at run time that no X or Z is present.

> **Status: not usable yet.** The repository currently holds only the P0
> groundwork: the build, library skeletons, a `haremasim parse` command that
> runs the [slang](https://github.com/MikePopoloski/slang) front end, the
> first tests, and CI. The detailed specifications under `docs/spec/` are
> headings only, and the P0 exit criteria are not met yet. There is no
> simulation engine.

**Most of the code is generated by AI (Claude Code); humans are responsible
for the specification, the tests, and review.** See
[docs/spec/AI_POLICY.md](docs/spec/AI_POLICY.md) and
[CONTRIBUTING.md](CONTRIBUTING.md).

## Building

Requirements: CMake 3.28 or later, Ninja, Python 3, and a C++23 compiler
(tested with Apple clang 21 on macOS arm64; CI also builds on Ubuntu 24.04).
The first configure downloads slang and GoogleTest.

```sh
cmake --preset dev            # also: release, asan, ubsan
cmake --build --preset dev
ctest --preset dev
```

| Preset | Flags |
| --- | --- |
| `dev` | `-O1 -g` |
| `release` | `-O3` |
| `asan` | `-O1 -g -fsanitize=address -fno-omit-frame-pointer` |
| `ubsan` | `-O1 -g -fsanitize=undefined -fno-sanitize-recover=all` |

Each preset builds into `build/<preset>/`.

## Usage (so far)

```sh
build/dev/src/driver/haremasim --version
build/dev/src/driver/haremasim parse file.sv ...        # parse and elaborate
build/dev/src/driver/haremasim --stats=json parse file.sv
```

`parse` exits with code 2 if slang reports any error.
